# 생존지식 · 글감·근거 보관함 MVP

이 파일의 목적은 **자료를 버리지 않고, 그 자료로 무엇을 검토했는지 남기는 것**이다. 기존 Knowledge Candidate/Evidence/BRIEF·C3 게시 승인 체계와 별도 발행 경로를 만들지 않는다.

## 실제 저장소 및 화면
- 정본: `knowledge/content/source-inbox.json` (versioned JSON, 원문 전문/사진 없음).
- 조회: 기존 로그인 운영자 화면 `/operator/knowledge/`의 **글감·근거 보관함**.
- 각 자료의 `related_guides`는 **기존 공개 글의 대조 후보**이다. `REVIEW_CANDIDATE`는 실제 Evidence 연결이나 공개된 글 수정이 아니다.
- V1은 **저장소에 기록한 공개 가능한 메타데이터만 읽는 방식**이며, 브라우저에서 새 URL을 DB에 즉시 저장하는 제보 UI는 미구현이다. 추후 기존 Knowledge Inbox DB 접근이 확인되면 권한 있는 운영자 쓰기 경로를 연결한다.
- 번들에 자료 메타가 들어가므로 **계정정보·개인정보·비공개 검토 메모를 JSON에 저장하지 않는다**.

## 운영 규칙
1. 원본 URL·기관·원문 표시 게시일/수정일(없으면 null)·우리 확인일을 구분해 저장한다.
2. 같은 URL은 추적용 쿼리만 제거한 식별값으로 중복 체크한다. `bbsNo`, `nttNo`, `key` 같은 문서 식별 인자는 **유지**한다.
3. 출처 조건은 원문 표시와 안내 URL을 함께 저장한다. 상업 이용·변경·출처표시·이미지/첨부 범위를 **각각 분리**한다. 확인 안 된 이용권은 허용으로 추정하지 않는다.
4. `HOLD`는 폐기가 아니다. 자료를 보존하면서 근거/권리/시점 확인을 기다린다. 게시 및 개정은 기존 인간 승인 게이트만 쓴다.
5. 사용된 자료도 남기고 여러 글과 연결할 수 있다. 추가 출처가 기존 설명을 실질적으로 개선하지 못하면 공개 글을 수정하지 않는다.
6. 공개 글의 ID·slug·canonical은 기존 승인 버전 그대로 유지한다. 첫 MVP에서는 공개 글 원문과 게시 이력을 건드리지 않는다.

## 확장 시점
- 실제 사용자 입력/DB 연결과 자동 중복 접수는 운영 DB가 연결된 후 P3에서 구현.
- 작성·검수·개정·버전 복구는 기존 C 승인·출처·revision 계약을 조사한 후 P4에서 연동.
- 새로운 예약, 유료 LLM, CMS, Production 강제 배포는 추가하지 않는다.
