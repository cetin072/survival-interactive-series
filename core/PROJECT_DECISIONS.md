# PROJECT DECISIONS — Long-term Canon

이 문서는 기획방에서 합의한 장기 운영 결정을 요약한다. 새 채팅이나 장기 공백 이후에도 이 문서를 기준으로 방향을 유지한다.

## 프로젝트 정체성
- 가칭: `생존기록` (정식명 미확정)
- 장르: 현대 가족 생존 인터랙티브 드라마 / MUD + 선택지 + 자유행동
- 주 타깃: 30~40대 남성
- 재미와 몰입이 최우선이며, 실제 생존지식은 플레이를 통해 자연스럽게 체득하게 한다.
- 플레이 중 메타 강의는 하지 않는다. 현실 피드백은 시즌 종료 후 선택형 AAR로만 제공한다.

## 가족 기본 구조
- 한준호(본인) 41세
- 서윤(아내) 39세
- 민석(아들) 13세, 중학교 1학년
- 정호(아버지) 68세
- 가족 4명은 수동 NPC가 아니라 각자 자율행동·의견·실수·갈등·피로·공포·경험 누적을 가진 독립 파티원이다.
- 자녀는 보호 대상이지만 완전 수동이 되지 않도록 중학생을 기본값으로 둔다.

## 콘텐츠 번호 체계
- 작품명 `생존기록` 자체에는 번호를 붙이지 않는다.
- 정식 본편: `S01`, `S02`, `S03` ... / 예: `생존기록 — S01: 제목`
- 튜토리얼: `T01`, `T02` ... / 예: `생존기록 — Tutorial T01: 지진`
- 이번 지진 플레이는 `T01 지진 튜토리얼 프로토타입 v0.1`로 보존한다.
- 기존 폭우/정전 테스트는 정식 번호를 소급 부여하지 않고 `Pre-Alpha Prototype`으로 본다.
- 공식 S01은 아직 설계·승인되지 않았다.

## 난이도
- Tutorial: 초보자/어린이/첫 진입자용. 기본 대응 학습 중심.
- Standard: 성인 본편 기본. 정보 불확실성, 자원 압박, 가족 변수, 장기 분기 포함.
- Hard: Standard보다 안전 여유가 적고 복합 손실 가능성이 높음.
- 본래 목표의 정식 본편은 `Standard와 Hard 사이`를 기본 감각으로 한다.
- 상세 기준은 `docs/CORE_GAME_SYSTEMS_V1.md`를 따른다.

## 시즌 설계
- `한 시즌 = 하나의 주요 사건/재난`을 기본으로 한다.
- 시즌 길이와 화수는 고정하지 않는다. 6화는 참고 감각일 뿐이며 완성도와 긴장 구조에 따라 유연하게 결정한다.
- 여러 시즌을 미리 완성해 두지 않는다. 먼저 한 시즌씩 설계→플레이→수정하면서 재미 공식을 발견한다.
- 정식 시즌은 단순 `재난 발생 → 대피 → 안전 확보 → 종료` 수준으로 끝내지 않는다.
- 주요 재난이 가족의 일상을 깨고, 여러 번의 위기와 선택, 누적 결과를 거쳐 새로운 안정상태에 도달해야 한다.

## 정식 본편 제작 순서 — 중요
이전 규칙처럼 플레이방에서 공식 S01의 전체 구조를 즉석으로 만들고 바로 시작하지 않는다.

앞으로 정식 본편은 반드시:
1. 기획방에서 시즌 설계
2. 주요 세계 상태·압력·전환점·가족 변수·장기 인과관계 설계
3. 현실성 검토
4. 시즌 설계 상태를 `APPROVED FOR PLAYTEST`로 동결
5. 플레이방에서 실제 플레이

순서를 따른다.

플레이방의 AI는 세부 장면·대화·자유행동 결과를 즉흥 생성할 수 있지만, 공식 시즌의 핵심 압력과 세계 구조를 플레이어 선택 뒤에 임의로 만들어 맞추지 않는다.

## 시나리오 생성 방식
- 완성 대본을 미리 읽어주는 구조가 아니다.
- 기획방은 `세계 상태 / 재난의 본질 / 숨은 위험 / NPC 목적 / 시간 이벤트 / 조건부 이벤트 / 가능한 종료 상태 / 장기 회수 포인트`를 먼저 설계한다.
- 플레이어의 실제 행동과 선택에 따라 세부 이야기는 즉흥적으로 생성된다.
- 핵심 원칙: `기획방에서 세계와 압력을 설계하고, 플레이방에서 이야기를 발견한다.`
- 선택 후 결과를 맞추기 위해 숨은 상태를 소급 변경하지 않는다.
- 플레이어가 보지 않은 사건·NPC·장소도 세계 안에서 독립적으로 진행될 수 있다.

## 본편 품질 기준
정식 시즌은 최소한 다음을 포함한다.
- 좋은 선택끼리의 충돌과 실제 포기 비용
- 정보 부족 또는 정보 충돌
- 가족 독립행동/의견/갈등
- 자원·시간·거점·이동수단 등의 실질적 손실 가능성
- 초반 선택이 후반에 돌아오는 장기 인과관계
- 실패해도 다음 상태로 이야기가 이어지는 Fail-Forward
- 최소 3회 이상의 의미 있는 상황 전환

상세 기준은 `docs/CORE_GAME_SYSTEMS_V1.md`를 따른다.

## 선택지와 입력 방식
- 선택지는 문자 대신 `1, 2, 3...` 숫자를 기본으로 한다.
- 플레이어는 하나만 고를 필요가 없으며 `3 → 5 → 1`처럼 행동 순서를 지정할 수 있다.
- 행동 순서, 시간, 거리, 동시행동 여부는 결과에 실제 영향을 준다.
- 자유행동 입력은 항상 허용한다.

## 가족 파티와 동시행동
- 가족은 각자 역할과 숨은 상태를 가진다.
- 플레이어가 가족별 임무를 나눠 동시에 진행할 수 있다.
- 동시행동은 시간을 절약하지만 통신 두절, 정보 비대칭, 독립 사건, 재합류 실패 위험을 만든다.
- 차량은 이동수단뿐 아니라 상황에 따라 이동형 비축공간/임시 거점이 될 수 있다.

## 현실성
- 실제 재난행동과 사회·건축·인프라 묘사는 현실성을 우선한다.
- 단순히 극적이기 위해 비현실적 장애물을 만들지 않는다.
- 현실지식은 `knowledge/SOURCES.md` 기준으로 검증한다.
- 플레이 중에는 출처나 교육 해설을 노출하지 않는다.

## 플레이 중 해설
정식 본편에서는 `좋은 선택`, `위험한 선택`, `이제 장기전` 등 메타 평가를 최소화한다.
기본 화면은 `상황 → 행동 → 결과`다.
현실 대응 분석과 플레이 평가는 시즌 종료 후 사용자가 원할 때 AAR로 제공한다.

## 시나리오 제작 중 시각 후보
- 장면 초안에 `[삽화 후보] ...` 또는 `[영상 후보] ...` 태그를 남길 수 있다.
- 태그는 후보 표시일 뿐 실제 제작 지시가 아니다.
- 시나리오 작성 → 플레이테스트 → 수정 → 분기/사건 확정 전에는 본격 삽화/영상 제작을 하지 않는다.

## 시즌이 끝난 뒤 자산화
한 시즌의 첫 플레이는 동시에 프로토타입, 플레이테스트, 공동 창작이다.
시즌 종료 후 아래 두 자산을 분리한다.
1. 실제 플레이 스토리: 사용자가 실제 선택해서 경험한 서사
2. 정식 시나리오 구조: 미사용 사건·다른 갈림길·다른 결말 후보까지 포함한 재사용 가능한 시나리오

정리 후 해당 시즌을 `Scenario v1.0`으로 만들 수 있다. 이후 다른 플레이어는 같은 세계/시나리오 뼈대를 사용하되 AI가 세부 장면과 대화를 유연하게 생성한다.

## Visual Bible / 이미지 / 영상
- 시즌 플레이테스트와 수정이 끝난 뒤 Visual Bible을 먼저 만든다.
- 가족 4명 외모, 연령감, 체형, 복장, 표정, 화풍, 색감, 화면비, 카메라 느낌, 재난 표현 강도를 고정한다.
- 이후 세계관 공용 랜드마크와 시즌 핵심 장면을 일괄 제작한다.
- 모든 선택지마다 그림을 만들지 않는다.
- 기본 경험은 `텍스트 + 선택 + 삽화`, 정말 중요한 순간만 짧은 영상 사용을 검토한다.
- 특정 생성도구는 지금 고정하지 않으며 제작 시점에 캐릭터 일관성·참조 이미지·영상 품질·비용을 다시 비교한다.

## 다른 플레이어를 위한 장기 방향
- 시나리오 데이터와 플레이어 세이브를 분리한다.
- 같은 시즌을 여러 사람이 서로 다른 선택으로 플레이할 수 있게 한다.
- 장기적으로 웹 기반 인터랙티브 게임으로 확장할 수 있으나 최소 3개 이상의 정식 시즌을 실제 플레이해 재미를 검증하기 전에는 웹앱/DB/회원가입/대형 게임엔진 개발을 하지 않는다.

## 플레이방 ↔ 기획방 피드백 루프
1. 기획방에서 시즌 설계
2. 플레이방에서 실제 플레이
3. 플레이 종료 또는 중간 체크포인트에서 사용자 체감 평가
4. 문제점/아이디어를 플레이테스트 기록에 보존
5. 기획방에서 원인 분석 및 시스템/시즌 수정
6. 필요 시 재플레이
7. Scenario v1.0 동결
8. Visual Bible/미디어 제작

## 정보 저장 원칙
- GitHub `cetin072/survival-interactive-series`가 Source of Truth다.
- ChatGPT 기억이나 이전 채팅보다 저장소의 최신 Canon / State / Log를 우선한다.
- 아이디어는 우선 INBOX에 잃지 않게 저장하고 이후 분류한다.
- 사용자는 저장 위치를 기억할 필요가 없다.

## 메타 명령
- `생존기록 시작` / `새 생존게임 시작` → 승인된 정식 시즌 또는 명시된 튜토리얼 플레이 시작
- `생존기록 이어서` / `생존게임 이어서` → 최신 저장 상태에서 계속
- `메모: ...` → 아이디어 보존 및 분류
- `설정확정: ...` → 공식 설정으로 승격
- `버그: ...` → 플레이테스트 문제 기록
- `상태` → 플레이어 공개 상태 요약
- `저장` → 체크포인트 저장
- `종료` → 현재 상태 저장 후 세션 종료

## 공개 저장소 주의
- 현재 저장소는 Public이다.
- API 키, 토큰, 비밀번호, 실제 개인 주소·연락처·민감정보를 저장하지 않는다.
- 외부 플레이어가 실제로 생기면 GM 스포일러 데이터는 별도 Private 저장소나 서버측 저장소로 분리하는 것을 검토한다.
