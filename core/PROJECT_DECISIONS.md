# PROJECT DECISIONS — Design Reference v4

이 문서는 **프로젝트의 장기 제작 방향**만 기록한다.
실제 플레이 런타임에는 기본 로드하지 않는다.

> 플레이 운영 핵심: `runtime/GM_KERNEL.md`
> 캐릭터 최신값: `core/CHARACTERS.json`
> 지속 세계/거점/관계: `core/PERSISTENT_CANON.md`
> S01~S05 중간점검: `docs/MIDTERM_REVIEW_S01_S05.md`
> Thin Engine 설계: `docs/THIN_ENGINE_SPEC_V0_1.md`

---

## 프로젝트 정체성
- 가칭: `생존기록` — 정식명 미확정.
- 장르: 현대 가족 생존 인터랙티브 드라마 / MUD + 숫자 선택지 + 자유행동.
- 주 타깃: 30~40대 남성.
- **재미와 몰입이 0순위**다.
- 현실 생존 해설은 본편에 끼우지 않고 시즌 종료 후 선택형 AAR로 분리한다.

## 현재 개발 단계 — S01~S05 완료
5회의 정규 시즌 플레이로 핵심 시스템 탐색 단계는 상당 부분 완료됐다.

현재 판정:
- 시스템 부족 단계가 아님.
- 핵심 재미 축과 조작방식은 확인됨.
- Runtime/Canon 구조도 실전 운용 가능 수준에 도달.
- 현재 핵심 과제는 **선택 비용, 장면 박동, 시즌 다양성, 가족 자율성의 실제 실행 강도**다.

따라서 S06 이후에는 새 시스템·새 규칙을 쉽게 추가하지 않는다.
먼저 기존 Runtime으로 해결 가능한지 확인한다.

---

## 캐릭터 관리
가족의 나이·학년·성향·역할을 이 문서에 중복 저장하지 않는다.
`core/CHARACTERS.json`이 최신 캐릭터 Source of Truth다.

가족 4명은 독립 파티원이며 자율행동·의견·실수·갈등·경험 누적이 가능하다.

## 조작 원칙
불변:
`복잡한 세계를 단순한 입력으로 다룬다.`

기본 입력:
- 숫자 선택
- `3 → 5 → 1` 순차 복수선택
- 필요 시 가족 역할분담
- 자유행동

복수선택은 유지하되 모든 행동 성공을 보장하지 않는다.
세부 비용 처리는 `runtime/GM_KERNEL.md`를 따른다.

---

## 정식 시즌 제작 철학
완성 대본을 먼저 만들지 않는다.
플레이 직전 Hidden World Seed만 잠근다.

핵심:
`세계는 먼저 존재하고, 이야기는 플레이로 생긴다.`

첫 플레이 전 미리 고정하지 않는 것:
- 정답 루트
- 의무 장면 순서
- 확정 클라이맥스
- 하나의 확정 엔딩

## 작품의 핵심 재미 축
1. **가족 운영** — 4인이 보호대상이나 기능 캐릭터가 아니라 실제 파티로 작동.
2. **거점 성장** — 단순 재고가 아니라 할 수 있는 일의 증가.
3. **이해관계 기반 협업** — 가족·이웃·기관 사이 제한과 비용이 있는 협력.
4. **독립적인 세계 압력** — 플레이어가 준비해도 세계는 계속 움직임.
5. **비싼 선택** — 무엇을 할지보다 무엇을 우선하고 포기할지가 중요함.

### 목표형
S01~S05에서 가장 잘 작동한 요소를 결합한다.

`S01 재난 박동 + S02 거점 성장 + S03 외생압력/협업 확장 + S04 정상사회 현실성 + S05 Runtime/AUTO/MUD UI`

---

## 본편 품질 기준
- 플레이어가 당연히 알고 있을 정보는 선택 전에 제공.
- 시간·거리·자원·기회의 실제 비용.
- 복수선택 순서가 결과에 영향.
- 가족의 독립 행동 또는 제안.
- 실질적 손실/포기 가능성.
- 이전 선택이 나중에 돌아오는 인과관계.
- Fail-Forward.
- 장기 시즌은 의미 있는 Phase 변화.
- Phase 변화 시 플레이 행동 종류도 변화.
- 평온한 반복 운영은 과감히 압축.
- 메인 압력이 끝나면 시즌 종료 우선 검토.

## NORMAL 방향
정식 본편 기본은 NORMAL 계열이다.

목표:
`합리적인 플레이를 하면 가족 생존 가능성은 높다. 그러나 모든 목표를 동시에 무손실로 지키는 것이 매 시즌 기본값은 아니다.`

난이도는 임의 사고보다:
- 선택 비용
- 정보 부족
- 판단 시간
- 회복 여유
- 동시 요구 충돌
- 일부 되돌릴 수 없음
으로 만든다.

핵심:
**강제 실패가 아니라 강제 비용.**

---

## 시즌 다양성 원칙
같은 재난명만 피하는 것으로 충분하지 않다.
연속 시즌에서 **같은 플레이 행동군**을 반복하지 않는다.

특히 S01~S05에서 충분히 검증된 반복축:
- 광역 전력/통신 장애
- 단수
- 연료·물류
- 가족 합류 후 외곽거점 이동
- 외곽 전력/물 활용

다음 시즌군에서는 가능하면 다른 압력과 다른 행동 종류를 우선 검증한다.

거점이 강해졌다는 이유로 거점을 무효화하지 않는다.
대신 거점이 답하지 못하는 이동, 가족배치, 의료, 행정, 생계, 지역특성, 시간, 책임 등 다른 축을 사용할 수 있다.

---

## 가족 + 확장 네트워크
가족 4명은 감정·위험·개인 이해관계의 핵심 파티다.
최씨·이장·협력가구·기관은 전략적 확장 네트워크다.

규모가 커져도 가족이 화면에서 사라지지 않는다.
반대로 가족을 살리기 위해 매 턴 억지 갈등이나 전원 대사를 넣지도 않는다.

좋은 가족 행동:
- 플레이어가 못 본 것을 발견
- 자기 역할에서 스스로 처리
- 운영 변경 제안
- 중요한 순간 다른 의견 제시

## 시각 자산
- 기본은 텍스트 MUD + 선택.
- 플레이 중 Text Visual Grammar를 우선한다.
- 실제 삽화/영상은 시즌이 충분히 굳은 뒤 선별 제작한다.
- 핵심 순간의 제한적 비주얼 실험은 가능하다.

## 시즌 종료 후 자산화
필요할 때만:
1. 플레이 Canon 보존
2. 시스템 복기
3. 현실 생존 복기
4. 재사용 가능한 시나리오 구조 추출
5. Branch Map/Scenario 동결 검토
6. Visual Bible/미디어 제작

모든 시즌을 Scenario v1.0까지 즉시 완성할 필요는 없다.

## Thin Engine v0.1 실험 — 승인
S01~S05에서 반복 확인된 GM의 기억·상태·표현 오류를 줄이기 위해 **얇은 보조엔진 실험을 허용한다.**

목적은 게임 제품화가 아니다.
목적은 ChatGPT GM에게서 다음 반복 업무를 분리하는 것이다.
- 현재 시간·위치·가족 동행관계 기억
- 차량·거점·자원 현재 상태 기억
- 복수행동 순차 처리
- 상태/권한 모순 검사
- MUD 화면의 반복적인 상태 표현

권장 책임 분리:
- **프로그램**: State Engine + Validator + MUD Renderer
- **AI GM**: 세계 창조 + 인물 + 사건 + 선택 + 즉흥반응
- **플레이어**: 판단과 자유행동
- **GitHub**: 장기 Canon/시즌 기록/회고/체크포인트

핵심 원칙:
`AI proposes, engine commits.`

AI가 상태를 직접 확정하지 않고 구조화된 변경을 제안하면 엔진이 현재 Live State와 검증한 뒤 반영한다.

Thin Engine v0.1의 구체적 범위와 제외사항은 `docs/THIN_ENGINE_SPEC_V0_1.md`를 따른다.

### 취미 보호선
- 로그인·멀티유저·결제·운영자 CMS·대형 인벤토리·복잡한 게임서버는 v0.1에 넣지 않는다.
- AI 삽화 자동생성도 v0.1 핵심 범위가 아니다.
- 개발의 목적은 **플레이를 더 편하고 안정적으로 만드는 것**이다.
- 개발 자체가 플레이보다 더 큰 프로젝트가 되면 기능 확대를 중단한다.

## 개발 원칙
- GitHub `cetin072/survival-interactive-series`가 장기 Source of Truth다.
- Runtime은 `GM_KERNEL + CHARACTERS + PERSISTENT_CANON + SAVE_STATE` 중심으로 가볍게 운용한다.
- 새 문제가 생길 때마다 새 규칙 파일을 만들지 않는다.
- 현재 핵심 병목은 코드보다 게임 디자인 실행이다.

### 구현 순서
1. Thin Engine v0.1의 Live State/Validator/MUD Renderer 최소 구현.
2. S01 일부 구간으로 회귀테스트.
3. AI GM 연결 후 State Proposal → Validator → Commit 흐름 검증.
4. 신규 시즌에 제한 적용.
5. 재미와 오류율이 개선될 때만 범위 확대 검토.

### 제품화 게이트
대형 게임엔진/복잡한 앱 개발은 아직 서두르지 않는다.

우선 검증:
1. S06에서 Runtime v4와 Decision Collision 검증.
2. Thin Engine v0.1이 실제 기억/정합성 오류를 줄이는지 확인.
3. 시즌 다양성 및 가족 자율성 개선 확인.
4. S06 또는 S07 이후 외부 블라인드 플레이 1회 이상.

그 뒤:
- 얇은 MUD 웹 UI의 유지/확장은 적극 검토 가능.
- 복잡한 전용 게임엔진/DB는 외부 플레이에서도 핵심 루프가 재미있다는 증거가 생긴 뒤 결정.
