# C04 / WORLDLINE_04 / S01 — 제4시도 정방향 동시시각 교차서사 계약 V1

상태: USER_APPROVED_CHRONOLOGICAL_RESTART / **ATTEMPT_04_PLAYING** / LIVE_SAVE_IS_IN_DATABASE

**초기 세션 준비의 역사적 기록 (2026-10-20; 2026-10-24 현재 이미 진행 중):** C04 제3시도 Save43/D1 19:15 전체가 `survival_rpg.state_archives`의 `PRE_RESTART_ATTEMPT_04_FULL_SNAPSHOT`으로 보존됐다. 기존 두 시도 및 제3시도 원문 **82건 모두 보존**, 제3시도 세션 CLOSED. 제4시도 Save **44 / D0 09:03 / S01_A04_D0_0903_FORWARD_OPENING_PENDING**, 활성 세션 `4306a61c-e760-4db9-b94a-9359c284a5d1` OPEN, 저장 메시지 0건. `get_c04_turn_context_v1`의 다음 ticket turn_no=0 검증 통과. **이 문서를 다시 읽어도 재시작을 반복하지 않는다.** 실제 진행 후 최신 수치는 DB를 우선한다.
이 문서의 적용 대상은 몽골 약 2km 소행성 충돌과 지구적 지각 연쇄재난의 세계관4 **제4시도**다. 제1~3시도의 Save와 공개 USER/GM RAW는 원문 그대로 영구 보존하고, 시간순 4번째 시도에서 이전 플레이의 자원·NPC·선택·결과를 자동 승계하지 않는다.

## 1. 독자가 혼란을 겪지 않는 것이 가장 중요한 연출 규칙

1. **본문에서 시간은 오직 정방향.** 카메라 A/B/C가 나라와 사람을 넘나들어도 같은 한국 표준시(KST) 기준으로 시간 표기를 통일한다. 다음 장면의 시각은 바로 전 장면과 같거나 늦어야 한다. D0 → D1 → D2의 날짜도 역행 금지.
2. **동일 시간대 교차는 필요할 때만.** 예: `D0 09:03 · 창원` → `같은 시각 · 몽골` → `D0 09:12 · 창원` → `같은 시각 · 중국`. 몽골 현지의 시차를 별도로 개입시키지 않고 모든 장면 시각은 KST로 쓴다.
3. **과거를 먼저 보여주는 영화식 콜드오픈도, 미래를 보여주고 과거로 되돌아가는 것도 이번 버전에서는 사용하지 않는다.** D0 11:43 몽골 소행성 충돌은 시계가 실제로 그 시각에 이르렀을 때 독자에게 발생한다. 이전 제3시도의 `D0 11:43 충돌 → D0 09:03 창원` 반전 편집을 반복하지 않는다.
4. **회상은 기본 사용 금지.** 특별한 인물의 기억이 꼭 필요하다면 현재 시각의 대사·감각·짧은 기억으로 처리한다. 별도 과거 장면으로 카메라를 옮기는 예외는 훗날 사용자가 허용할 때만 사용한다.
5. **같은 턴에서 수십 분·시간을 건너뛰는 것도 가능하되 진행 방향만 앞으로.** 결정적인 행동 전에 사용자 선택을 먼저 묻는다. 평범한 대기·배송 반복은 압축한다.
6. **사건 발생시각과 정보를 입수한 시각을 구분한다.** 나중에 알게 된 '전날 중국의 피해'는 현재의 뉴스·목격자 증언으로 보여주고 카메라를 전날로 되돌리지 않는다. 전지적 카메라 A는 현재 시간의 전파·생존자·시설 파괴·연쇄 위기를 직접 보여준다.
7. **장면 헤더:** 장소가 전환될 때 KST 단일 시간 라벨과 구체적 장소를 짧게 표기한다. 독자가 `언제? 어디?`를 다시 추리할 필요가 없어야 한다. 너무 많은 메타 시계나 거리 보고서를 본문에 넣지는 않는다.
8. **검수 게이트:** GM은 원문 공개·저장 전에 순서대로 장면의 KST 시각을 가볍게 비교한다. 구간이 겹치거나 시간이 불명확하면 같은 시각의 컷인지 명확히 적고, 뒤로 가면 본문을 바로잡는다. 이 검수는 매번 외부 AI를 부르거나 전체 과학 자료를 다시 읽으라는 뜻이 아니다.

## 2. 초기 인물·시간 설정

- 주인공: 이태준, 35세, 미혼·자녀/현재 연인 없음, 창원 성산구 가음동의 일반 배송기사.
- **제4시도 첫 게임 시각:** `D0 09:03 KST`. 이태준의 평범한 배송 업무로 시작한다. 같은 시각 몽골 고비사막과 주변 지역에서도 재앙 이전의 실제 사람·작업·움직임을 보여줄 수 있다. 첫 페이지부터 독자가 충돌 이후를 미래로 본 것처럼 쓰지 않는다.
- 소행성: 약 2km, **몽골 남부 고비사막**, 충돌의 확정된 감독 시각 `D0 11:43 KST`. 사용자 행동 때문에 늦춰지지 않는다.
- **동시 진행 예시(정사 강제 각본 아님):**
  - D0 09:03 창원 — 첫 배송과 평범한 사람들.
  - 같은 시각 D0 09:03 몽골 — 충돌을 모르는 사람들과 지형의 고요함.
  - D0 10:30~11:40 창원/국가별 경보·배송·준비. 반드시 당사자의 선택을 존중한다.

  - D1~D7 몽골 원점에서 시작된 허구적 전 지구 판 연쇄활성화로 중국·한반도·일본 등 각 지역에서 독립적 지각재난·지진·해일·화재가 시간차로 진행한다. 일본은 분기이지 주 경로를 대체하지 않는다.

## 3. A/B 연출의 목적

- **외부 카메라:** 몽골 충돌→중국→황해→한반도→창원의 큰 재앙 경로는 유지하되, 그 자체가 지역별 촬영 순서나 인물 중심의 연속 드라마를 요구하지 않는다. 대규모 재난 현장 또는 태준의 현재·앞날에 직접 이어질 결과를 보여줄 때 **짧게 전환**한다. 모두에게 동일한 강도의 물리적 충격을 강제하지 않는다.
- **본류 카메라:** 이태준의 생존과 인물 관계·선택·실행 결과에 충분한 장면을 준다. 그가 보거나 전달받지 못한 외부 컷의 사실을 자동으로 알지는 못한다. 외부에 장기 서사선을 만들었다면 나중에 태준과의 직접적 인과 연결·합류가 필요한 경우에만 허용한다.
- **별도 재난 분기:** 일본 규슈·시코쿠 대지진·해일 및 장기 침강은 실제 큰 재난이 발생할 때 짧게 보여준다. 일본 인물의 일상·가족·구조·후속 인터랙션을 별도의 주인공 서사처럼 지속하지 않는다.
- 모든 컷은 단일 KST 정방향 시간축이며 재앙의 영향이 창원에 닿을 때 **이태준의 실제 행동·감각**을 중심으로 묘사한다. 외부 컷은 선택적이고 전환 없는 긴 태준 본류 장면이 기본이다. 전 지구 지각 연쇄재난과 장기 물류·식량 위기의 전개는 남는다.

## 3-1. 독자가 부담 없이 누르는 플레이 선택

- 평범한 시간순 카메라 교차에서는 본문 뒤에 억지 선택지를 두지 않는다. 사용자가 `ㄱ`이라고 하면 다음 의미 있는 장면을 진행한다.
- 이태준의 위험 감수·대피 방향·제한된 준비 시간·중요 관계·이동 등 결과를 바꿀 갈림길에서는 **1, 2, 3으로 구분된 짧고 구체적인 선택지를 반드시 제시하고 자유입력도 허용**한다.
- 사용자가 `ㄱ`만 입력한 상태에서 중요한 미결 선택지를 임의로 골라 다음 시간으로 점프하지 않는다. 한 번 정한 선택권을 본문의 설명이나 과도한 장면 전환 속에 숨기지 않는다.
- 실제 본문은 `GM_RULES.md`의 `C04_DECISION_MENU_V1` 규칙을 우선한다.

## 4. 플레이 경계 및 출판

- 대재앙이 일어나는 사실 자체는 GM 고정 환경. 이태준의 구체적 위치·행동·동행·물자·생존 결과는 사용자의 선택과 주변 사람들의 독립적 행동으로 결정된다.
- 큰 재난은 강렬하고 짧은 외부 컷으로도 보여줄 수 있다. 평범한 반복·부연 설명·일상 행정 보고를 압축하고 주요 인물의 첫 묘사와 태준 중심 대사·행동·장면 밀도는 충분히 확보한다. 4,000~6,000자는 유연한 참고치로 삼고 **진전 없는 장면으로 채우지 않는다**.
- RAW와 발행용 소설은 다른 층위다. 시도4 원문을 기존 시도3 RAW와 혼합하거나 과거 원문을 편집하여 '플레이 정사'로 만들지 않는다.
- **운영 지시문·재시작 승인만으로 제1화 RAW를 임의로 등록하지 않는다.** 첫 실제 게임방 턴에서 그 방의 USER 입력과 최종 GM 본문을 함께 저장한다. `get_c04_turn_context_v1`·`commit_c04_turn_v1` 사용, 낡은 ticket 재활용 금지.

## 5. 리셋 안전 기준

**다음은 2026-10-20에 이미 완료한 최초 재시작 절차의 역사적 기록이다. 현재 제4시도에서는 다시 실행하지 않는다.**

제4시도로 실제 재시작하기 전에는 현재 제3시도 최신 Save 전체(JSON state와 gm_state, 버전), RAW 개수, 세션 3개를 확인한다. 완전한 스냅샷을 별도 보존하고, 기존 세션을 CLOSED로 종료한 후 새 UUID 세션을 개설한다. 최신 Save 버전 CAS로 새 최소 초기 상태를 구성하고, 이전 RAW·C03 Save를 건드리지 않는다. 신규 세션에는 최초 실제 게임 턴 전까지 메시지 0건. 다시 시작 작업이 끝난 뒤에는 **이 문서의 리셋 절차를 재실행하지 않는다**.
