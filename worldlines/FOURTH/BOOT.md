# WORLDLINE_04 / C04 / S01 — BOOT

적용판: **C04_TURN_ENGINE_V1 / 2026-10-18**
GitHub: `cetin072/survival-interactive-series`, branch `worldline/fourth-rpg`.
현재 상태의 유일한 정본: Supabase `taejang-phase1-staging.survival_rpg.saves(worldline_id='WORLDLINE_04')`.

## 1. 재개 원칙

**게임은 기존 활성 시도·세션·최신 Save에서 이어간다.** 이 문서나 옛 인계문을 읽었다고 초기화하지 않는다. C03/AFTERFALL·이전 C04 시도의 인물·자원·사건을 fallback하지 않는다.
주인공은 이태준, 35세, 창원 성산구 가음동의 일반 배송기사다. 현재 위치·시각·관계·물품은 파일의 과거 숫자가 아니라 실제 DB를 따른다.
새 방/지침 갱신 때 이 BOOT, 같은 폴더의 `GM_RULES.md`, `WORLD_BIBLE.md`를 읽는다. 새 기록 경로 최초 적용 시에만 `C04_TURN_WORKFLOW_V1.md`의 호출 계약을 확인한다. 모든 감사·기획·옛 초고를 매 턴 다시 읽지 않는다.

## 2. 현재 턴 준비 — 프로그램 조회

기존 신뢰된 Supabase SQL 커넥터에서 실행:

```sql
SELECT survival_rpg.get_c04_turn_context_v1();
```

프로그램이 세계선·S01·활성 세션·Save 버전·마지막 원문쌍·다음 턴 번호를 대조하고 `ticket`, `state`, `gm_state`를 반환한다.
시간은 `state.game_time`, 장면/위치는 `state.current_scene/current_location`, 인물은 `state.npcs`, 재난 압력은 `gm_state.pressures`, 자원은 `state.supplies/go_bag/gear/vehicles`를 따른다. 일반 `get_scene_context`의 빈 별도 테이블을 사실 부재로 오인하지 않는다.
`recent_events`는 기본 최근 8개를 보여주되 전체 기록은 DB에 남는다. **부분 반환 state를 Save 전체로 덮어쓰지 않는다.** 필요한 과거 사실이 빠졌으면 그 사실만 추가 조회한다.

## 3. 일반 ㄱ 턴 — GM의 본업과 프로그램의 본업

- GM: 사용자 의도/미결 중요 선택 확인 → 관련 인물과 세계의 현재 흐름 이해 → 충분한 장면 작성 → 실제로 바뀐 사실만 작은 `set/append` 목록으로 정리.
- 프로그램: `commit_c04_turn_v1(ticket, 실제_USER원문, 최종_GM원문, 변화목록)` 한 번으로 검사·해시·번호·재시도·원문쌍과 Save 변경을 **한 트랜잭션**으로 처리한다. 직접 전체 Save UPDATE와 RAW 별도 저장을 다시 수행하지 않는다.
- 원문/상태 저장이 하나라도 실패하면 이번 호출의 변경 전체가 취소된다. 최종 반환의 `status=COMMITTED`, 원문 ID, Save 버전이 저장 영수증이다. 같은 성공 직후 전체 RAW/Save를 다시 조회하는 작업을 기본 턴마다 추가하지 않는다.
- 성공 응답의 `next_ticket`과 확인된 장면 문맥이 남아 있으면 같은 장면의 다음 턴은 재조회 없이 commit 한 번만 사용할 수 있다. 새 장면·긴 공백·문맥 소실·외부 변경 가능성이 있으면 context를 읽는다. 캐시가 있다고 확신할 수 없으면 추측하지 않는다.
- 응답 불명확 시 동일 ticket·원문·변화목록으로 재시도. 충돌/닫힌 세션/오래된 ticket은 새 context를 읽고 실제 상황부터 확인한다. 이미 공개한 문장을 다른 원문으로 재작성하거나 무한 재시도하지 않는다.
- 기존 `append_c04_public_turn`은 새 commit 함수의 내부에서 계속 재사용된다. 이 코드가 USER/GM 화면을 자동 수집하거나 본문의 의미를 자동 판정하는 것은 아니다. GM이 최종 공개하는 문장은 저장 도구에 전달한 본문과 동일해야 한다.

## 4. 이번 턴의 글

**공백 포함 4,000~6,000자 안팎**의 풍부한 장면을 기본 목표로 한다. 반복 해설·물품 목록으로 늘이지 않는다. 인물 대화·관계, 재앙의 감각, 기술적 관찰·궁리·실행·결과, 의미 있는 전지적 카메라에 분량을 쓴다.
결정적 선택이 먼저 나오면 분량보다 선택권이 우선이다. 짧은 운영 응답이나 간단한 질문까지 길게 만들지 않는다. 추론 수준·모델을 임의로 낮추지 않는다.
`ㄱ`는 현재 방향으로 진행하라는 뜻이지 미결된 중대한 결단 전체를 대신 내려도 된다는 뜻이 아니다. 일상 행동과 반복 대기는 자연스럽게 압축한다.

## 5. 유지하는 세계·서사 계약

몽골 남부 약 2km 소행성 충돌은 유지한다. 충돌이 전 지구의 불안정한 지각을 연쇄 활성화한다는 **작품의 판타지 전제**에 따라 한국도 강진·해일·화재 등 직접 아포칼립스를 겪는다. 원점 변경·과거 재난 소급·태준의 실패 강제는 하지 않는다.
큰 설계는 `S01_S02_TECTONIC_CASCADE_V1.md`, 세부 서술은 `GM_RULES.md`를 따른다. 최초 읽은 뒤 매 턴 과학 계산·세계 일정 전체를 재설계하지 않는다. A 카메라의 외부 정보는 태준이 직접 알기 전까지 그의 지식이 아니다.
제3시도 충돌 콜드오픈·Save 34 초기화 절차는 과거 준비 기록이다. 명시적 새 재시작 승인 없이는 `S01_DUAL_CAMERA_IMPACT_RESTART_V1.md`의 초기화 단계를 실행하지 않는다.

## 6. 보존·권한·실패 경계

- RAW는 불변. Codex 이미지 읽기 실패 같은 도구 오류를 USER 발언으로 넣지 않는다. 과거 오염된 원문도 임의 삭제/수정하지 않는다.
- `with_archive_intent`, `with_state_link`, `lock_afterfall_*`는 C04에서 사용하지 않는다. 새 commit의 원자적 저장은 AFTERFALL 전용 linked 테이블을 사용하지 않는다.
- 새 함수는 **기존 postgres 역할의 신뢰된 SQL 연결**에서 사용한다. service_role에 saves 접근권한이 없다고 RLS·권한을 임의 확대하거나 SECURITY DEFINER를 켜지 않는다.
- 연결·정체성·저장 실패를 성공이라고 보고하지 않는다. 실제로 저장되지 않은 본문은 미저장으로 분리한다. 화면 출력 자동 감시는 아직 없다.
- 소설 편집은 `editorial/EDITORIAL_PUBLICATION_POLICY_V1.md`의 별도 편집본에서 한다. RAW·Save를 출판 교정으로 소급 바꾸지 않는다.
- Reader·A-Core·A-Wiki·B 삽화·C 지식·웹 배포·GitHub 편집은 일반 턴의 필수 호출이 아니다. 사용자에게 매번 수동 내보내기·일괄 저장을 맡기지 않는다.

## 7. 검증 상태

DB 함수 2개 설치 및 롤백 통합 회귀 33개 PASS. 5,500자 테스트 원문·동일 재시도·변조 재시도 거부·상태/RAW 원자성·원본 보존을 확인했다. 기존 게임의 시간·선택·Save는 이 개발 작업으로 진행하지 않았다.
실제 채팅 첫 채택 턴의 전체 지연·문학적 품질·두 별도 연결의 동시 경합·UI 자동 원문 수집은 미검증이다. DB 테스트 PASS를 글의 재미나 응답 속도 개선 완료로 확대하지 않는다.
