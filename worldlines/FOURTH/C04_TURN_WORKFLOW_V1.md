# C04_TURN_ENGINE_V1 — ㄱ 이후 작가와 기록 프로그램의 분담

상태: DB_DEPLOYED_AND_ROLLBACK_TESTED / LIVE_CHAT_ADOPTION_PENDING
기준일: 2026-10-18. 대상: WORLDLINE_04 / C04 / S01, 기존 활성 시도 그대로.
승인: 사용자는 추론 수준·원문 보존을 낮추지 않고 더 풍부한 장면을 쓰며, 기계적 조회·저장을 즉시 프로그램에 넘기도록 요청했다. 별도 유료 API·서버·코덱스 상시 워커는 만들지 않았다.

## 1. 실제 분석 범위

기존 BOOT/GM_RULES와 라이브 append_c04_public_turn, append_public_transcript_turn, append_public_transcript_message, open_public_transcript_session을 읽었다.
기존 함수는 SHA·UUID·USER/GM 순서를 처리하지만, GM이 현재 Save와 세션을 조회하고 의미 변화를 정리하며 Save UPDATE와 RAW 저장을 별도로 조율했다.
이 문서는 그 운영 흐름을 분해한 결과다. LLM 내부 추론별 소요시간이나 과거 7분 응답의 초 단위 프로파일은 확보하지 않았으므로 추론·네트워크·DB 각각의 시간을 지어내지 않는다.

| 단계 | 남길 담당 | 바뀐 일 |
|---|---|---|
| ㄱ·계속·구체 행동의 의미와 미결 선택 확인 | GM | 중요한 선택까지 ㄱ를 포괄 승인으로 보지 않음 |
| 현재 세계선·활성 세션·Save 버전·다음 턴 확인 | 프로그램 | get_c04_turn_context_v1 한 번으로 조회·검증·ticket 생성 |
| 관련 인물/자원/앞선 사건과 세계 시간표 이해 | GM + 프로그램 | 실제 state/gm_state 제공, recent_events는 기본 최근 8개만 반환하되 전부 DB 보존. 필요시 0~50 범위 또는 특정 기록을 추가 조회 |
| 장면·대사·인과·전지적 카메라·선택권 | GM | 한 턴 기본 4,000~6,000자 안팎의 충분한 장면 목표. 의미 없는 해설로 분량 채우지 않음 |
| 실제로 달라진 사실 판단 | GM | 전체 Save를 다시 쓰지 않고 필요한 set/append 변화만 제시 |
| 유효성·동시 변경·기대 버전·해시·재시도·원문/Save 저장 | 프로그램 | commit_c04_turn_v1이 기존 안전 writer를 재사용해 단일 트랜잭션 처리 |
| 최종 공개 응답 | GM/ChatGPT 화면 | 저장 도구에 전달한 최종 본문과 동일하게 출력. 서버가 ChatGPT 화면을 자동 수집한다는 뜻은 아님 |
| 문학적 편집·Reader·Wiki·B/C·배포 | 별도 후속 작업 | 일반 턴에서 실행하지 않음. 기존 자동화나 RAW 정책은 중단하지 않음 |

## 2. 평시 실행 — 외부 도구는 기본 두 단계, 캐시가 있으면 저장 한 번

**부팅/재개/문맥 소실/새 장면 확인:** 신뢰된 기존 Supabase execute_sql 연결에서 다음을 실행한다.

```sql
SELECT survival_rpg.get_c04_turn_context_v1();
```

반환하는 `ticket`을 수정하지 않고 보관한다. worldline/season/session/expected_version/turn_no/base_digest는 프로그램의 결과다. 번호·UUID·해시를 GM이 새로 계산하지 않는다.
반환 state/gm_state에서 현재 장면·인물·자원·지식·압력을 확인한다. recent_events는 **표시용 일부**이므로 반환 state 전체를 UPDATE로 덮어쓰지 않는다. 핵심 옛 사실이 필요하면 그때 해당 원본을 읽는다.

**작성 후 저장:** 실제 USER 입력과 최종 GM 본문, 이번에 실제로 바뀐 항목만 전달한다.

```sql
-- 기획용 호출 형식. 아래 자리에 임의 원문/사건을 넣어 실게임으로 저장하지 않는다.
SELECT survival_rpg.commit_c04_turn_v1(
  p_ticket := '<조회한 ticket 그대로>'::jsonb,
  p_user_content := '<실제 사용자 메시지>',
  p_gm_content := '<최종 공개할 GM 본문>',
  p_changes := '<실제 변화의 JSON 배열>'::jsonb
);
```

각 변화는 `target: state 또는 gm_state`, `op: set 또는 append`, `path: 문자열 배열`, `value: 새 값`이다. 특정 기존 값을 전제로 바꿀 때 `expect`를 함께 넣을 수 있다.
`set`은 지정한 한 필드를 수정하며 부모 경로는 실제 존재해야 한다. 배열 인덱스는 기존 인덱스만 변경한다. `append`는 기존 배열에 요소 하나를 추가한다. 없던 NPC는 `state.npcs` 아래 해당 NPC 객체를 한 번에 추가한다.
`recent_events`는 append만 허용한다. 세계선·시즌·시도·활성 세션과 저장 영수증은 게임 델타로 변경할 수 없다. 플레이어의 `state.game_time` 역행, 자료형 파괴, 누락된 부모, 잘못된 순서는 오류로 멈춘다.

**성공 응답:** 원문 두 개의 ID, Save 버전, 원문 길이, 실제 상태 변화 여부, `next_ticket`이 반환된다. 본문 전체나 Save 전체를 다시 돌려주지 않는다. 성공 후 같은 이야기/상태를 검증하려고 별도 전체 readback을 매번 호출하지 않는다.
확인된 같은 장면을 계속하고 `next_ticket`과 상태 문맥이 온전히 남아 있으면 다음 턴은 재조회 없이 commit 한 번으로 처리할 수 있다. 다른 방/운영자가 중간에 바꾼 값은 버전 및 스냅샷 digest/세션 순서 검사로 차단된다. 문맥이 불확실하면 read를 생략하지 않는다.

## 3. 실패/재시도/상태 버전

- 최신 요청의 응답을 받지 못했으면 **동일 ticket·동일 원문·동일 changes**로 재시도한다. 동일 요청은 같은 원문 ID/처리 영수증을 반환하고 상태를 두 번 적용하지 않는다.
- 같은 요청에 다른 본문/다른 changes를 보내면 23505 충돌. 최신보다 오래된 영수증 재시도는 fail closed하며 새로 기록하지 않는다.
- stale ticket/외부 변경은 40001: 새 context를 읽고 실제 상황을 확인한다. 옛 결과를 무조건 덮어쓰거나 무한 재시도하지 않는다.
- 부분적 RAW나 Save만 남기지 않는다. 한 호출에서 실패하면 해당 호출의 RAW·세션순서·Save 변경이 함께 취소된다.
- 서사 상태 변화가 없으면 Save의 서사 버전은 증가하지 않지만 RAW는 보존한다. 마지막 처리 영수증과 last_transcript_turn_no는 내부 운영 메타데이터로 갱신된다.
- 중요한 미결 선택을 프로그램이 대신 결정하거나, 이야기를 읽고 의미 델타를 추출하는 AI를 추가로 실행하지 않는다. 그 판단은 GM의 책임이다.
- 내부 영수증은 마지막 처리 1건만 gm_state에 둔다. 원문 이력은 기존 RAW에 그대로 남는다. 새 DB·작업 대기열·영구 워커를 만들지 않는다.

## 4. 글의 밀도와 분량

일반적인 전개 턴의 목표는 **공백 포함 4,000~6,000자 안팎**이다. 숫자를 맞추기 위해 물품 목록·중복 해설·모든 단역 외형을 늘리지 않는다.
재앙의 감각, 중요한 인물의 대화·관계, 관찰→궁리→실행→결과, 두 카메라의 대비에 분량을 쓴다. 결정적 선택에 먼저 도달하면 짧게 멈추고, 단순 답변·운영 확인을 긴 소설로 늘이지 않는다.
사용자의 추론 수준/모델을 임의로 낮추지 않는다. 더 긴 출력은 여전히 시간이 들 수 있으므로 7분이 반드시 1분이 된다거나 품질이 이미 개선됐다고 보장하지 않는다.

## 5. 실행·검증·권한

- 기존 DB에 추가한 함수 2개: `get_c04_turn_context_v1(integer)` 및 `commit_c04_turn_v1(jsonb,text,text,jsonb)`.
- Migration `c04_turn_engine_v1`: 설치와 기본 리허설을 한 트랜잭션에서 수행. 기존 함수/테이블/RLS/데이터를 교체하지 않음.
- 후속 통합 회귀 **33개 통과**. 5,500자 한국어 테스트 본문의 정확한 보존, set/append·버전·동일 재시도·변조 재시도 거부·오염 USER 차단·시간 역행 거부·캐시된 next_ticket·오류 후 부분 저장 없음 검증.
- 모든 시험용 본문·Save·세션 변경은 ROLLBACK. C04 Save 39와 기존 RAW 74개, AFTERFALL Save 295 및 각 행 내용 동일 확인. 진짜 게임 턴을 새로 생성하지 않음.
- 현재 호출 역할은 `postgres`인 기존 신뢰된 SQL 커넥터다. 새 함수는 SECURITY INVOKER이며 PUBLIC/anon/authenticated/service_role에 실행 권한을 주지 않았다. 서비스 역할에 saves SELECT/UPDATE가 없다는 사실을 발견했지만 권한을 넓히거나 SECURITY DEFINER로 우회하지 않았다.
- 실채팅의 첫 채택 턴, 별도 두 연결의 동시 경합, 화면 최종 출력 자동 감시, 문학적 품질·사용자 체감 시간 개선은 **미검증**. 앱이 자동으로 새 함수 이름을 발견하거나 기존 채팅 지침이 원격 교체되는 구조도 아님.

## 6. 원본·철회·인계

SQL: `db/C04_TURN_ENGINE_V1.sql`, 회귀: `db/C04_TURN_ENGINE_REGRESSION_V1.sql`.
기존 `append_c04_public_turn`은 수정하지 않고 새 commit 내부에서 재사용한다. 철회 필요시 새 경로 사용을 중단하고 마지막 정상 Save/RAW를 확인한다. 함수 삭제가 필요하다면 새 함수 두 개만 별도 승인 후 제거하고 게임 데이터/기존 함수에는 손대지 않는다.
기존 게임방이 최신 BOOT/GM_RULES 및 이 문서를 1회 읽은 뒤부터 새 경로를 사용한다. 설정 적용 메시지 자체는 게임 턴/RAW로 보관하지 않는다. 사용자에게 매번 수동 저장이나 복사·내보내기를 맡기지 않는다.
