# STRONGHOLD — Persistent State Protocol

목표: 긴 플레이를 여러 채팅방에 걸쳐 이어도 세계 사실과 영구 자산을 잃지 않되, GM이 매번 전체 대화를 다시 읽지 않아도 되게 한다.

## 1. 저장 구조
현재 상태는 세 층만 유지한다.

### A. CURRENT_STATE.json — 지금의 진실
가장 최신의 권위 있는 스냅샷이다.
매번 읽어야 하는 파일은 이것 하나가 중심이다.

추적 범위:
- 시각 / 날짜 / 현재 위치
- 플레이어 상태
- 돈/현금 접근성
- 핵심 자원 밴드
- 도시 거주지
- 외곽 거점
- 차량
- 알려진 사람/동료와 현재 위치·상태
- 주요 관계
- 주요 경로
- 기관/시장/전력/통신 등 현재 세계 상태
- 해결되지 않은 문제
- 최근 중요 변화

### B. LEDGER.md — 영구 사건 장부
Append-only 기록.
모든 턴을 적지 않는다. 되돌리기 어려운 변화만 적는다.

기록 대상 예:
- 새 인물과 중요한 관계 형성
- 사망/이탈/배신/합류
- 거점 취득/상실/시설 완성/파손
- 차량 취득/상실/대파
- 큰 금전 변화
- 장기 부상
- 지역 영구 통제/붕괴
- 세력과 동맹/원한
- 중요한 약속/빚/비밀의 공개
- 플레이어가 정한 장기 원칙

### C. CANON.md — 오래된 안정 사실
CURRENT_STATE에 매번 넣기엔 무겁지만 계속 기억해야 하는 공개 사실.
예: 등장인물 배경, 장소 설명, 거점 역사, 세력의 성격, 과거 주요 사건의 요약.

## 2. 읽는 순서
새 채팅방에서는 절대 전체 과거 원문부터 읽지 않는다.

1. `BOOT.md`
2. `CURRENT_STATE.json`
3. `LEDGER.md` 최근 15~25개 항목
4. 필요할 때만 `CANON.md`

이 방식으로 장기 플레이가 길어져도 부팅 비용을 거의 일정하게 유지한다.

## 3. 업데이트 빈도
매 선택마다 GitHub를 갱신하지 않는다.

### 즉시 체크포인트가 필요한 경우
- 사람 사망/합류/이탈
- 거점/차량 등 큰 자산 상실
- 큰 이주
- 세계 국면이 바뀜
- 게임 날짜가 크게 점프함
- 플레이 종료 요청

### 일반 플레이
대략 3~6개의 중요한 플레이어 결정 또는 하나의 큰 장면 묶음이 끝날 때 한 번 갱신하면 충분하다.

## 4. 수치화 원칙
모든 것을 숫자로 세지 않는다.

기본은 5단계 밴드:
`없음 / 부족 / 보통 / 충분 / 풍부`

다만 결정에 실제 숫자가 중요한 순간에는 수량을 함께 기록한다.
예:
- 연료 22L
- 현금 180만원
- 식수 34L
- 약 9일분

숫자가 다시 중요하지 않아지면 밴드 중심으로 압축할 수 있다.

## 5. 핵심 자원군
- 물
- 식량
- 의료/약
- 전력/배터리
- 연료
- 통신
- 현금/결제 접근성
- 차량
- 도구/수리능력
- 보온/주거
- 정보
- 노동력/사람

거점 능력은 별도로 추적:
- 저장
- 물 확보
- 전력
- 조리
- 난방/냉방
- 수리
- 의료
- 통신
- 식량 생산/보존
- 경계/안전
- 수용 인원

## 6. 사람과 관계
호감도 숫자를 플레이어에게 직접 보여주지 않는다.
내부 기록도 단순 한 숫자보다 짧은 상태 문구를 우선한다.

예:
- `신뢰 높음 / 최근 명령에는 불만`
- `도움 빚 1회`
- `가족 구조를 조건으로 협력 중`
- `도현이 약속을 지킬지 지켜보는 중`

장기적으로 중요한 약속, 구조 경험, 배신, 빚은 LEDGER에 남긴다.

## 7. 모순 방지 원칙
새 장면을 쓰기 전 최소 확인:
- 현재 위치가 가능한가
- 차량과 운전자/탑승자가 같이 있는가
- 이미 잃은 물건을 다시 쓰지 않는가
- 이미 죽거나 떠난 인물이 무단 복귀하지 않는가
- 이동시간이 앞뒤와 맞는가
- 밝혀진 세계 사실과 충돌하지 않는가

모순이 생겼다면 이야기를 억지로 유지하지 말고 가장 작은 수정으로 현재 상태를 우선한다.

## 8. 원문 보존
재미있는 대화 원문은 IP 자산으로 별도 보존할 수 있지만, 런타임 상태의 근거로 매번 읽지 않는다.

원칙:
`RAW PLAY -> LEDGER/CANON -> CURRENT_STATE`

현재 플레이 부팅에는 `CURRENT_STATE`가 최우선이다.

## 9. 부담 제한
GM은 매 턴 세계 전체를 시뮬레이션하지 않는다.

- 플레이어 주변과 현재 관련 지역만 고해상도
- 멀리 있는 지역은 요약 상태
- 최대 3개의 active world front
- 최대 5개의 unresolved major thread
- 중요하지 않은 재고/주민/도로는 필요할 때 생성

이 제한을 지켜 세계가 커져도 운영 복잡도가 폭발하지 않게 한다.
