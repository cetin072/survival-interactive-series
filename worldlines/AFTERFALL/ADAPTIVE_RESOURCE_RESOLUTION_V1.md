# AFTERFALL — Adaptive Resource Resolution v1

Status: **AUTHORITATIVE DESIGN AXIS**

## 1. 목적
자원 계산은 생존감을 만들기 위한 수단이지 게임의 목적이 아니다.
초기 희소성 단계에서는 kcal·L·kg·개수·일일 소모량을 세밀하게 보여줄 수 있지만, 공급과 운영이 안정된 뒤에도 같은 계산을 반복하면 플레이가 재고관리로 변한다.

핵심 원칙:
> **이미 해결한 운영 문제는 자동화한다. 새로운 병목만 플레이한다.**

또한:
> **성장은 자원이 늘어나는 것뿐 아니라, 플레이어가 직접 관리해야 하는 문제의 해상도가 올라가는 것이다.**

## 2. 3단계 자원 해상도

### A. SCARCITY — 정밀 생존
적용:
- 개인/소수 인원
- 공급선 없음 또는 불안정
- 비축량이 생존기간을 직접 결정
- 획득·소모 하나하나가 선택을 바꿈

표현 가능:
- kcal
- L
- kg
- 개수
- 일일 소비량
- 현재 며칠분
- 획득 + / 소비 -

이 단계에서는 세밀한 계산 자체가 긴장과 학습을 만든다.

### B. MANAGED — 운영
적용:
- 팀/초기 거점
- 반복 소비가 예측 가능
- 담당자·창고·배급·급수 등 운영체계가 생김
- 일부 공급선이 존재하지만 아직 끊길 위험이 있음

표현:
- 약 N일분
- 일평균 소비
- 예상 유입
- 순증/순감 추세
- 특정 병목 품목

평범한 일일 소비는 자동 처리한다.
플레이어에게 매일 같은 차감 선택을 요구하지 않는다.

### C. STABLE — 추상 운영
적용:
- 생산/거래/보급선이 평균 소비를 안정적으로 감당
- 담당자와 절차가 정착
- 정상 변동이 전략적 판단을 바꾸지 않음

표현:
- 안정 / 빠듯 / 적자 / 위험
- 공급망 상태
- 특정 취약점
- 전략 비축 수준

정상적인 +/−는 백그라운드에서 상쇄된 것으로 처리한다.
정확한 수치는 전략적 필요가 생길 때만 다시 계산한다.

## 3. 자동화는 보상이다
우물·정수체계가 완성되면 매일 물 뜨기를 선택하게 하지 않는다.
정기 식량 공급망이 생기면 매일 쌀 몇 kg을 먹었는지 묻지 않는다.
담당자와 배급체계가 생기면 정상적인 배급은 자동 진행한다.

플레이어가 시스템을 구축했다면 반복 업무에서 해방되는 것 자체가 성장 보상이다.

## 4. 재정밀화 — 위기 때 다시 확대
STABLE/MANAGED 상태라도 다음 변화가 생기면 해당 자원만 한시적으로 해상도를 높인다.

예:
- 공급선 단절
- 생산시설 고장
- 피난민/파티 급증
- 화재·오염·도난·부패
- 도로/차량 상실
- 연료 가격/교환조건 급변
- 계절 변화
- 특정 필수품 고갈

예:
식량 공급망 STABLE
→ 정미소 정지 + 신규 인원 23명
→ MANAGED 또는 SCARCITY로 강등
→ 현재 비축량과 소비율을 다시 계산

위기가 해결되면 다시 추상화한다.

## 5. 자원별 독립 해상도
모든 자원이 동시에 같은 단계일 필요는 없다.

예:
- 물: STABLE
- 식량: MANAGED
- 디젤: SCARCITY
- 일반 의약품: MANAGED
- 항생제: SCARCITY

플레이어가 실제로 고민해야 할 병목에만 화면과 선택을 집중한다.

## 6. 스케일 성장
같은 자원도 시즌/성장에 따라 질문이 달라진다.

초기:
- 오늘 먹을 것을 어디서 구할 것인가?

팀:
- 8명이 30일 버틸 비축을 어떻게 만들 것인가?

거점:
- 평균 소비를 감당할 공급망과 저장체계를 어떻게 만들 것인가?

세력:
- 생산지·정미소·운송로·연료망을 어떻게 유지하고 보호할 것인가?

신질서:
- 지역 식량권·거래규칙·배급·외교를 어떻게 설계할 것인가?

세부 계산을 버리는 것이 아니라, 해결된 하위 문제를 시스템에 위임하고 더 큰 문제로 올라간다.

## 7. GM 운영 규칙
- 초기에는 정밀 계산을 적극 허용한다.
- 플레이어가 명시적으로 소비 차감을 요구하면 중요한 기간에는 반영한다.
- 그러나 동일한 일상 소비를 장기간 턴마다 반복 노출하지 않는다.
- 공급선/담당자/운영체계가 안정되면 자동 수지로 전환한다.
- 자동화된 자원은 전략적 변화가 없으면 Choice Gate를 만들지 않는다.
- 자원 변화가 의미 있는 임계치를 넘을 때만 플레이어에게 다시 노출한다.
- 숫자가 재미와 판단을 만들 때 계산하고, 숫자가 장부 노동이 되면 추상화한다.
- 추상화 상태에서도 내부적으로 자원이 무한해진 것으로 취급하지 않는다.
- 안정은 영구 면역이 아니다. 외부 충격과 수요 변화로 다시 부족해질 수 있다.

## 8. 권장 상태 모델
각 핵심 자원은 필요할 때 다음 메타 상태를 가질 수 있다.

```json
{
  "food": {
    "resolution": "MANAGED",
    "status": "ADEQUATE",
    "runway_days": 31,
    "supply_line": "PARTIAL",
    "trend": "NEUTRAL",
    "bottlenecks": ["cooking_fuel"]
  }
}
```

STABLE에서는 runway_days 같은 세부값을 매일 갱신할 필요가 없다.
전략적 변화가 있을 때 재계산한다.

## 9. UI/서술 원칙
좋음:
- "식량은 현재 공급과 소비가 거의 균형이다. 특별한 사고가 없다면 당분간 문제없다."
- "물은 자급 안정. 디젤만 11일 수준으로 떨어졌다."
- "정기 보급이 자리 잡아 일상 소비는 팀이 알아서 처리한다."

나쁨:
- 안정된 거점에서 매일 동일한 kcal/L 차감표 출력
- 플레이어에게 식사·급수·충전 같은 루틴을 매번 선택시킴
- 시스템 구축 이후에도 초기 생존과 동일한 재고관리 부담 유지

## 10. 최종 원칙
> **정밀함은 필요할 때만 재미다.**
>
> **안정화는 자동화를 획득하는 성장이다.**
>
> **게임은 항상 현재의 가장 흥미로운 병목을 플레이한다.**
