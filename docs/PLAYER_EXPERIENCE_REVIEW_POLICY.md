# Player Experience Review Policy

Status: ACTIVE FOR CANON V2 SEASON CLOSEOUT

## 목적

정식 《생존일기》 시즌 종료 시 실제 플레이어의 재미·몰입·긴장·난이도·선택 압박·성장 보상·스토리 만족도를 별도로 기록한다.

이 평가는 다음 문서들과 역할이 다르다.

- `SURVIVAL_DEBRIEF`: 현실 생존 관점 평가
- `RETROSPECTIVE`: 제작/GM 관점 평가
- `PLAYER_EXPERIENCE_REVIEW`: 실제 플레이어 체감 평가

## 기본 원칙

- 플레이어 만족도는 GM이 임의 추정해 확정하지 않는다.
- 플레이어가 직접 말한 체감과 평가를 우선 기록한다.
- 숫자 점수는 선택사항이다. 서술형 피드백만으로도 충분하다.
- 시즌 직후 기억이 생생할 때 짧게 수집하는 것을 기본으로 한다.
- 구조적 해석과 다음 시즌 설계 반영은 기획방에서 수행한다.
- 시즌방에서는 실제 플레이와 즉각적인 체감 원자료를 남긴다.

## 권장 수집 항목

필수 질문을 길게 늘리지 않는다. 최소한 다음을 확보한다.

- 전체 재미
- 몰입감
- 긴장감
- 체감 난이도
- 선택이 고민됐는지
- 가족/캐릭터 만족도
- 스토리 만족도
- 다음 시즌 플레이 의향
- 가장 재미있었던 부분
- 가장 루즈하거나 아쉬웠던 부분

필요하면 10점 척도를 사용할 수 있으나 점수 자체보다 이유를 더 중요하게 본다.

## 분석할 핵심 축

### 긴장과 페이싱
- 위기 구간의 압력이 충분했는가
- 위기 이후 관망 구간이 과도하게 길지 않았는가
- 다음 장면으로 넘어가고 싶은 동력이 유지됐는가

### 선택
- 선택이 실제로 고민됐는가
- 좋은 선택만 하면 모든 목표를 동시에 지킬 수 있지는 않았는가
- 가족의 독립판단이 선택 비용을 만들었는가

### 성장
플레이어 성장 체감을 세 축으로 본다.

- 캐릭터 성장
- 플레이어/가족 능력 성장
- 거점·장비·관계 성장

시간·돈·노동을 투자했다면 실제로 확인 가능한 보상이 있어야 한다.

### 거점 성장 원칙

거점의 만능화를 막기 위해 성장을 억제하지 않는다.

> 거점은 강하게 성장시키되 전문화한다.

각 시설은 특정 위험에 실제 이점을 주지만 모든 재난·사회문제·의료·접근 문제를 해결하지 않는다.

### 권장 시즌 리듬

`위기 → 적응 → 성장 보상 → 새로운 압력`

안정화 구간은 반복 운영을 AUTO/시간점프로 압축하고, 플레이어가 투자한 경우 시설·관계·기술·선택지의 가시적 성장을 보여준다.

## 시즌 종료 루틴에서의 위치

정식 시즌 종료 기본 흐름:

1. RAW TRANSCRIPT ARCHIVE
2. PLAYTHROUGH CANON
3. END STATE / PERSISTENT CANON
4. SURVIVAL DEBRIEF
5. RETROSPECTIVE
6. PLAYER EXPERIENCE REVIEW
7. IP PACKAGE
8. 다음 시즌 START HANDOFF

플레이어 피드백이 아직 없으면 `PLAYER EXPERIENCE REVIEW — PENDING` 상태로 두고, 추정값을 작성하지 않는다.

## 웹게임화와의 연결

여러 시즌의 Player Experience Review가 쌓이면 웹 기능을 경험 데이터에 근거해 결정한다.

예:
- 어떤 상태정보를 실제로 자주 확인했는가
- 자유행동과 숫자 선택지 중 무엇이 더 몰입을 높였는가
- AUTO 압축이 적절했는가
- 거점 성장 피드백이 충분히 보였는가
- 가족 대화가 재미를 높였는가
- 어느 시점에서 플레이 템포가 떨어졌는가

따라서 웹게임 UI를 먼저 과도하게 설계하기보다, 정식 시즌 플레이테스트 데이터를 계속 축적하면서 필요한 기능을 확정한다.
