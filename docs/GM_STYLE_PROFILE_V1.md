# 《생존일기》 GM Style Profile v1

## Status
- 이 문서는 Canon 사실의 Source of Truth가 아니다.
- `seasons_v2/S01/raw_transcript/**` 등 실제 플레이 RAW를 분석해 **문체·장면 편집·턴 리듬의 공통 패턴만 파생한 품질 프로필**이다.
- RAW 자체는 계속 COLD ARCHIVE이며 런타임 입력으로 로드하지 않는다.
- 현재 세계 사실은 Canon v2와 Engine authoritative state가 결정한다.

## 핵심 정의

《생존일기》의 좋은 GM 출력은 순수 웹소설도, 상태 로그도 아니다.

> **MUD + 인터랙티브 드라마 + AI GM**

플레이어의 선택 하나가 실제 장면을 만들고, 가족과 주변 세계가 반응하며, 전화·문자·공지·뉴스·이동·거점 변화가 서로 다른 형식으로 화면에 등장한다. 중요한 정보는 소설 문단 속에 묻지 않고 시각적으로 구분한다.

## RAW에서 반복 확인된 장면 리듬

### 1. 장면에는 시간과 목적이 있다
좋은 턴은 `18:24 — 아버지부터 압박`처럼 현재 시점과 장면의 초점을 빠르게 잡는다.

### 2. 플레이어 행동을 실제로 실행한다
선택문을 다른 말로 반복하지 않는다. 전화했다면 통화가 시작되고, 이동했다면 이동 중 새 문제가 생기며, 회의를 열었다면 가족 각자가 판단을 말한다.

### 3. 가족은 독립 인물이다
서윤·민석·정호는 명령 수행 결과값이 아니다.
- 동의
- 반론
- 질문
- 수정 제안
- 독립 행동
- 우려
을 직접 대사와 행동으로 드러낸다.

### 4. 첫 결과 뒤에 세계가 한 번 더 움직인다
한 턴에는 보통 2개 이상의 의미 있는 진행 비트가 있다.

예시 구조:
`플레이어 행동 → 가족 반응 → 외부 신호/상황 변화 → 새로운 판단 문제`

외부 신호는 다음처럼 다양하다.
- 긴급재난문자
- 병원/회사/학교 공지
- 마을 방송
- 지도·교통 변화
- 뉴스
- 이웃의 행동
- 전력·물류·통신 변화

### 5. 정보 형식을 섞는다
모든 것을 동일한 줄글로 쓰지 않는다.

한 장면에서 필요에 따라 다음을 섞는다.
- 장면 제목
- 짧은 일반 서술
- 직접 대화
- 문자·공지·방송 인용
- 현재 상태/변화 목록
- AUTO 압축
- 다음 선택

### 6. 위기와 안정기의 리듬이 다르다
위기에서는 분 단위로 장면을 확대한다.
안정기에는 반복 작업을 AUTO로 압축하고, 가족회의·거점 성장·직장·의료·지역사회 변화처럼 의미 있는 변화가 생길 때 다시 장면을 확대한다.

### 7. 환경 묘사는 판단에 필요한 만큼만
바람, 연기, 정전, 도로 상태처럼 선택에 영향을 주는 환경은 사용한다.
빛·풍경·소리만으로 분량을 채우지 않는다.

## 웹 GM의 한 턴 목표

기본적인 중요한 턴은 다음 순서를 우선한다.

1. **행동 실행** — 플레이어가 고른 행동을 바로 장면으로 시작
2. **인물 반응** — 관련 가족/주변 인물이 자기 판단으로 반응
3. **세계 반응** — 새 연락, 공지, 이동 문제, 자원 변화, 사회 변화 중 최소 하나
4. **의미 변화** — 이전보다 판단 조건이 달라짐
5. **결정 지점** — 방금 생긴 상황에서 자연스럽게 다음 선택

모든 턴을 같은 템플릿으로 출력하지 않는다. 장면에 맞춰 일부 블록을 생략하거나 순서를 바꿀 수 있다.

## MUD형 표시 문법 v1

웹 GM의 `narrative` 문자열은 아래의 가벼운 표시 문법을 사용할 수 있다.

### 장면 제목
`## 18:24 — 아버지부터 압박`

### 일반 서술
빈 줄로 문단을 구분한 자연스러운 한국어.

### 대화
`서윤(아내): “병원에서 바로 못 나갈 수도 있어.”`

### 외부 신호
`> [긴급재난문자]`
`> 외곽도로 일부 통제 예정.`

### 상태/변화
`### 현재 변화`
`- 외곽 진입로 통제 가능성 상승`
`- 서윤 즉시 합류 불확실`

### 장면 구분
`---`

이 문법은 화면 편집을 위한 것이며 Canon/상태 계약이 아니다.

## 선택지 품질 규칙

기본 4개.

- 서로 다른 전략이어야 한다.
- 결과·성공률·보상·정답 힌트를 쓰지 않는다.
- `다시 전화`, `다시 확인`, `앱 다시 보기`처럼 정보 확인만 하는 선택을 여러 개 만들지 않는다.
- 원칙적으로 4개 중 최소 2개는 **세계를 직접 움직이는 행동**이어야 한다.
- 정보 확인 선택은 현재 불확실성이 실제 판단의 핵심일 때만 1개 정도 둔다.
- 자유행동과 최대 2개 순서 선택은 계속 허용한다.

## 문체 규칙

- 자연스러운 현대 한국어.
- 가족 대사는 실제 가족 대화처럼 짧고 기능적으로 쓴다.
- 번역투, 비문, 이상한 합성어, 조사 오류를 피한다.
- 같은 사실을 서술과 선택지에서 반복 설명하지 않는다.
- 고정 문장 수보다 장면 완결성을 우선한다.
- 일반 턴은 읽을 만한 분량을 확보하되, 긴 문단 하나보다 여러 형식의 장면 블록으로 리듬을 만든다.

## 비용/속도 원칙

스토리텔링 품질을 위해 무조건 고가 모델을 기본값으로 올리지 않는다.

1. 저비용·저지연 모델에서 Style Profile을 최대한 재현한다.
2. 모델을 상향할 때는 품질 향상폭, 턴당 비용, 응답시간을 함께 비교한다.
3. 장기적으로 필요하면 평시/단순 턴은 저비용 모델, 큰 전환·가족회의·복합 자유행동만 상위 모델을 쓰는 선택적 라우팅을 검토한다.

## 품질 통과 질문

- 한 선택 뒤에 실제 장면이 생겼는가?
- 가족이 살아 있는 사람처럼 말하고 판단했는가?
- 행동 이후 세계가 한 번 더 움직였는가?
- 글줄이 아니라 장면·대화·신호가 섞여 읽는 리듬이 있는가?
- 다음 선택이 단순 정보 재확인 반복이 아닌가?
- 다음 장면이 궁금한가?

이 중 핵심 항목이 반복적으로 실패하면 UI 장식보다 GM 구조를 먼저 수정한다.
