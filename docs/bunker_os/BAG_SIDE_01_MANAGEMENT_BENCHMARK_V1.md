## 결정 질문

> 우리 방식이 실제 생존가방을 정확히 관리하면서도, 사용자에게 **갖고 싶고, 자부심이 생기며, 다시 사용하고 싶은 '준비하는 사람의 도구'**가 되는가?

**사용자 교정(2026-10-11):** 효율성만을 절대 잣대로 삼지 않는다. 전용 앱의 존재 자체, 미관, 정체성, 준비하고 있다는 자부심은 실재하는 사용자 가치 가설이다. 엑셀보다 입력 시간이 조금 더 들거나 터치 수가 비슷해도, 해당 경험을 더 좋아해 자발적으로 사용하는 사람은 있을 수 있다. 이를 근거 없이 모든 고객의 취향으로 일반화하지 않고 검증한다.

기능 개수나 '생존가방 전용'이라는 표어만으로 경쟁우위를 증명할 수도 없다. 이미 응급가방 특화 앱이 있고 실제 국내 수요·설치 의사·선호는 미확인이다.

## 제품 경험 가설: “나는 준비하는 사람”

- **기능적 가치:** 정확한 수량·표시기한 관리와 꺼냄→부족→실제 보충.
- **감성적 가치:** 휴대전화에 나만의 준비 도구를 소유하고, 보기 좋은 화면을 열며 느끼는 만족감.
- **정체성 가치:** '나는 위기에 불안해하기만 하는 사람이 아니라 가족과 일상을 준비하는 사람'이라는 자기인식.
- **브랜드 후보:** 생존일기 사이트에서도 재난의 공포만 강조하기보다, **준비를 생활 습관이자 긍정적 태도로 보여주는 지식·도구·이야기**를 제안한다. 멤버십/커뮤니티는 훗날 검증할 선택지이며 지금 출시 계획에 넣지 않는다.

### 가장 작은 디자인·메시지 가설

- 첫 물품 등록 뒤 **“내 생존가방 관리가 시작됐어요”**처럼 실제 행동에 비례한 작은 성취를 보여준다.
- 첫 화면은 '내 가방 / 보충할 물품 / 다음 확인할 날짜'를 분명히 하되 **갖고 싶은 도구처럼 차분하고 정돈된 디자인**을 실험한다.
- 이후 원하는 사람에게만 '나는 준비를 시작했어요' 같은 공유 카드를 검토한다. 가방 구성·보관 위치·가족·의약품·비상시설 위치는 공유하지 않는다.
- **금지:** 근거 없는 '생존 준비 100%' 인증/안전보장, 과장된 공포 마케팅, 매일 접속·연속 출석 강요, 돈을 내야 준비한 사람으로 인정하는 구조.

**비교 원칙:** 시간·터치·오류와 함께 매력·소유욕·준비하는 사람이라는 느낌·재사용 의향을 **같은 시나리오에서** 비교한다.

### 앱 전환에 필요한 별도 요구

- **부족분:** 목록 시트는 `기초수량/장부재고/실사수량`을 관리하지만, `목표수량` 별도 열이 없어 `목표 - 실제 가방 수량`으로 **자동 부족량을 계산하는 전용 기능이 없다**.
- **기한별 묶음:** `유효기간/교체예정일` 열이 품목당 하나라 같은 간편식의 기한이 다른 A/B 묶음을 직접 모델링하지 않는다. 품목ID를 나누는 우회와 '단일 품목' 집계는 별도 처리가 필요하다.
- **알림:** XLSX는 개별 휴대폰 알림을 보장하지 않는다. `EDATE`는 '점검 예정일 계산'이지 단말에 '푸시 예약'한 증거가 아니다.
- **기록과 안심의 차이:** 엑셀의 '정상'은 `M7` 상태 수식의 표시기한/점검일 조건일 뿐, 목표수량이 충족됐거나 재난에 안전하다는 보장이 아니다.
- **입력 부담:** 5종 관리에 품목ID·입출고 로그·5개 시트가 있는 구조는 범용 관리 장부에 적합하지만, 모바일에서 가방 하나를 관리하려는 신규 사용자에게 부담일 가능성이 있다. **실기기 사용시간을 측정한 사실은 아니다.**

따라서 **엑셀을 폐기/대체하지 않는다.** 상세 재고·사업장용으로 재사용하고, 추가 Side Track의 간단한 가방 UX가 실제로 별도 가치를 주는지 비교한다.

### 다음에 만들 최소 화면의 가설 (아직 구현 아님)

**한 화면, 처음 5종, 가방의 실제 보유량만 진실로 다룸.**

- 첫 인상: **'나의 생존가방' + '나는 준비하는 사람'**. 멋있는 도구 같은 정돈된 디자인과 작고 사실적인 성취 표현.
- 상태 요약: `관리 중인 품목 5개`, `보충할 품목 1개`, `다음 확인일`. '준비 100%'나 가짜 생존 보장 점수 금지.
- 관리 흐름: **'꺼냈어요' → '보충 필요' → '실제로 넣었어요'**. '주문했어요'는 가방 수량을 변경하지 않음.
- 일상 사용: 점검할 일이 없으면 굳이 열지 않아도 되고, 열었을 때 정리된 내 가방을 보며 만족하는 경험.
- 가설 질문: 엑셀과 터치 수가 비슷해도 사람들이 **이 전용 앱을 갖고 싶어 하고 다음 점검 때 다시 열 이유가 있는가?**
- Android 수개월 알림/스토어/광고/계정/멤버십은 이 UX의 가치를 관찰한 뒤 별도 검증. 유저 진짜 물품 데이터는 데모에 저장하지 않음.

`docs/bunker_os/BAG_SIDE_01_SCENARIO_V1.json`이 테스트 기준이다. 물품 5종은 가상 예시이며 권장 비축품/권장 수량/안전성 판단이 아니다.

|---|---:|---:|---|
| 간편식 | 6 | 6 | 기한이 다른 A 4개 + B 2개 |
| 생수 | 2 | 2 | 표시된 날짜 1묶음 |
| 손전등 | 1 | 1 | 작동 점검일 관리 |
| 보조배터리 | 1 | 1 | 충전·작동 점검일 관리 |
| 위생티슈 | 2 | 2 | 표시된 날짜 1묶음 |

**고정 시나리오**
1. 위 물품 5종을 '내 가방'에 등록한다. 기한이 다른 간편식은 개별 묶음으로 기록한다.
2. 간편식 A에서 2개를 꺼낸다 → 총 보유 6→4, 부족 0→2, B 묶음은 변경 없음.
3. '구매함/주문함' 표시만 한다 → 보유 4, 부족 2. 구매를 곧바로 실제 가방 입고로 간주하면 실패.
4. 2개를 새 묶음 C로 실제 가방에 넣는다 → 총 보유 4→6, 부족 2→0. 묶음 A·B의 날짜 변경 금지.
5. 알림 미루기 → 표시기한과 수량 불변. 상태가 '안전 보장'으로 바뀌면 실패.
6. 가능하면 백업→복원하여 상태/날짜/부족량이 모두 동일한지 확인한다.

날짜는 **제품 표시기한과 임의의 관리예정일을 별도로 관리**하며, 여유기간(예: 90일)은 안전기준이 아닌 사용자 설정이다. 약은 자동 순환 섭취 권고 대상이 아니다.

## 측정 방법 (우선 검증, 비용 0원)

### 1. 기록 정확성 — **필수 탈락선**

- 6→4→6, 부족 0→2→0, 묶음별 표시기한 보존, 중복 차감 방지, 주문만으로 보충 완료 금지, 백업·복원 동일성.
- 잘못된 안도감을 주는 '준비 완료/안전 보장' 문구 금지. **기록·기한·수량 오류 0건**은 편의성이나 심리적 매력으로 상쇄할 수 없다.

### 2. 편의성 — **관찰 지표**

- 5종 첫 등록 시간, 조작/입력 횟수, 도움 질문, 꺼냄·보충 처리 소요시간을 관찰한다.
- 초기 5종 5분 이내, 소비·보충 각각 30초 이내는 **도전용 목표**이지 기존 앱보다 더 빨라야만 하는 일률적 성공 조건이 아니다.
- 기능이 같은데 조금 더 번거롭더라도 사용자가 미관·전용 도구에 더 가치를 느끼는지 함께 본다.

### 3. 소유 만족감·정체성 — **선택 이유**

- 같은 과제를 경험한 후 '어떤 방법을 휴대전화에 두고 싶나요?', '왜 그것을 선택하나요?', '나는 준비하는 사람이라는 느낌이 드나요?', '다음 점검 때 다시 열고 싶나요?'를 묻는다.
- 멋진 그림만 보여주고 실용성을 입증한 것으로 착각하지 않는다. **예쁘다/깔고 싶다/실제로 계속 쓸 것 같다**를 따로 기록한다.
- 3~5인의 첫 사용자 관찰은 정성 탐색이다. 앱을 먼저 써본 순서 효과, 지인 편향, 클릭·설치 의사와 실제 장기 이용의 차이를 기록한다.

**잠정 판정:** 기능 정확성은 필수. 나머지는 **조작 효율 + 선호·정체성 + 실제 관리 시점의 재방문**을 종합한다. **터치 수가 같거나 약간 많다는 이유만으로 자동 탈락시키지 않는다.**

## 최소 UX 후보와 중단 조건

필수 상태: `목표수량 / 실제 가방수량 / 부족수량 / 묶음별 표시기한 / 다음 확인일`.
필수 행동: `꺼냈어요 / 가방에 넣었어요 / 점검했어요 / 나중에 알림`.
첫 화면 우선순위: `오늘 확인할 것 / 부족한 것`. 광고, 회원가입, 게임, AI 추천, 가족 동기화, 쇼핑몰은 첫 시험에서 배제.
부족 계산은 `max(목표 - 실제, 0)`. **구매 또는 알림 미룸으로 재고를 증가시키지 않는다.**
오프라인 저장/백업과 Android 수개월 알림은 분리된 기술 Gate. 5분 후 알림 성공을 9개월 보장으로 표현하지 않는다.

### 개발 계속/중단

- **CONTINUE:** 수량·날짜·백업 등 정확성 오류 0건. 다수가 기존 방법보다 편리하다고 느끼거나, 약간의 수고를 감수해도 '내 전용 준비 도구'로서 갖고 싶고 다시 쓰고 싶은 이유가 구체적이면 다음 비공개 알파를 검토한다.
- **REVISE:** 정확성 오류가 있거나 버튼이 어렵고, 디자인·준비 경험이 이용 의향을 만들지 못하면 우선 수정하고 동일 과제로 재시험한다.
- **STOP/SWITCH:** 기능 정확성을 유지하기 어렵거나, 사용자에게 편의·기분·정체성 면에서 모두 별도 도구를 선택할 이유가 거의 없으면 앱 개발을 보류한다. 그 결과는 기존 지식·엑셀·브랜드 경험 개선에 재사용한다.
