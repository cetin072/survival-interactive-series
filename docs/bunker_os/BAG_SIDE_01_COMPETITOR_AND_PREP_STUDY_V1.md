# BAG-SIDE-01 — 생존가방과 기존 앱 경쟁분석 V1

조사일: 2026-10-11 KST · 상태: 공개 기능 및 공공자료 조사 완료 / 경쟁 앱 실제 사용·국내 사용자 인터뷰는 미실행.

## 목적과 범위

기존 《생존일기》의 Month 01 (#501), E-001/E-002/E-003, 자동화 A/A-Wiki/B/C는 그대로 운영한다. 이 문서는 별도의 생존가방 추가 과제 BAG-SIDE-01의 설계 참고다. 신규 대형 앱/서버/광고/스토어 공개나 다른 실험의 자동 교체를 승인하지 않는다.

이미 공개된 앱에도 기한·재고 부족·순환 소비·가방·임박순 정렬 기능이 있다. 그러므로 이런 기능 자체가 우리만의 신기술이라는 주장은 철회한다. 비교할 것은 **정확하게 관리되면서 첫 화면이 이해하기 쉽고, 실제 보충까지 끝내고 싶으며, 사용자가 자기 준비 활동에 자부심을 느끼는가**이다.

## 실제 생존가방 준비 분야 학습

1. **이동 가방 vs 집 비축.** 대한민국 국민재난안전포털의 '비상대비용품' 민방위 안내는 '손에 들고 갈 비상용 백'과 '집에 비치할 것'을 별도 항목으로 다룬다. 해당 자료에는 대피경로·가족 연락·서류 방수 보관도 포함된다. 미국 적십자 역시 이동용과 가정 비축을 구분한다. 집 비축 전체를 이동 배낭에 넣도록 자동 계산하지 않으며, 포털의 특정 민방위 문맥을 모든 재난의 수량 기준으로 일반화하지 않는다.
2. **대상의 차이.** 물·식품·조명·연락·위생·서류의 기본 분류를 제시하되, 아이·반려동물·노인·개인 의료 필요와 예상 대피 방법에 따라 목록이 달라진다. '기본 품목 자동 추가'가 '실제 보유'를 뜻해서는 안 된다.
3. **관리 방식의 차이.** 식품·물품의 표시기한/보관 조건, 전자 장비의 충전·작동 테스트, 연락처·서류의 최신성 확인은 별도의 점검 상태로 다뤄야 한다. 약품에 '교체시점이 가까우니 먹으라'고 안내하지 않는다.
4. **순환과 정기 점검.** 적십자 인쇄 자료는 비상용품 6개월 간격 확인과 기한 임박품 교체를 권고한다. 한국 법적 의무/절대 안전기준은 아니며, 현재 실험의 '표시기한 90일 전 검토'도 사용자가 조정할 관리 시점 가정이다.
5. **기록 이상의 준비.** 앱 목록은 실제 가방의 무게·접근성·작동 여부를 보장하지 않는다. 준비했다는 심리적 만족감은 좋지만, 가방 상태를 현실보다 안전하게 표시하지 않도록 제한한다.
6. **보안과 개인정보.** 주민등록·의료·보관장소·가족의 상세 준비내역을 공유/광고/분석 서버로 기본 업로드하지 않는다. 향후 공유·멤버십도 동의/비식별/최소정보를 검토한다.

## 현재 V2 개선 — 사용자 피드백 반영

**색상:** 기존 연한 파스텔 녹색의 부드러운 홍보 화면을 짙은 그라파이트·네이비와 선명한 오렌지 행동 강조색으로 변경. 위험을 자극하는 군사 마케팅이 아니라 **명확한 대비·단단한 도구의 제품성**을 의도한다.

**첫 화면:** '나는 준비하는 사람'이란 긴 배너를 아래로 이동. 현재 관리 품목 수 / 실제 보충 필요 / 30일 이내 관리 일정이 **최상단**에 나온다. 상태 카드를 눌러 실제 목록을 필터링할 수 있다. 실물 구매만으로 보충 완료로 계산하지 않는다.

**일정 정렬:** 다음 액션을 즉시 보충 부족 → 날짜순으로 정렬. 장비는 다음 점검일, 날짜 있는 물품은 **실제 수량이 남아 있는 묶음 중 표시기한 - 예시 90일**을 계산한 가장 가까운 관리 날짜 기준. 상태에는 관리일과 원래 표시기한을 구분해 보여주고, 지나간 관리일을 '식품 안전 불가'라고 자동 판단하지 않는다.

**UI 계약:** 주목할 상태 → 다음 관리 일정 목록 → 전체 물품 → 소비·주문·입고 클릭 실험 → 나의 준비 태도 메시지 → 근거 자료. 자료 읽기만 해도 가방 기록이 변경되지 않는다.

**아직 구현 안 됨:** 개인 품목 추가/수정, 영구 로컬 저장, 백업/복원, OS 예약 알림, 재부팅/앱 휴면 복구, 설치용 Android APK, 앱스토어, 수익화, 가족 공동 관리. 실험화면은 매번 가상 수량을 로드한다.

## 이어서 검증할 것

- **5초 판별 테스트:** 첫 화면에서 무엇이 부족하고 언제 점검해야 하는지 바로 보이는가?
- **관리 일정 이해:** '표시기한'과 '90일 전 순환 검토일', 장비 점검일을 구분하는가?
- **정확성:** 상품 A·B 기한이 다를 때 2개 소비→부족 유지→실제 입고 후에만 부족 해소가 지켜지는가?
- **경쟁 실사용:** Ember Omnia와 MoshiMono 또는 Stockpile의 동일 5품목 업무를 Android 실제 기기에서 해보고 시간/터치·실수·학습 부담·소유 만족도를 비교한다.
- **제품 매력:** 컬러와 첫 화면이 매력적인지, 군사용 포스터처럼 부담스러운지, 정말 자기 가방을 계속 관리할 마음이 드는지 물어본다.
