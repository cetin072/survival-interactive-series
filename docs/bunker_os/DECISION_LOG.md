# Bunker OS V1 — DECISION LOG

기준일: 2026-10-10 KST

중요한 결정을 “무엇을 정했는가 / 왜 / 무엇이 바뀌면 재검토하는가”로 남긴다.
사소한 구현 선택은 기록하지 않는다.

## D-001 — 최상위 목적은 실제 벙커
- Date: 2026-10-10
- Decision: 생존일기 전체 프로젝트의 최상위 목적은 실제 벙커에 도달하는 여정이다.
- Why: 게임·사이트·사업은 이 장기 여정을 유지하고 앞당기는 수단과 자산이다.
- Revisit when: 벙커라는 목적 자체를 사용자가 변경할 때만.

## D-002 — 생존지식 사이트는 최소 5년 지속
- Date: 2026-10-10
- Decision: 단기 수익 여부와 무관하게 사이트를 최소 5년간 발전시킨다.
- Why: 사용자에게 유희·필요·장기 자산의 의미가 모두 있음.
- Revisit when: 사용자가 명시적으로 종료/전환을 결정할 때.

## D-003 — 수익은 비선형이고 방법은 열어둔다
- Date: 2026-10-10
- Decision: 1년마다 일정액을 벌어야 한다는 선형 목표를 두지 않는다. 광고·영상·제휴·상품·앱·B2B 등 방법도 고정하지 않는다.
- Why: 장기 프로젝트는 준비·자산 축적 뒤 후반에 큰 결과가 발생할 수 있음.
- Revisit when: 반복 가능한 강한 수익 엔진이 실제 데이터로 확인되면 해당 엔진에 집중할 수 있음.

## D-004 — 운영총괄은 AI, 사용자는 감독
- Date: 2026-10-10
- Decision: 운영총괄이 조사·계획·개발·실험·해석을 주도하고 사용자는 방향을 평가한다.
- Guard: 결제·계약·계정 소유권·비가역 Production 변경·데이터 삭제·개인정보 경계·고위험 정보 공개는 사용자 승인 필요.

## D-005 — MUA는 제품 지표이지 최상위 Mission이 아님
- Date: 2026-10-10
- Decision: Monthly Useful Actions를 사이트 개선의 핵심 지표로 사용하되, 최상위 북극성은 Bunker Progress + 5년 사이트 자산 축적이다.
- Why: 행동 최적화가 장기 목적을 대체하지 않게 하기 위함.

## D-006 — 기존 자동화는 백그라운드 유지
- Date: 2026-10-10
- Decision: Archive/Knowledge/Automation A·B·C의 검증된 운영은 별도 중단 결정이 없는 한 계속한다.
- Why: Bunker OS는 기존 생산 시스템을 대체하는 새 자동화가 아니라 방향·학습·의사결정 계층이다.
- Guard: 북극성과 충돌하는 신규 자동화 확장은 만들지 않는다.

## D-007 — 준비기간도 성공 경로가 될 수 있다
- Date: 2026-10-10
- Decision: 1~4년차가 주로 준비와 자산 축적이고 5년차에 큰 수익/실행이 발생하는 경로도 허용한다.
- Condition: 준비기간마다 지식·사용자·유통·기술·네트워크·벙커 준비도 중 측정 가능한 진전이 있어야 한다.

## D-008 — Bunker OS V1을 전략 학습의 기본 기록계로 사용
- Date: 2026-10-10
- Decision: NORTH_STAR / STRATEGY / SOURCE_LIBRARY / DECISION_LOG / EXPERIMENT_LOG 다섯 문서를 사업·사이트·벙커 전략의 최소 공통 컨텍스트로 사용한다.
- Why: 좋은 외부 지식과 프로젝트 학습이 채팅마다 사라지는 문제를 줄이기 위함.


## D-009 — 현재 사업 기준선을 태장 + 온라인사업부로 둔다
- Date: 2026-10-10
- Decision: 현재 주업은 태장과 태장 내 온라인사업부이며, PC방 사업은 종료 상태로 본다. 벙커는 취미이자 장기 북극성이다.
- Why: Bunker OS의 전략과 수익화 계획이 종료 사업이나 과거 상태를 현재 자원으로 오인하지 않게 하기 위함.
- Revisit when: 태장/온라인사업부의 사업 구조가 크게 바뀌거나 새로운 주업이 생길 때.


## D-010 — 공개 Bunker OS와 비공개 운영 Snapshot을 분리한다
- Date: 2026-10-10
- Decision: 공개 GitHub Bunker OS에는 전략에 필요한 요약만 저장하고, 개인 토지 규모·예산·구체적 사업수치·실제 벙커 위치/보안정보 등은 비공개 Project Source에서 관리한다.
- Why: 장기 컨텍스트는 유지하되 불필요한 개인정보·사업기밀·보안정보 공개를 막기 위함.
- Guard: 공개 여부가 애매한 정보는 기본적으로 비공개로 둔다.

## D-011 — 공개 모델/사무실 벙커와 실제 사용 벙커를 분리 검토한다
- Date: 2026-10-10
- Decision: 사업·콘텐츠용 공개 공간과 실제 비상 사용 공간은 같은 위치/정보공개 수준을 전제로 하지 않는다.
- Why: 콘텐츠/사업 활용과 실제 보안·프라이버시 요구를 동시에 만족시키기 위함.
- Revisit when: 사업모델과 실제 벙커 요구조건이 구체화될 때.
