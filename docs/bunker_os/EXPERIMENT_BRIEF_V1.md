## 1. 추천안과 검증 질문

**질문:** 방문자가 생존지식을 읽은 뒤 실제 준비를 위한 유용한 행동을 하는가?

**주 실험:** K-002를 읽은 성인 방문자가 **집에 이미 있는 비상용품 1종을 직접 확인하고, 기존 XLSX에 점검 기록 한 행을 남기는가**를 동의한 소규모 시험에서 확인한다.

- 운영자가 과업을 제시하는 **비공개 실행 가능성 시험**이다. 자연 방문자가 스스로 준비를 시작하는 비율·반복 사용·채널 효과는 후속 관측이 필요하다.
- E-002의 원 가설인 ‘명확한 자료 CTA가 행동을 늘린다’의 **첫 실행 가능성 시험**이다. 비교군·사전 기준선이 없으므로 증가 효과/일반 방문자 전환율은 이 시험으로 확정할 수 없다.
- E-001은 아래 수기 이벤트 정의·중복 제거·분모 기록만 의존성으로 사용한다. 페이지뷰 추적·새 수집 엔드포인트·DB 테이블·분석 SaaS를 만들지 않는다.
- 보조 실험은 **0개**. E-003의 외부 게시/공유 유통은 Week 3의 별도 계획이다. 참가자에게 공유·구매를 추가 과업으로 요구하지 않는다.
- BAG-SIDE-01 앱, 물품별 신규 글, 가방 등록·알림·보충 기능은 사용하지 않는다. 그 개발/배포/CI 성공을 E-002 이용 증거로 합산하지 않는다.

## 4. 제공할 행동 하나와 진행 대본

**‘이미 가진 물품 1종을 확인해 관리표에 점검 기록 한 행 남기기’**만 요청한다. 구매·섭취·전기/가스 조작·약품 점검·실제 대피는 요구하지 않는다.

1. 기존 방문 경로로 K-002를 읽게 한다. 시험 목적·수기 기록 항목·미수집 정보를 먼저 설명하고 동의 받는다. 화면/음성 녹화·파일 업로드는 하지 않는다.
2. 읽기를 마친 방문자가 과업 시험 시작에 동의하면 `trial_start`를 기록한다. 이 순간부터 **10분 과업 창**을 시작한다. 운영자는 정답·셀 위치를 안내하지 않는다.
3. 방문자에게 다음 문장만 제공한다:
   > 집에 이미 있는, 안전하게 살펴볼 수 있는 비상용품 한 종류의 실제 수량과 표시된 기한을 확인하고, 이 글의 관리표에 점검 기록 한 행을 남겨 저장해 보세요. 표시기한이 없는 물품은 기한 칸을 비워 두세요. 구체적인 물품·수량·기한·위치는 우리에게 보내지 않습니다. 언제든 중단할 수 있습니다.
4. 방문자는 기존 링크로 받은 파일의 **자기 로컬 사본**에서 입력한다. 예시 시트/합성 값을 실제 점검으로 계산하지 않는다. 화면 공유 없이 작업하고, 10분 안에 아래 완료 여부만 직접 답한다.
5. 자발적 완료 보고의 조건은 **실물 수량 확인 / 표시기한 확인(없으면 없음 확인) / 한 행 기록 및 로컬 저장**의 세 가지 모두다. 하나라도 빠지면 완료로 세지 않는다. 운영자의 유도 질문·대신 입력·화면 수정으로 끝낸 경우는 `assisted`로 별도 기록하고 분자에서 제외한다.

운영자 참고(참가자에게 선제 제시 금지): ‘비상용품 목록’의 첫 입력 행은 7행. A 품목ID, B 분류, C 품목명, D 보관 위치(선택·로컬), E 단위, F 기초수량, H 실사수량, J 표시기한, K 마지막 점검일, N 조치/메모가 입력 영역이다. 실제 새 사본에서는 고유 임시 품목ID와 확인 수량을 F/H에 기록한다. G/I/L/M은 계산 영역이므로 덮어쓰지 않는다. **파일의 ‘정상’ 표시가 물품의 섭취·작동 안전 보증은 아니며 L의 6개월은 관리 예시**다.

## 5. 대상·기간·노동 한도

- 대상: 일반 가정의 준비에 관심 있는 **성인 방문자** 중, 현물 1종을 안전하게 확인하고 **이미 보유한 로컬 XLSX 편집 환경**을 사용할 수 있는 자발적 참가자. 이름/연락처를 모집 명부로 저장하지 않는다. 유료 소프트웨어 구매, 클라우드 업로드, 매크로 허용·보안 해제는 요구하지 않는다.
- 표본: 사전에 조건을 확인한 **처음 시작한 8명**, 각 1회. 운영자·개발자·자동 테스트 제외. 내부 지인/기존 독자 편의표본이면 그 사실을 결과에 표시하며 자연검색·국내시장 대표 표본이라고 부르지 않는다.
- 가능한 대상 수는 아직 모른다. 모집 부족을 해결하려고 Week 3 외부 배포나 유료 모집을 선행하지 않는다.
- 창: 승인/사전 점검 후 첫 유효 시험부터 **7일**, 8명 시작 또는 운영노동 **4시간** 중 먼저 도달하면 종료. 목표 실행 주는 Week 2 **2026-10-17~23 KST**. 시작이 늦으면 실제 시작/종료일을 기록하고 기간 연장을 자동 결정하지 않는다.
- 과업 창 10분, 동의·독서·짧은 마무리 포함 1인 약 20분을 계획한다. 사전 점검·취합 포함 총 4시간 상한. 추가 현금 지출 **0원**, 보상금·유료 서비스 없음. 기존 비용이 무료로 바뀌었다는 뜻은 아니다.

## 6. 최소 E-001 측정 계약

**이벤트는 설계 명칭이며 현재 구현된 중앙 수집 이벤트가 아니다.** 운영자가 동의한 세션에서 발생 여부를 수기 기록한다. 기존 공유 JS에 없는 분석 기능을 있다고 가정하지 않는다.

| 이벤트/결과 | 발생 기준·관찰 방법 | 해석 |
|---|---|---|
| `trial_start` | 글 읽기 후 본인이 과업 시작에 동의. 운영자 수기 1회 | 분모 시작. pageview/모든 독자 수 아님 |
| `tool_download` | 기존 XLSX 링크 클릭을 본인이 알리거나 공개 페이지 부분에서 관찰 | **다운로드 요청**. 파일 저장/열기/실제 준비 완료 보장 아님 |
| `tool_open_report` | 로컬 관리표가 열렸다고 답함 | 자기보고. 파일/스크린샷 수집 없음 |
| `prep_row_self_report` | 10분 이내, 세 완료 조건 모두 직접 보고, 도움 없음 | **자기보고 준비 과업 완료**. 원본 기록/실물의 독립 검증 아님 |
| 종료 결과 | `completed_self_report / assisted / incomplete / technical_block / withdrawn` 중 1개, 10분 창 종료 시 확정 | 중도 이탈/응답 없음은 incomplete. 빈칸을 성공으로 채우지 않음 |

- 임시 수기 기록: `trial_code(T01~T08), spec_commit, 환경(PC/모바일), start, download_request, open_report, prep_report, outcome, duration_bucket(≤5/≤10/>10분)`만. 환경은 넓은 구분이고 기기 식별자는 아니다. 자유입력 사유 대신 `file_open / cell_discovery / saving / no_report / other`의 비식별 실패 범주만 허용.
- trial_code는 한 시험 내 중복 제거용 순번이며 계정·IP·이메일·이름·연락처·브라우저 ID와 연결하지 않는다. 다른 주차/사이트 행동과 결합하지 않는다.
- 동일 사람이 한 과업에서 반복 클릭·재다운로드·새로고침해도 각 이벤트 **최대 1회**. 같은 사람이 다시 오면 첫 세션만 집계한다(본인 확인 진술, 식별자 저장 없음). 세션 간 완벽한 중복 방지는 못 한다는 한계를 보고한다.
- 운영자 QA/Preview/합성 데이터는 `QA`로 분리해 N/C에 넣지 않는다. 시작 뒤의 파일 열기 실패·저장 실패·중도 중단은 **분모에 남고 완료는 0**이다. 어려운 참가자를 사후 제외·대체하지 않는다.
- 동의 철회 시 해당 trial 행을 지우고 재연락하지 않는다. 대체 참가자로 채우지 않는다. 철회로 N이 8 미만이면 판단 보류다. 개인 데이터는 받지 않더라도 참여 선택권은 유지한다.
- 수기 원자료는 기존 비공개 작업 공간의 임시 파일에서만 보관, 접근은 시험 운영자만. 분석 직후 늦어도 종료 7일 내 삭제한다. GitHub/공개 문서/운영 일지에는 **집계·방법·한계만** 남긴다. 이번 단계에서는 원자료도 생성하지 않는다.

## 7. 분모·분자와 사전 판정

- **N:** 동의하여 `trial_start`한 중복 제거 대상자 수. 철회 데이터만 제거. 열기 실패·포기·무응답 포함. 계획 최대 8.
- **C:** N 중 `prep_row_self_report` 조건을 모두 만족하며 10분 내 도움 없이 완료한 사람 수. 주 지표 `C/N`의 이름은 **동의한 과업 시작자 중 자기보고 준비 기록 완료율**이다.
- 다운로드 요청률과 파일 열기 보고율은 각각 해당 고유 이벤트 수/N으로만 보조 해석한다. C/다운로드 수를 전체 행동률이라고 바꾸지 않는다. 공유 클릭은 C에 포함하지 않는다.
- 전체 자연 방문자 수·독자 전환율·행동 증가율·채널별 전환율·재방문·매출의 기준선은 **미확보**다. 실측 0건이라는 주장이 아니라 측정하지 않았다는 뜻이다.

8명은 통계적 시장 검증 표본이 아니라 운영시간 한도 안에서 파일 접근·기록 장벽을 찾기 위한 계획 표본이다.

다음 숫자는 **감독 검토용 사전 목표/중단 기준**이며 업계 기준·과거 성과·통계적 유의성 기준이 아니다. Day 7 승인 때 고정하고 시작 뒤 결과에 맞춰 바꾸지 않는다.

| 판정 | 조건 | 다음 해석 |
|---|---|---|
| PASS | N=8, C≥6, 아래 무효/중단 조건 없음 | 작은 집단에서 가능한 행동이라는 초기 신호. 다음 실제 사용 검증 검토. ‘증가 효과/성장 엔진 검증/제품 출시 성공’ 아님 |
| FAIL | N=8, C≤2, 측정·자산 접근이 유효하고 안전 중단 없음 | 현재 글→XLSX 과업 흐름을 수정/보류. 사이트 전체·가정 수요 부재로 일반화하지 않음 |
| INCONCLUSIVE | N<8, 또는 N=8이고 C=3~5, 측정 누락/집계 모순/버전 혼합/안전 중단 | 낮은 모집/기록 품질을 수요 실패로 위장하지 않음. 원인과 재시험 승인 필요 사항 기록 |

반증할 좁은 가설: ‘현재 K-002와 기존 XLSX만으로 대상자가 별도 도움 없이 작은 점검 기록을 끝낼 수 있다.’ 유효 N=8 중 2명 이하 보고라면 이 형태의 실험 가설을 지지하지 않는다. 완료 보고만으로 실제 장기 준비 유지·안전 향상을 증명할 수 없고, 자기보고 편향을 제거하지 못한다.

## 8. 시작 전 점검·승인 및 중단

**Day 7 감독 결정:** (1) 주 실험 K-002와 대상 범위 (2) N/C 정의·6/8·2/8 기준 (3) 동의/수기 비식별 기록·삭제 기한 (4) 7일·4시간·0원 한도를 승인/수정/보류한다. 이 문서 작성은 실험 실행·사람 승인 receipt가 아니다.

승인 뒤 Week 2 담당자가 할 사전 점검:

1. 고정한 문서 commit·K-002·파일 SHA와 실제 공개 URL을 확인. 이후 글·파일이 달라지면 버전을 분리하고 자동 합산하지 않는다.
2. 이미 보유한 로컬 편집 앱에서 **가상 데이터** 한 행 입력→저장→재열기, F/H·G/I 연계와 날짜 입력/표시를 확인. 외부 링크 없음·매크로 없음과 별개로 실제 호환성을 검수한다. 이 QA는 이용자 성공 수에 넣지 않는다. 실패하면 공개 원본을 몰래 고치지 말고 시험 보류 후 별도 수정 승인.
3. 수기 시험 행으로 중복 클릭 1회 처리, 중도 중단 분모 유지, 철회 삭제, 모순 이벤트/분자>N 탐지를 확인. 새로운 분석 서비스·자동 수집 코드는 불필요하다.
4. 동의 설명문과 위 대본, 기존 접근 가능한 방문자 모집 방식, 실제 운영 담당자/시간을 확정. 모집 메시지 발송/게시 자체는 승인 뒤 별도 수행한다.

즉시 중단: 개인정보/현물 파일·약품 정보가 전달되거나 안전 위험·잘못된 물품 권고가 발생, 수식/파일 손상, 비용/노동 한도 초과, 수집 고지 불일치. 해당 건은 보관 확대 없이 비공개에서 처리하고 결과는 INCONCLUSIVE로 남긴다. 원래 8명 내 1~2명의 단순 열기 어려움은 기술 장벽이라는 실제 실패 신호로 남기되 자산 자체 결함과 구분한다.

**개발 승인 경계:** 현재 추천안은 기존 공개 자산+수기 측정이라 새 사이트 기능 개발이 필요 없다. 후속 CTA 문구/위치 변경, 브라우저 자동 이벤트, 저장·보존정책/권한 변경이 필요하면 별도 범위·동의·비용 검토와 Draft PR 승인을 받는다. 현재 금지된 새 테이블/cron/분석 서비스는 이 설계를 핑계로 만들지 않는다. Production 변경은 기존 2일 release-marker 정책과 별도 병합 승인 절차를 유지한다.
