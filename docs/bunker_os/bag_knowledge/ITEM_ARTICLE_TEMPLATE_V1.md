## 콘텐츠 원칙

1. **전체 원고 신규 집필.** 기존 현실 생존지식(Automation C)은 복사하거나 약간 바꿔 붙이지 않는다. 필요하다면 해당 글을 `관련 생존지식` 링크로 제시한다. A-Wiki(허구 세계관)는 근거가 아니다.
2. **생활에서 시작하는 설명.** 첫 문단은 구체적이지만 과장하지 않은 상황으로 시작한다. 어떤 문제가 생기고, 해당 물품이 어떤 문제를 줄이는지 이어 쓴다. 가공된 경험을 실화처럼 표현하지 않는다.
3. **고정 순서, 유연한 길이.** 모바일에서 헤딩 순서와 역할을 통일하지만, 설명할 것이 적은 품목을 억지로 늘리거나 중복 문구로 채우지 않는다. 한 문단 2~4문장, 짧은 소제목, 쉬운 한국어.
4. **선택과 사용은 구분.** 필요한 이유·사용법·구매 판단·수납·정기 점검을 섞지 않는다. 개별 제품명이나 광고 중심으로 쓰지 않는다.
5. **안전 사실 확인.** 공공기관·제조사 공식 지침 등을 출처로 기록한다. 효능·용량·보관기한·재난별 안전 행동은 해당 근거 없이 단정하지 않는다. 특히 물, 의약품, 정화, 화학·전기·화기 관련 글은 공개 전 추가 검수한다.
6. **수량은 개인화.** 기존 카탈로그의 `exampleTarget`은 입력 예시이지 충분한 생존 수량이 아니다. 글에서 공식 필수량·완비 기준으로 바꿔 말하지 않는다.
7. **원본 보호.** 새 글 작성은 IndexedDB의 실제 수량·제품 기한·재고·백업/복원, 카탈로그 ID, A/B/C 자동화나 배포 설정을 수정하지 않는다.

## 데이터 연결: 최소 구조

- 기존 `guide-01`~`guide-49`를 **품목의 안정적인 참조키**로 사용. 품목명·분류·배열 순서로 글을 추측해 연결하지 않는다.
- 공개 시 글마다 별도의 고정 URL과 `catalogId`를 갖는다. 예: `guide-43` ↔ `/knowledge/bag/flashlight/` (경로는 연결 개발 시 확정; **현재 존재하는 페이지라고 주장하지 않음**).
- 물품별 소개 화면에는 "자세히 알아보기" 1개와 "내 가방"으로 돌아오는 경로를 제공한다. 기존 Automation C 문서는 본문으로 복제하지 않고 "더 읽기"로 연결.
- 처음에는 단순 정적 원고·명시적 ID 매핑을 우선하고, 관리 DB·자동 게시·새 스키마·별도 예약은 만들지 않는다.
- 기존 개인 물품은 사용자가 직접 이름을 정할 수 있다. `catalogId`에 대응하는 추천 항목만 1차 자동 연결하며 임의 이름의 물품까지 부정확하게 일치시키지 않는다.

- 공개 전: 실제 `CATALOG` ID/품명 일치 → 신규 집필·중복 점검 → 출처 URL·내용 확인 → 모바일 가독성 → 안전/개인정보 주의 → 사용자 승인.
