## 동일한 가상 시험 데이터

`docs/bunker_os/E002_BAG_SCENARIO_V1.json`이 테스트 기준이다. 물품 5종은 가상 예시이며 권장 비축품/권장 수량/안전성 판단이 아니다.

| 물품 | 목표 | 처음 보유 | 별도 묶음/점검 |
|---|---:|---:|---|
| 간편식 | 6 | 6 | 기한이 다른 A 4개 + B 2개 |
| 생수 | 2 | 2 | 표시된 날짜 1묶음 |
| 손전등 | 1 | 1 | 작동 점검일 관리 |
| 보조배터리 | 1 | 1 | 충전·작동 점검일 관리 |
| 위생티슈 | 2 | 2 | 표시된 날짜 1묶음 |

**고정 시나리오**
1. 위 물품 5종을 '내 가방'에 등록한다. 기한이 다른 간편식은 개별 묶음으로 기록한다.
2. 간편식 A에서 2개를 꺼낸다 → 총 보유 6→4, 부족 0→2, B 묶음은 변경 없음.
3. '구매함/주문함' 표시만 한다 → 보유 4, 부족 2. 구매를 곧바로 실제 가방 입고로 간주하면 실패.
4. 2개를 새 묶음 C로 실제 가방에 넣는다 → 총 보유 4→6, 부족 2→0. 묶음 A·B의 날짜 변경 금지.
5. 알림 미루기 → 표시기한과 수량 불변. 상태가 '안전 보장'으로 바뀌면 실패.
6. 가능하면 백업→복원하여 상태/날짜/부족량이 모두 동일한지 확인한다.

날짜는 **제품 표시기한과 임의의 관리예정일을 별도로 관리**하며, 여유기간(예: 90일)은 안전기준이 아닌 사용자 설정이다. 약은 자동 순환 섭취 권고 대상이 아니다.

## 측정 방법 (우선 검증, 비용 0원)

- 첫 입력: 시작~5종 등록 완료 시간, 화면 누름 횟수, 도움 질문 수.
- 유지 관리: 2개 꺼냄 → 부족 표시 → 물리적 입고 완료까지 걸린 시간/누름 횟수.
- 정확성: 6→4→6, 부족 0→2→0; 날짜 묶음 혼합, 이중 차감, 구매만으로 완료, 백업 손상 **모두 0건**.
- 재사용 의사: '실제 다음 관리 때 이 방식을 쓰고 싶은가?'와 **왜 그런지** 짧게 묻는다.
- 3~5인 관찰은 UX 오류 발견 목적. 시장 수요/유료 구매의사의 통계적 증거 아님.
- 동일한 진행자가 동일한 순서/기기 조건에서 각 대안을 비교. 실험순서 효과(처음/나중 익숙함) 기록.

**잠정 가설/도전 기준:** 우리 초안은 5종 초기 등록 5분 이내, 소비·보충 각 30초 이내, 장부 오류 0건. 3~5명 중 다수에게 경쟁 대상보다 적은 수고가 관찰되지 않으면 Android 전체 개발 보류. 시간이 조금 단축된 것만으로 '사업성 PASS'를 선언하지 않는다.

## 최소 UX 후보와 중단 조건

필수 상태: `목표수량 / 실제 가방수량 / 부족수량 / 묶음별 표시기한 / 다음 확인일`.
필수 행동: `꺼냈어요 / 가방에 넣었어요 / 점검했어요 / 나중에 알림`.
첫 화면 우선순위: `오늘 확인할 것 / 부족한 것`. 광고, 회원가입, 게임, AI 추천, 가족 동기화, 쇼핑몰은 첫 시험에서 배제.
부족 계산은 `max(목표 - 실제, 0)`. **구매 또는 알림 미룸으로 재고를 증가시키지 않는다.**
오프라인 저장/백업과 Android 수개월 알림은 분리된 기술 Gate. 5분 후 알림 성공을 9개월 보장으로 표현하지 않는다.

### 개발 계속/중단

- **CONTINUE:** 실제 사용자가 기존 방식을 선택하지 않고 우리 흐름을 이유 있게 선호하고, 오류 0건. 그때부터 비공개 웹 알파 또는 최소 Android POC를 다음 실험으로 제안.
- **REVISE:** 복잡함·단계 초과·버튼 모호함이면 사용자 불편 지점을 줄인 뒤 동일 과제로 1회 재검증.
- **STOP/SWITCH:** 종이/엑셀/기존 앱이 이미 충분하거나 차별화·사용 의향이 거의 없으면 앱 제작 보류하고 기존 지식·관리표·알림 안내를 개선.
