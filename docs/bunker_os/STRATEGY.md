# Bunker OS V1 — STRATEGY

기준일: 2026-10-10 KST

이 문서는 현재 가장 합리적이라고 보는 **전략 가설**이다. NORTH_STAR와 달리 새로운 증거가 나오면 적극적으로 바꾼다.

## 현재 전략 가설

> **생존지식 사이트는 실용 지식과 도구의 본진이 되고, 벙커로 가는 장기 여정은 사람들이 계속 따라올 이유가 되며, 검색·영상·공유 등은 유통망, 상품·제휴·광고·앱·서비스 등은 열린 수익 출구가 된다.**

### 역할 분리
- **생존지식**: 문제를 해결한다.
- **도구/자료**: 읽기를 실제 준비 행동으로 바꾼다.
- **Bunker Journey**: 장기 서사와 차별화를 만든다.
- **검색/영상/공유**: 사람을 데려온다.
- **수익 모델**: 실제 반응이 확인된 곳에 붙인다.

모든 독자가 벙커에 관심 가질 필요는 없고, 모든 벙커 콘텐츠 시청자가 상품을 살 필요도 없다.

## 현재 실행 기반 — 사용자 확인 사실

- **주업:** 태장. 태장 안에 사용자가 기존부터 운영해 온 구매대행·온라인 유통 경험을 포함한 온라인사업부가 있다.
- **종료 사업:** PC방 사업은 종료 상태이며 현재 캐시플로나 성장축으로 계산하지 않는다. 과거 운영 경험은 역량 참고로만 본다.
- **장기 개인 프로젝트:** 벙커는 취미이자 최상위 북극성이다.
- 태장/온라인사업부의 인력·유통·물류·B2B·제조/포장 자산은 실제 시너지가 확인될 때만 Bunker Project에 활용한다. 본업을 해치면서 억지로 결합하지 않는다.
- 과거 대화에서 파악한 세부 역량은 시간이 지나며 바뀔 수 있으므로, 30일/분기 계획을 확정할 때는 현재 숫자와 자원 상태를 별도 스냅샷으로 갱신한다.

## 수익화 원칙

수익 모델은 미리 하나로 고정하지 않는다.

현재 후보:
1. 광고·협찬
2. 관련 제품 제휴/커머스
3. 자체 자료·도구·웹앱
4. 영상·출판·후원·IP
5. 사업자 대상 자료/서비스/B2B
6. 반복 사용 이유가 확인된 뒤의 멤버십·구독
7. 사이트 개발과 운영 과정에서 파생되는 별도 사업 기회

### 선택 기준
각 후보는 다음을 본다.
- 실제 유입
- 실제 유용 행동
- 돈을 낼 이유
- 객단가
- 반복 가능성
- 운영 노동
- 법·안전·신뢰 위험
- 벙커 여정과의 시너지

아이디어는 넓게 보관하되 동시에 큰 실험은 하나, 보조 실험은 최대 하나를 원칙으로 한다.

## 시간 전략

### 0~6개월 — 이해와 기반
- 사이트 자산·시장·경쟁·유통·수익모델을 이해한다.
- 행동 측정 기반을 만든다.
- 대표 글을 “읽기 → 행동”으로 바꾸는 소규모 실험을 한다.
- 검색 외 유통 후보를 조사한다. YouTube는 유력 후보이나 아직 정답으로 확정하지 않는다.
- 벙커 요구사항과 연구 범위를 정의한다.

### 6~18개월 — 반복되는 신호 찾기
- 반복 사용·재방문·공유·다운로드가 일어나는 주제와 도구를 확대한다.
- 유망한 유통 채널 1~2개를 반복 실험한다.
- 첫 수익 신호가 있다면 작은 규모로 재현성을 확인한다.
- 벙커 준비 연구를 콘텐츠와 별개로도 계속 축적한다.

### 18~36개월 — 자산화
- 쌓인 자료·도구·자동화·사용자 데이터를 운영 자산으로 만든다.
- 수익모델이 반복되면 확대하고, 아니면 과감히 교체한다.
- 벙커 부지/법/설계/전문가/재원 시나리오를 구체화한다.

### 36~60개월 — 확대와 실물화
- 가장 강한 유통·상품·브랜드 경로에 자원을 집중한다.
- 조건이 갖춰지면 벙커 설계·허가·시공 단계로 들어간다.
- 4년 준비 후 5년차에 큰 수익이나 실행이 발생해도 허용한다. 중요한 것은 준비 기간에 자산과 증거가 실제로 쌓였는가이다.

## 외부 지식 적용 규칙

좋은 영상·기사·책·채널·제품·사례를 발견하면:
1. SOURCE_LIBRARY에 기록
2. 핵심 주장과 근거 수준 파악
3. 기존 전략과 충돌/보완 여부 확인
4. 전략에 영향이 크면 DECISION_LOG 후보 생성
5. 검증할 수 있으면 EXPERIMENT_LOG로 전환
6. 결과가 나오면 STRATEGY를 수정

좋은 자료를 채팅에서 소비하고 끝내지 않는다.

## 현재 실행 초안

현재 30일 운영 초안은 Issue #501이다. Bunker OS V1이 main에 정착한 뒤 월간·주간 계획을 사용자와 최종 합의하고 실행한다.

## 전략 변경 조건

다음 중 하나면 전략을 다시 본다.
- 유효 행동이 예상과 크게 다름
- 반복 유입 채널이 발견됨
- 예상하지 못한 수익 신호가 발생
- 운영 노동이 수익보다 빠르게 증가
- 안전·법·신뢰 리스크 발견
- 벙커 준비 과정에서 새로운 제약/기회 발견
- 사용자가 “재미/목적이 훼손되고 있다”고 판단
