# Bunker OS — 전 프로젝트 상위목표 정렬판 V1

- 기준일: 2026-10-16 (KST)
- 상태: **기본 방향 합의 / 개별 프로젝트별 독립 점검 결과 접수 전**
- 목적: AI 대화방이 달라도 **삶의 목표 → 각 프로젝트의 역할 → 현실의 증거 → 다음 행동**을 잃지 않도록 하는 최상위 인덱스.
- **공개 범위 주의:** 이 저장소는 PUBLIC이다. 개인·가족 재무 수치, 태장 거래처 연락처·견적·계약, 비공개 사업정보, 개인 자산/벙커 위치, 인증정보, 전체 대화 원문은 이 파일에 저장하지 않는다.

## 1. 삶의 방향과 우선순위

> **가족과 함께 안정적이고 준비된 미래를 구축한다.** AI와 함께 현실의 벙커를 만들어 가는 것은 장기 북극성이며, 그 전제이자 당장의 첫 관문은 가정을 지키는 안정적인 수익·현금흐름과 경제적 실행력이다.

- **현재 먼저 지킬 것:** 가족 생활 안정, 태장의 기존 고용·운영 기반, 필수 법적/안전 책임.
- **현재 먼저 성장시킬 것:** 태장에 적합한 반복 작업의 외부 수요와 실제 유료 매출을 검증하고, 온라인 판매 경험을 낮은 구조적 의존도와 개선된 실질 수익으로 전환한다.
- **장기 북극성:** 벙커의 실물화. 조사·설계·건설 가능성은 준비도를 쌓되 가정과 본업을 희생하지 않는다.
- **취미와 장기 자산:** 생존일기·생존지식·생존가방·벙커 연구는 창작의 재미와 재충전의 가치가 있다. 단기 현금 수익을 강요하지 않으며, 실제 사용 수요가 확인될 때 상품화 가능성을 시험한다.
- **AI/자동화:** 목표 달성의 수단이지 목표 자체가 아니다. 업무를 늘리는 자동화는 확대하지 않는다.

이 삶 전체의 우선순위와 기존 [NORTH_STAR](NORTH_STAR.md)의 장기 벙커 Mission은 서로 다른 시간 계층이다. 기존 5년 생존지식/벙커 계획을 곧바로 폐기·중단하는 결정이 아니다.

## 2. 프로젝트별 역할 — 각 프로젝트의 원본을 대체하지 않는다

| 프로젝트 | 상위 목표에 대한 역할 | 최근 확인된 방향 또는 범위 | 현실 성과/다음 판단 | 로컬 기록의 주인 |
|---|---|---|---|---|
| **태장** | 당장의 생활 안정 + 사업 성장의 핵심 엔진 | 기존 계약·고용을 지키고 외부 반복 임가공 작업 확보, 장기적으로 참여 모회사 확대 | **실제 고객 접촉과 유료 반복 수주**가 검증 대상. 후보 탐색은 수주 성공이 아니다 | 비공개 업무수첩/Notion, 태장 사업 기록 |
| **온라인 판매** | 기존 현금 유입 보호 + 장기 체질 전환 | 저마진 구매대행 의존을 점진적으로 낮추고 자체/고부가 상품 판매 검증 | 고객 수요·반품·공헌이익·재고 위험을 기준으로 판단. 신제품 성공 미검증 | 태장/온라인사업 운영 자료(비공개) |
| **현실 벙커 / Bunker OS** | 장기 북극성 및 전략·결정의 통합 기준 | 부지·법·안전·설비·예산·전문가 검증으로 불확실성 감소 | 계획 작성과 실제 건설 가능성 검증을 구분 | Bunker OS, 비공개 상세 원본 별도 |
| **생존지식 사이트** | 취미에서 출발한 실용 지식·장기 자산 | 근거 있는 지식과 검색 가능성, 실제 도움이 되는 콘텐츠 축적 | 작성·발행 ≠ 독자의 실사용. 기존 운영 계획 독립 유지 | 생존지식/Automation C, Bunker OS 요약 |
| **생존가방 앱** | 지식을 실제 준비·관리 행동으로 연결하는 제품 | 웹·PWA 운영기반과 지식 연결 유지·검증 | 기술 QA ≠ 실제 이용자 지속 사용. 기존 보류/검수 상태 존중 | BAG-SIDE 원본 이력, Bunker OS 요약 |
| **생존일기·위키·그림 / A·B·A-Wiki** | 창작 재미·재충전·미래 IP 선택권 | 검증된 자동화는 유지, 실패 복구·품질 개선만 필요한 만큼 | 운영 정상 ≠ 수익화. 본업을 압박하는 확장 경계 | 각 Automation/Worldline 원본 |
| **업무수첩** | 현실 업무 실행·후속처리의 개인 기록 원본 | 기존 Notion 기록, 우선업무 브리핑, 모바일 입력 재사용 | 사용자의 실제 처리 완료와 기록을 분리 확인 | 업무수첩/Notion (비공개) |
| **온라인 학습 파이프라인** | 유용한 외부 지식을 빠르게 이해·토론·활용 | 유튜브 링크 → 원문 확인 → 토론. 공급자/도구 개발은 수단 | 실제 링크 한 번으로 대화 성공 여부가 성과 | `online-learning-pipeline` 비공개 원본 |
| **공통 AI 개발 방식** | 위 프로젝트의 시행착오·운영 부담 감소 | 단순화, 구조화, 검증, 재사용; 별도 공통 서비스 과잉 설계 금지 | 코드 수나 PR 수보다 절약된 노동과 오류 감소 | 각 프로젝트 GitHub/운영 규칙 |

**기준:** 표의 '현재 방향'은 기존 대화/문서의 기준선이다. 이 표 전체가 각 프로젝트의 최신 런타임 상태를 검수했다는 뜻은 아니다. 프로젝트별 신규 점검 보고를 받으면 실제 근거를 읽고 업데이트한다.

## 3. 지금 가장 중요한 현실 행동

- **1차 경제 실행:** 태장의 기존 작업 여력을 활용할 수 있는 외부 임가공 수요를 **실제 업체 문의로 확인**한다. 첫 영업 후보는 조사됐지만, 고객 수요와 수주 결과는 아직 검증되지 않았다.
- 사용자 역할: 실제 상담·외부 연락·계약 판단.
- AI 역할: 공개 후보 발굴, 사실 확인, 연락 전략·수익성 검토, 응답에 따른 다음 행동 제안.
- **완료 판정:** '후보를 찾았다'가 아니라 '실제 연락·응답을 기록했다'를 실행 증거로 인정한다. 유료 발주·반복 구매는 별도의 성과다.
- 고객의 실명/전화번호/단가/상담 내용과 사용자 개인 가용 자금은 공개 Bunker OS에 복사하지 않고 **기존 비공개 실행 원본**에서 관리한다.

이 행동만이 모든 프로젝트의 다음 행동이라는 뜻은 아니다. 각 프로젝트의 고유한 안전·운영 필수 작업은 유지한다. 다만 **현재 신규 성장 노력의 가장 높은 우선순위**를 명시한다.

## 4. 개별 프로젝트 점검 결과를 모으는 최소 계약

사용자가 각 프로젝트 대화방에 **상위목표 정렬 점검 지시문**을 전달한다. 개별 AI가 해당 프로젝트의 원본과 현황을 검토한 후 다음 7개 항목만 Bunker OS에 전달할 수 있도록 간결히 정리한다.

1. **Project ID / 자료 기준일:** 프로젝트명, 실제로 읽은 로컬 원본·검증 시점.
2. **목표:** 상위목표 한 문장과 삶 전체에서의 역할(주업/장기 자산/취미/운영 수단).
3. **근거 있는 성과:** 실제 서비스 작동, 사용자 행동, 매출/수주 등을 구분. 미검증이면 미검증.
4. **병목 + 핵심 변수 가설:** 가장 큰 장애와 이를 바꿀 후보 한 가지. 가설이라고 표시.
5. **단 하나의 다음 행동:** 누가, 무엇을, 어떤 완료 증거로 확인하는가.
6. **결정:** 유지/축소/중단 검토 및 재검토 조건(필요 시 [DECISION_LOG](DECISION_LOG.md) 갱신).
7. **기록 위치 + 비공개 경계:** 상세 원본이 어디에 있는지 유형만 기재하고 공개에 부적절한 내용을 제거.

**입력 규칙:** 각 프로젝트 AI가 보낸 검수 보고나 사용자 확인을 Bunker OS에 가져오면 해당 행/결정만 갱신한다. 다른 채팅방·비공개 시스템의 내용을 자동으로 읽거나 즉시 동기화한다고 약속하지 않는다. 접근 권한이 없으면 `확인 불가`로 남긴다.

## 5. 기록의 원본과 안전한 동기화

```text
개별 프로젝트의 실제 증거·업무 상태 (각각의 기존 원본)
                  │
          근거를 확인한 점검 요약
                  ▼
         Bunker OS (전체 목표와 전략 기준)
          ├─ NORTH_STAR: 바꾸기 어려운 삶의 방향
          ├─ STRATEGY: 바뀔 수 있는 전략 가설
          ├─ DECISION_LOG: 선택·기각 이유·재검토 조건
          ├─ EXPERIMENT_LOG: 소규모 실험 가설·결과
          └─ 이 문서: 프로젝트 전체 정렬·진행 인덱스
                  │
                  ▼
       기존 업무수첩/홈페이지는 필요한 내용을 읽어 보여줌
```

- **중복 기록 방지:** 로컬 상태(업무 완료, 고객 연락, 제품 발행, 운영 receipt)의 권위는 기존 시스템에 남는다. Bunker OS는 교차 프로젝트 우선순위·의사결정·검증 요약의 권위만 갖는다.
- **공개 경계:** 전략 요약은 PUBLIC GitHub에 둘 수 있지만, 개인 현금흐름·가족/사업 기밀·고객 자료·계약·벙커 실제 부지는 별도의 비공개 원본에만 둔다. 공개/비공개 자동 복제는 만들지 않는다.
- **실제 증거 표시:** `USER_REPORTED`(사용자 진술), `DOCUMENT_VERIFIED`(문서 확인), `RUNTIME_VERIFIED`(실사용 검증), `HYPOTHESIS`(가설), `UNVERIFIED`(미확인)을 구분한다.
- **업데이트 주기:** 새 전략 결정을 내리거나, 프로젝트 점검 보고가 도착하거나, 현실 성과가 달라질 때만 해당 행을 갱신한다. 우선 자동 일정·신규 DB·대시보드는 만들지 않는다.
- **성공 판정:** 'Bunker OS가 업데이트됐다'가 아니라 **가정 안전을 해치지 않으면서 실제 다음 행동·증거가 누적됐는가**를 본다.

## 6. 첫 회차 상태 — 2026-10-16

- **전체 삶의 목표와 경제적 관문:** 사용자 확인, 방향 확정.
- **태장 첫 실험:** 외부 반복 일감 수요를 실제 문의로 검증하기로 결정. 현재 문의·수주 결과는 미확인.
- **다른 프로젝트:** 사용자에게 공통 점검 프롬프트 전달 예정. 각 프로젝트의 신규 진단 결과는 **아직 접수 전**. 기존 운영 작업을 일괄 중단·완료·우선순위 변경하지 않음.
- **본 기록 자체:** 다른 프로젝트의 자료를 자동 취합하는 프로그램이나 웹보드가 아님. 기존 파일만 활용하는 최소 실행 기록.
