10/15/18kg은 참고 무게 예산이며 실제 합산 중량이 아니다. 어린이·고령자·질환자에게 일반화하거나 가족 인원을 곱하지 않는다.
모든 이름·분류·단위·설명은 기존 catalog를 참조한다. 처방약·고위험 방호용품은 프리셋에 없으며 개인 필요를 별도 확인한다.

## 적용·날짜·데이터 보존

미리보기에서 포함 체크·목표·점검일을 조절하고 한 번 제출한다. 기본 실재고 0.
실제 담음 옵션은 미선택 기본이며 새 물품만 대상으로 한다. 기존 항목은 목표·주문·묶음·날짜를 그대로 유지한다.
catalog 연결 ID 또는 기존 NFC/소문자 정확 일치 이름만 식별한다. 비슷한 다른 이름은 통합하지 않는다.
더 작은 프리셋도 기존 항목을 삭제하지 않는다. 같은 프리셋 재적용은 저장 내용과 revision이 그대로다.

첫 점검 예정일: 물·식품·위생·전원/통신 30일, 의류·보온·수면 90일,
서류·일반 도구 180일, 의약품 분류(구급함·밴드 포함) 당일.
앱의 초기 관리 설정이며 제품 수명·섭취 가능 기간·제조사 권장 주기가 아니다.
제품 기한과 보관조건은 실물에서 즉시 확인한다. 식품·물·의약품의 기한 미입력은 미래 점검일과 별개로 바로 안내한다.
로컬 날짜로 최초 미리보기 시 계산하고 저장하며, 새로고침/재적용으로 밀리지 않는다. `today` 주입으로 테스트한다.

`schemaVersion:1`, 백업 `formatVersion:1`, IndexedDB version 1과 기존 엄격한 필드 검증을 유지한다.
새 필드·마이그레이션 없이 기존 item ID `catalog-guide-NN`에 연결을,
기존 batch ID `draft-<random ID>`에 초안 출처를 기록한다. 날짜는 기존 `nextInspection`, 제품 기한은 `markedUntil:null/dateType:none`.
0수량 초안 묶음 한 개를 생성하며 반복 적용에서 늘어나지 않는다. 목록에는 펼치지 않아도 초안 날짜가 보이고,
기존 `dashboardBag`는 계속 0수량 묶음을 실물 관리 일정에서 제외한다.
구버전 탭도 같은 V1 필드를 이해하며 revision 검사로 오래된 저장을 차단한다. 알 수 없는 필드 허용 없음.

전체 후보 검증 후 기존 `saveBag` 한 번 호출. current/previous는 같은 transaction에 저장되며 실패 시 함께 롤백한다.
이전 저장 복원으로 적용 직전 가방 전체를 복구할 수 있다. JSON은 예전 V1과 새 초안의 왕복을 모두 지원한다.

고정 QA는 branch-deploy context·HTTP200·noindex를 추가로 요구한다. 임의 원격 주소/Production은 거절한다.
실제 결과·CI run·HEAD·QA SHA는 PR 검증 댓글을 따른다. 이 문서만으로 배포 PASS를 선언하지 않는다.

## 한계

참고 무게를 실제 계산하지 않는다. 푸시·Android·회원·동기화·클라우드·자동화 예약 없음.
QA와 다른 origin의 기록은 자동 이동하지 않는다. 장기 보존은 브라우저 정책에 영향을 받으므로 JSON 별도 보관이 필요하다.
초안의 점검 출처는 ID로 구분하므로 사용자가 JSON에서 ID를 직접 바꾸면 출처 표시는 없어질 수 있다.
