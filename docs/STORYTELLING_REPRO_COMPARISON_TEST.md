# 《생존일기》 스토리텔링 재현·비교 테스트

## Status
- 그래픽/UI 초기 기획은 이 테스트 기간 동안 기능 추가를 최소화한다.
- 현재 최우선 검증 대상은 **AI GM 스토리텔링 품질**이다.
- Canon v2가 현재 세계 사실의 Source of Truth다.
- 과거 RAW transcript는 **비교용 품질·사건 구조 자료**일 뿐 런타임 입력이 아니다.

## 핵심 질문

> 현재 웹게임 AI GM과 플레이했을 때, 예전 ChatGPT에서 《생존일기》를 플레이하던 것처럼 내가 선택한 뒤 이야기가 자연스럽게 계속 전개되고 다음 장면이 궁금해지는가?

이 질문에 YES가 나올 때까지 스토리텔링 병목을 우선 개선한다.

---

## 1. 테스트 방식 — Replay가 아니라 같은 출발선의 비교

사용자가 과거 선택을 기억하거나 동일하게 재현하지 않는다.

### A. 과거 플레이 벤치마크
기존 RAW / Canon / 실제 플레이 기록에서 다음을 추출한다.
- 초기 세계 상태
- 가족 위치와 관계
- 거점 상태
- 차량 및 공개 물자 상태
- 최초 사건
- 초반 위기 구조
- 주요 갈림길
- 과거 GM의 장면 전개 방식
- 당시 실제 사용자 행동

이 데이터는 비교용 기준으로만 사용한다.

### B. 현재 AI GM 테스트
동일하거나 매우 유사한 초기 세계 조건에서 출발한다.
사용자는 과거 선택을 몰라도 되며 지금 하고 싶은 판단대로 플레이한다.

> 같은 세계 조건에서 과거 GM과 현재 GM이 각각 얼마나 좋은 생존 이야기를 만들어내는가를 비교한다.

현재 런타임에 과거 USER 선택 경로를 주입하지 않는다.

---

## 2. 첫 비교 시즌 — Canon v2 S01 산불

### 선정
첫 벤치마크는 **Canon v2 S01 산불·대피 오프닝**으로 확정한다.

### 선정 근거
- 초반 사건이 산불이라는 명확한 압력을 가진다.
- 가족 4인이 서로 다른 위치에서 시작한다.
- 이동 / 통신 / 정보 / 도로 / 거점 판단이 동시에 등장한다.
- 가족 독립 판단과 갈등이 자연스럽게 발생할 수 있다.
- 단순 생존 퀴즈보다 장기 이야기로 확장될 여지가 크다.
- S01 RAW는 시작부터 종료까지 9개 PART로 연속 보존되어 비교 자료가 충분하다.

### 현재 웹 벤치마크 시작 조건
과거 시즌을 그대로 복제하지 않고 다음 조건만 유사하게 맞춘다.
- 2026년 9월 초 저녁 / 현대 한국
- 준호: 회사
- 서윤: 병원
- 민석: 학원
- 정호: 산림 인접 외곽주택
- 가족 차량 사용 가능
- 통신 정상
- 도심 아파트와 외곽주택 존재
- 강풍 속 산불 확산 우려 긴급 안내
- 외곽 도로 통제 가능성
- 퇴근시간 교통 증가

이후 사건은 현재 AI GM이 플레이어 선택과 공개 상태만 보고 독립적으로 전개한다.

## 3. 원하는 한 턴의 서사 구조

실패 패턴:

`선택 → 성공/실패 요약 → 상태값 변경 → 즉시 다음 선택`

목표 패턴:

`선택 → 실제 행동 장면 → 가족/주변 사람 반응 → 환경/사회 상황 변화 → 새로운 정보 → 필요하면 대화·작은 사건 → 새로운 판단 지점 → 다음 선택`

모든 턴을 장문으로 만들 필요는 없다.
그러나 플레이어의 한 선택이 최소 하나의 **의미 있는 장면**을 만들어야 한다.

상세 품질 기준은 `docs/GM_NARRATIVE_QUALITY_BENCHMARK.md`를 따른다.

## 4. 평가 항목

플레이 중 매 턴 점수표를 띄우지 않는다.
몰입을 유지하고, 한 구간 또는 세션 종료 후 평가한다.

1. **몰입감** — 다음 이야기가 궁금했는가
2. **서사 진행** — 행동 후 상황이 실제로 앞으로 갔는가
3. **인과관계** — 플레이어 선택이 이후 세계에 남았는가
4. **가족 생동감** — 서윤·민석·정호가 독립된 사람처럼 행동했는가
5. **긴장 변화** — 위기가 발전·완화·변형되고 같은 상황이 반복되지 않았는가
6. **선택지 품질** — 현재 장면에서 자연스럽게 나온 선택인가
7. **자유행동 이해** — 복수 행동, 역할 분담, 자연어 명령을 이해했는가
8. **상태 연속성** — 위치·차량·물자·시간·이전 행동의 모순이 없는가
9. **장기 전개 능력** — 단순 턴 반복이 아니라 더 큰 국면으로 발전하는가
10. **읽는 재미** — 기존 ChatGPT 시즌처럼 계속 읽고 싶은가 (**최우선**)

## 5. 과거 시즌과 비교할 항목

문장을 동일하게 만드는 것이 목적이 아니다.

비교 대상:
- 장면 밀도
- 사건 발생 빈도
- 가족 대화와 갈등
- 예상 밖의 상황 발생
- 플레이어 행동 반영 정도
- 장기 이야기 확장성
- 반복적 GM 문장 여부
- 선택지의 기계적 생성 여부
- 자유행동 반응 품질
- 한 턴에 실제로 진행되는 사건량

---

## 6. 사용자 기억에 의존하지 않는다

사용자에게 다음을 요구하지 않는다.
- 예전에 몇 번을 골랐는지
- 당시 어떤 순서로 행동했는지
- 정확히 어떤 문장을 입력했는지

필요한 과거 데이터는 GitHub의 RAW / Canon / 기록에서 시스템이 직접 확인한다.

현재 테스트에서 사용자는 현재 판단대로 플레이한다.

---

## 7. 테스트 중 신규 개발 제한

이번 구간에서는 신규 기능을 계속 붙이지 않는다.
문제를 발견하면 먼저 원인을 다음 범주로 분류한다.

- AI 모델 자체의 서사 능력
- GM 프롬프트
- 턴 종료 조건
- 선택지 생성 구조
- Validator가 서사를 지나치게 제한하는 문제
- 상태 저장/복원 문제
- 자유행동 파싱 문제
- 출력 토큰/시간 제한

원인을 확인하기 전 임의의 기능 추가로 문제를 덮지 않는다.

### UI 동결 예외
플레이 자체를 방해하는 다음 문제만 수정 가능하다.
- 화면 잘림
- 입력 불가
- 선택 팝업이 화면 안에 들어오지 않음
- 글자 크기/가독성의 명백한 문제
- 상·하단 HUD가 사라지는 문제

## 8. 세션 운영

첫 플레이는 사용자가 자연스럽게 진행한다.
권장 관찰 구간은 **최소 10턴, 가능하면 하나의 초반 국면이 끝나는 지점까지**다.

테스트 도중 기술 오류가 아니라 스토리 취향 피드백이 나오면 즉시 프롬프트를 계속 수정하지 않고 기록한다.
한 구간을 끝낸 후 묶어서 분석한다.

## 10. 통과 조건

스토리텔링 구조의 1차 통과 기준은 숫자 점수가 아니라 다음 사용자 판단이다.

> **예전 시즌처럼 선택 뒤 이야기가 충분히 진행되고, 가족이 살아 있으며, 다음 장면을 계속 읽고 싶다.**

이 판단이 나오기 전까지 그래픽/UI 확장을 주 개발 목표로 올리지 않는다.
