# Post-Season Survival Debrief v1

Status: Canon v2 core feature  
Parent: GitHub Issue #45 / #48

## 1. 목적

《생존일기》는 플레이 중 생존 강의를 하는 게임이 아니다.

플레이어는 먼저 재난을 **경험하고 선택**한다. 시즌이 끝난 뒤 자신이 실제로 겪은 장면과 판단을 바탕으로 현실 생존지식을 확인한다.

핵심:

> **먼저 살아본다. 끝난 뒤 실제라면 어땠는지 배운다.**

## 2. 본편과 교육의 분리

### 본편 중
- 재난 상식은 장면, 환경, 정보, 선택 결과에 자연스럽게 녹인다.
- 장황한 설명이나 출처 나열을 하지 않는다.
- 플레이어에게 점수나 교사식 평가를 수시로 제시하지 않는다.

### 시즌 종료 후
원할 때 Post-Season Survival Debrief를 연다.

두 층으로 분리한다.

1. **플레이어 생존 리포트** — 현실 생존 관점
2. **제작/시스템 복기** — 게임 개발 관점

웹에서는 1번을 기본 플레이어 콘텐츠로, 2번은 개발/테스트 모드 또는 별도 메뉴로 둘 수 있다.

## 3. 플레이어 생존 리포트 기본 구성

### A. 이번 시즌 핵심 상황
- 시즌에서 실제 플레이어가 직면한 주요 위험 3~7개
- 결과를 스포일러식으로 재서술하기보다 판단 맥락 중심으로 요약

### B. 잘한 판단
각 항목:
- 당시 선택
- 왜 현실적으로 유리했는가
- 어떤 위험을 낮추거나 선택권을 늘렸는가

### C. 위험했던 판단
각 항목:
- 당시 선택
- 어떤 위험 노출을 키웠는가
- 결과가 좋았더라도 왜 위험했는가

**결과가 좋았다는 이유만으로 안전한 판단으로 평가하지 않는다.**

### D. 놓친 요소
- 확인하지 못한 정보
- 준비하지 못한 자원
- 시간/거리/피로/가족 변수
- 현실에서는 추가로 확인했을 요소

### E. 운과 판단 분리
가능하면 다음을 구분한다.
- 좋은 판단이 만든 이득
- 위험한 선택이 우연히 무사했던 부분
- 나쁜 결과가 반드시 나쁜 판단 때문은 아닌 부분
- Hidden State/불확실성 때문에 결과가 달라진 부분

### F. 현실에서 개선할 수 있는 준비
게임 플레이 경험을 현실 준비 행동으로 연결한다.

예시 범주:
- 가족 연락/합류 계획
- 재난정보 확인 습관
- 물·식량·의약·전력·연료 기본 준비
- 차량/이동 계획
- 거주지별 위험 파악

세부 내용은 해당 시즌의 검증된 공식 지식만 사용한다.

### G. 이번 시즌 핵심 생존지식
기본 3~7개.

각 항목은:
- 짧은 제목
- 핵심 한두 문장
- 플레이에서 연결되는 장면
- 근거 Source ID

를 가진다.

## 4. 평가 톤

- 플레이어를 비난하거나 조롱하지 않는다.
- `정답을 못 맞혔다` 식으로 다루지 않는다.
- 생존 판단에는 정보 부족과 불확실성이 있다는 점을 반영한다.
- 위험 감수와 무모함을 구분한다.
- 플레이어가 의도적으로 위험 결과 범위를 시험한 `[STRESS_TEST]` 선택은 일반 판단 실수와 분리한다.

## 5. 점수 정책

기본적으로 `72점`, `A등급` 같은 종합 점수는 사용하지 않는다.

이유:
- 실제 재난에는 단일 정답이 없는 경우가 많다.
- 운과 정보 부족이 개입한다.
- 점수는 플레이어가 게임 정답을 찾는 방향으로 학습하게 만들 수 있다.

필요하다면 미래에 영역별 진단을 도입할 수 있지만, Canon v2 기본값은 **질적 복기**다.

## 6. 사실 검증과 출처

현실 생존 지식은 `knowledge/SOURCES.md` 및 향후 구조화된 Source Registry를 기준으로 한다.

우선순위:
1. 대한민국 정부/지자체 공식 재난안전 자료
2. 공신력 있는 의료·응급·보건기관
3. 기타 전문기관

커뮤니티 팁이나 출처 불명 정보는 공식 지침과 충돌할 경우 사용하지 않는다.

### 중요
- GM의 서사적 판단과 현실 생존 사실을 분리한다.
- 공식 근거가 없는 사실을 교육 콘텐츠에서 확정적으로 말하지 않는다.
- 검증일을 기록한다.
- 공식 지침이 변경되면 교육 콘텐츠를 갱신할 수 있어야 한다.

## 7. 미래 웹 렌더링을 위한 콘텐츠 계약 방향

최종 형식은 구현 단계에서 결정하지만, 최소 개념은 다음과 같다.

```json
{
  "season_id": "R-S01",
  "decision_reviews": [
    {
      "scene_ref": "...",
      "decision": "...",
      "assessment": "good | risky | mixed | stress_test",
      "reason": "...",
      "source_ids": ["..."]
    }
  ],
  "missed_factors": [],
  "real_world_preparation": [],
  "lessons": [
    {
      "title": "...",
      "summary": "...",
      "source_ids": ["..."]
    }
  ]
}
```

이 JSON 예시는 방향일 뿐 현재 엔진 계약으로 확정하지 않는다.

## 8. 시즌 종료 데이터 수집

복기의 품질을 위해 플레이 중 모든 턴을 장기 저장할 필요는 없다.

대신 의미 있는 Decision Record를 남길 수 있다.

후보:
- 플레이어의 중요한 선택
- 선택 당시 공개 정보
- 주요 Hidden State 결과(시즌 종료 후 공개 가능한 범위)
- 발생한 비용/손실/회피된 위험
- `[STRESS_TEST]` 여부

AI GM이 기억으로 복기를 재구성하지 않고, 엔진/시즌 로그를 기준으로 복기를 만들 수 있는 구조가 목표다.

## 9. 제작/시스템 복기

플레이어 생존교육과 별도다.

검토 항목:
- 재미
- 몰입
- 캐릭터성
- 긴박감
- 선택 다양성
- 선택 비용
- 가족 자율성
- 정보 불확실성
- 장기 인과관계
- 반복성
- AI GM 오류
- Validator/State 오류
- 다음 시즌 개선

이 복기는 IP 제작과 AI GM 개선에 사용한다.

## 10. 완료 기준

Post-Season Survival Debrief가 성공하려면:

1. 본편 재미를 방해하지 않는다.
2. 플레이어의 실제 선택과 연결된다.
3. 결과론이 아니라 판단 당시 조건을 평가한다.
4. 공식 근거가 연결된다.
5. 짧게 볼 수도 있고 더 자세히 펼칠 수도 있다.
6. 플레이 후 `하나라도 실제로 배우고 싶다`는 욕구를 만든다.
