## 4. 직접 재확인한 데이터 경로

### 세션과 원문

- open_public_transcript_session은 identity를 매개변수로 받고, 동일 session 재개 시 원래 payload와 상태를 검사한다.
- append_public_transcript_turn은 내부에서 append_public_transcript_message를 USER/GM 순으로 호출한다.
- 하위 message 함수는 UTF-8 SHA-256, 세션 identity, message_order, 동일 idempotency_key에 대한 payload 일치, OPEN 상태를 검사한다.
- 이 일반 경로의 소스 정의에서는 AFTERFALL/C03 고정이 없었다. **새 세계선에서의 실제 성공은 리허설 전 미검증**이다.

### 단순화안에 추가로 필요한 작은 보완

현재 get_scene_context의 반환 JSON에는 save_version, worldline_id, gear, supplies, vehicles가 직접 포함되지 않는다. 따라서 이 결과만 읽고 expected_version으로 상태를 저장하거나 물자·차량을 판정하면 필요한 정보가 빠질 수 있다.

이 함수는 NPC를 characters, 압력을 world_pressures, 장면을 scenes, 일부 상태를 saves에서 읽는다. **saves.state만 바꾸는 commit_scene 1개**를 붙이면 NPC·압력·장면의 최신값이 같은 조회 경로에 반영된다는 보장은 없다.

최소 보완은 전체 엔진 재설계가 아니라, 기존 조회에 현재 Save 버전과 필수 자원을 함께 반환하고, 실제 바뀐 인물·압력·장면을 어디에 반영할지 좁게 정의하는 것이다. 상태 변경은 expected_version 검사, 중첩 JSON 보존, 미확정 응답의 재시도 식별, 세계선 범위 제한을 포함해야 한다. 이는 구현 전 요구이며 완료된 함수가 아니다.

check_runtime_consistency에는 압력 트랙을 8개로 기대하는 경고도 있다. 이 옛 기대치를 만족시키려고 새 작품에 불필요한 8개 트랙을 만들지 않는다.

### 수치의 해석

이번 읽기 조회에서도 AFTERFALL GM 원문 96개, 평균 3,508자, Save 295가 확인됐다. Save 버전은 플레이 턴 수가 아니므로 96/295를 누락률로 계산하지 않는다. 10개 작업 항목 중 서사 작성이 1개라는 분류도 시간·토큰의 90%가 낭비라는 실측은 아니다. 줄일 부담은 분명하지만 개선율은 실제 실행 로그로 확인해야 한다.

## 5. 수동 내보내기를 기본으로 삼는 제안의 보완

외부 환경 감사는 수동 내보내기를 명시했고, 저장 후 출력과 실시간 아카이브 보장을 잃는 점도 기록했다. 유효한 선택지지만 아직 사용자가 그 손실과 수동 작업을 승인한 것은 아니다.

OpenAI 공식 안내 확인일 2026-10-17:
https://help.openai.com/en/articles/7260999-how-do-i-export-my-chatgpt-history-and-data
- 데이터 내보내기는 도착에 최대 7일이 걸릴 수 있고 다운로드 링크는 24시간 뒤 만료된다.
- ZIP은 계정의 대화 기록과 기타 데이터를 포함한다. 자동 수집기에는 대상 대화의 명시적 선택과 비공개 정보 제외가 필요하다.
- 따라서 이를 즉시 매일 실행 가능한 무인 RAW 수집 경로라고 보고하지 않는다. 실제 계정의 내보내기 샘플을 아직 검증하지 않았다.

'나중에 수집해도 손실이 없다', '최악의 손실은 장면 하나'는 이 자료만으로 보장되지 않는다. 아직 수집되지 않은 대화가 계속 접근 가능하고, 분기·재생성·첨부·누락을 수집기가 정확히 처리하며, 장면 상태가 실제로 저장됐다는 조건이 필요하다. 대화 요약/기억 검색을 누락 RAW 복원에 사용하지 않는다.

프로젝트 문서를 서사용 규칙과 세계 설정으로 줄이는 방향은 좋다. 다만 프로젝트 파일을 넣었다고 매 응답에서 최신 전문이 반드시 로드된다는 보장은 검증되지 않았다. 새 방에서는 정확한 세계선과 최신 Save·필요 문서를 한 번 명시적으로 확인하고 같은 장면에서는 재사용하는 쪽이 안전하다.
https://help.openai.com/en/articles/10169521-projects-in-chatgpt

## 6. 작성자의 권고 — 사용자 미승인 운영 제안

**기존 ChatGPT·Supabase 유지 + 기본 세션/일반 RAW 재사용 + 기계적인 계산은 코드로 이관 + 의미 있는 상태만 저장 + 짧은 서사 문서.**

- 원문 보존 정책은 아직 변경하지 않는다. 수동 내보내기는 우선 보조 백업/복구용 후보로 둔다.
- 새 작품의 일반 RAW 경로는 기존 기본 함수로 시작 가능성을 시험한다. linked/intent 전용 객체를 고치기 위해 출발을 지연시키지 않는다.
- 해시·순서·재시도 키는 기존 trusted 도구의 프로그램/SQL로 처리하는 가장 작은 방식을 우선 검토한다. 추가 유료 API·새 서비스·대형 프레임워크를 만들지 않는다.
- 이 방식에서도 매 턴 원문을 DB에 남기려면 기록용 전달은 필요하다. **일반 턴 도구 호출 0회·원문 자동 외부 보존·추가 수동 작업 없음**을 모두 달성했다고 주장하지 않는다.
- 반대로 원문 외부 보존의 지연과 수동 내보내기를 사용자가 선택하면, 배치 수집안으로 갈 수 있다. 그때는 실제 export 샘플과 idempotency·분기·재시도·비공개 정보 배제부터 검증한다.
- 서사 규칙 문서와 세계 설정 문서는 압축하되 개발·감사 자료의 원본을 지우지 않는다. 반복 감사 패키지는 만들지 않는다.

## 7. 게임 시작까지 남은 최소 확인

1. 이름·나이·첫날 위치·가족관계 등 실제 선택을 좌우하는 미정 사항만 좁힌다. 성산구·일반 배송·성인 남성·관계 방향은 다시 묻지 않는다.
2. 충돌하지 않는 기술 ID와 독립 초기 상태를 준비한다. 기획 ID를 실제 worldline로 오인하지 않는다.
3. 확정된 보존 정책에 맞는 기본 기록/상태 경로를 실제 접속 방식으로 시험한다. 기본 세션 → 정확한 원문 쌍 → 같은 payload 재시도 → 상태 갱신과 버전 충돌 → scene 재조회에 바뀐 정보가 반영됨을 확인한다.
4. 리허설은 끝에 ROLLBACK하는 검증된 트랜잭션으로 수행하고, AFTERFALL 원본 불변과 테스트 잔여 데이터 없음을 확인한다. 실제 프롤로그로 시험 오류를 덮지 않는다.
5. 준비상태를 짧게 피드백한 뒤 본편을 시작한다. DB 안전·첫날 조건이 비어 있는 상태에서 분위기 장면부터 만들지 않는다.

이번에 수행한 것은 **외부 보고서 검토, 읽기 전용 재확인, 이 검토 기록의 Draft 저장**이다. 새 Save/세션 생성, DB 구조·권한 변경, 원문 정책 전환, 프로젝트 설정 변경, main 병합, 배포, 기존 자동화 중단은 수행하지 않았다.
