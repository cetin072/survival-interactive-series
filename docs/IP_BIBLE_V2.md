# 《생존일기》 IP Bible v2

Status: Reboot planning baseline  
Parent: GitHub Issue #45

## 1. IP 정의

《생존일기》는 단순 재난 시뮬레이터, 교육용 게임, 웹 기술 데모가 아니다.

> **평범한 한국 가족이 기존 사회가 무너지는 대규모 재난 속에서 살아남고, 선택의 결과를 누적하며, 시즌 종료 후 실제 생존지식까지 배우는 장기 인터랙티브 아포칼립스 IP**

웹, AI GM, Thin Engine, 음악, 삽화는 IP를 전달하는 수단이다. 특정 플랫폼이 바뀌어도 IP의 핵심은 유지되어야 한다.

핵심 문장:

> **먼저 살아본다. 끝난 뒤 실제라면 어땠는지 배운다.**

## 2. 최상위 목표

1. 재미와 몰입이 최우선이다.
2. 다음 장면이 궁금해야 한다.
3. 가족과 주변 인물이 기억에 남아야 한다.
4. 선택은 실제 비용과 장기 결과를 가진다.
5. 생존 지식은 본편을 방해하지 않고, 시즌 종료 후 현실 자료로 연결된다.

## 3. 세 개의 핵심 층

### ENTERTAINMENT
- 영화·드라마급 대재난과 긴장
- 강한 캐릭터성
- 시즌마다 변하는 세계
- 장면과 장면 사이의 기대감

### SIMULATION
- 숫자 선택, 복수 행동, 자유행동
- 가족의 독립 판단
- 동시 사건과 기회비용
- 상태·시간·자원·위치의 일관성
- `AI proposes, engine commits.`

### SURVIVAL KNOWLEDGE
- 플레이 중에는 장황한 강의를 하지 않는다.
- 실제 판단과 결과를 먼저 경험한다.
- 시즌 종료 후 실제 행동요령·준비·위험요소를 복기한다.
- 공식 재난·응급 자료를 우선 근거로 삼는다.

## 4. Story Rule v2

1. 《생존일기》는 장기 아포칼립스 생존 드라마다.
2. 재난은 배경이 아니라 세계의 규칙을 바꾼다.
3. 핵심 인물은 욕망, 두려움, 고집, 약점, 독립 결정을 가진다.
4. 가족은 플레이어에게 자동 복종하지 않는다.
5. 여러 문제가 동시에 진행되고 모든 것을 지킬 수 없는 순간이 존재한다.
6. 좋은 선택은 좋은 결과를 보장하지 않는다. 좋은 선택은 생존확률·정보·선택권을 개선한다.
7. 손실은 플레이어를 벌주기 위한 것이 아니라 세계 인과에서 발생해야 한다.
8. 반복적인 거점 보수·재고순환·정비는 AUTO 또는 시간점프로 압축한다.
9. 시즌마다 최소 하나의 비가역적 변화가 남는다.
10. 대규모 아포칼립스 연속성에서 정상사회 완전 복귀를 기본 결말로 두지 않는다.
11. 메인 압력의 단계가 변하면 플레이어가 해결해야 하는 문제의 종류도 달라져야 한다.
12. 시즌을 늘리기 위해 사건 수만 늘리지 않는다. 선택 비용과 충돌을 강화한다.

## 5. 캐릭터 원칙

주요 인물은 기능성 동료가 아니라 자기 삶을 가진 사람이어야 한다.

각 핵심 인물은 최소 다음을 가진다.
- 원하는 것
- 두려워하는 것
- 고집 또는 금기
- 잘하는 것
- 취약한 것
- 플레이어와 충돌할 수 있는 가치축
- 위기에서 스스로 내릴 수 있는 결정
- 장기적으로 변화할 가능성

좋은 캐릭터의 기준은 `이 상황이면 저 사람은 이렇게 행동하겠구나`가 느껴지는 것이다.

## 6. 가족 4인 기본 방향

기존 가족 4인의 기본 콘셉트는 재사용할 수 있으나 Legacy 시즌에서 획득한 성장·자산·관계는 자동 승계하지 않는다.

- 플레이어: 책임감과 계획성이 강하지만 모든 것을 직접 해결하려는 경향이 충돌축이 된다.
- 배우자: 생활 지속성과 가족 전체의 안전을 독립적으로 판단하는 공동 의사결정자다.
- 자녀: 보호 대상만이 아니라 정보·기술 적응·독립성 성장의 주체다.
- 아버지: 지역 경험과 생활기술을 가진 독립 성인이며 도움을 받는 방식 자체가 갈등축이 될 수 있다.

세부값은 Reboot S01 baseline에서 별도 확정한다.

## 7. 재난 철학

- 지역 불편 수준에 오래 머물지 않는다.
- 장기 시즌의 메인 재난은 전력, 통신, 물류, 금융, 의료, 치안, 식량, 행정 중 여러 축을 장기간 흔들 수 있다.
- 플레이어의 준비가 재난 자체를 지우지는 않는다.
- 준비는 피해 감소, 시간 확보, 선택지 증가, 회복 가능성 증가로 보상한다.
- 재난 정체와 장기 궤적은 플레이 시작 전 Hidden World Seed에 잠그되 플레이어에게 사전 공개하지 않는다.
- 완성 대본, 정답 루트, 확정 클라이맥스는 만들지 않는다.

## 8. 긴박감 설계

기존의 `문제 발생 → 해결 → 다음 문제`만 반복하지 않는다.

권장 구조:

`문제 A + 문제 B + 문제 C → 플레이어가 A를 처리하는 동안 B/C도 진행`

긴박감은 사건 수가 아니라 다음에서 나온다.
- 시간 압박
- 거리
- 가족 분산
- 자원 한계
- 상충하는 가족 요구
- 잘못된/불완전한 정보
- 동시에 유지할 수 없는 가치
- 되돌릴 수 없는 결정

## 9. 거점과 건설

거점 성장과 협업은 《생존일기》의 중요한 재미지만 본체를 대체하지 않는다.

- 거점의 반복 운영은 배경 시스템으로 압축한다.
- 거점 성장은 단순 재고량이 아니라 `할 수 있는 일의 증가`로 표현한다.
- 어떤 거점도 모든 재난에 유리한 만능 안전지대가 아니다.
- 협력은 자동 공동체화가 아니라 이해관계 기반의 협업이다.

## 10. 시즌 구조

기본 곡선:

`발단 → 압박 증가 → 선택 충돌 → 비가역 변화 → 클라이맥스 → 새로운 세계상태`

시즌 종료는 `사건 끝, 원래대로 복귀`보다 다음에 가깝다.

> **살아남았다. 그러나 세계와 가족은 이전과 달라졌다.**

## 11. 교육과 본편 분리

본편 중:
- 필요한 현실 상식은 세계·선택·결과 안에서 자연스럽게 경험한다.
- 강의, 출처 나열, 플레이어 평가를 끼워 넣지 않는다.

시즌 종료 후:
- 플레이어 생존 복기
- 현실 생존 교육 자료
- 필요할 경우 제작/GM 복기

를 분리한다.

## 12. 플랫폼 독립성

현재 주요 구현은 웹게임이지만, IP 레이어와 엔진/플랫폼 레이어는 분리한다.

재사용 가능한 하부:
- State
- Validator
- Action Queue
- Save
- RNG
- AI GM Adapter
- MUD Renderer

교체 가능한 상부:
- 세계관
- 인물
- 사건
- 시즌
- 분위기
- 교육 콘텐츠

《생존일기》가 실패하더라도 기술은 다른 인터랙티브 IP에 재사용할 수 있고, 반대로 플랫폼이 바뀌어도 《생존일기》 IP는 유지될 수 있어야 한다.

## 13. Legacy Timeline

기존 S01~S07-era 자료는 **Legacy Prototype Timeline**이다.

삭제하지 않는다. 그 안에는:
- 실제 플레이 기록
- 실패 원인
- 검증된 재미
- 파생 규칙
- 세계/캐릭터 실험

이 남아 있다.

그러나 Legacy의 누적 거점, 관계, 회사, 마을 상태를 Reboot Canon v2의 현재 사실로 자동 승계하지 않는다.

## 14. 최종 품질 질문

새 기능·시즌·규칙을 넣기 전에 다음을 묻는다.

1. 더 재미있어지는가?
2. 캐릭터가 더 살아나는가?
3. 선택이 더 비싸고 의미 있어지는가?
4. 다음 장면이 더 궁금해지는가?
5. 엔진/기술이 이야기보다 앞에 나서고 있지 않은가?
6. 시즌 종료 후 현실 생존지식으로 자연스럽게 연결할 수 있는가?

여섯 질문 중 다수에 답하지 못하면 기능 확대보다 삭제·단순화를 우선한다.
