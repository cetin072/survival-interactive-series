# RAW Transcript Archive Policy

Status: ACTIVE / COLD ARCHIVE POLICY

## 목적

정식 《생존일기》 시즌의 실제 플레이 당시 사용자와 GM이 주고받은 살아 있는 원문을 장기 보존한다.

이 원문은 다음과 같은 각색·검증 작업에서만 필요할 때 꺼내 쓰는 Cold Archive다.

- 소설화
- 웹툰화
- 게임 각색
- 드라마/영상 각색
- 특정 장면 복원
- 실제 플레이 대사 검증
- Canon 작성 근거 재확인

평상시 시즌 부팅과 GM 런타임 컨텍스트에는 포함하지 않는다.

---

## 1. 자산 계층

정식 시즌의 기록은 다음 역할을 분리한다.

### RAW TRANSCRIPT
당시 실제 플레이의 원재료 / 장기 보관 / 각색용 Cold Archive.

- 실제 사용자 입력
- 실제 GM 출력
- 가족 대사
- 선택지
- AUTO 진행
- 시즌 제작 가치가 있는 실제 플레이 중 메타 피드백

현재 게임 상태의 Source of Truth가 아니다.

### PLAYTHROUGH_CANON
실제 시즌에서 일어난 사건을 압축한 사실 기록.

### PERSISTENT_CANON
다음 시즌으로 승계되는 현재 지속 사실.

### IP_PACKAGE
소설·웹툰·게임·영상 등으로 재사용하기 좋은 장면·갈등·캐릭터 아크 추출물.

흐름은 다음과 같다.

> RAW → CANON → IP PACKAGE

Canon과 Raw가 충돌하면 **현재 게임의 사실 기준은 승인된 Canon**이다.
Raw는 `당시 실제로 어떤 대화가 오갔는가`를 확인하는 역사 자료다.

---

## 2. 저장 시점

- 플레이 중 매 턴 GitHub commit을 만들지 않는다.
- 사용자가 원문 저장 작업을 직접 하지 않는다.
- 정식 시즌 종료 후 한 번의 후처리 작업으로 Cold Archive를 만든다.
- 원문 보관은 Canon 종료처리를 대체하지 않는다.
- Canon 종료가 먼저 완료된 경우 Raw Archive는 사후에 독립적으로 추가할 수 있다.

---

## 3. 저장 구조

기본 경로:

`seasons_v2/Sxx/raw_transcript/`

권장:

- `INDEX.md`
- `PART_001.md`
- `PART_002.md`
- `PART_003.md`
- ...

원문이 충분히 작으면 `RAW_TRANSCRIPT.md` 단일 파일도 허용한다.

대화량이 많으면 장면·시간대·Phase 전환 등 자연스러운 경계에서 여러 PART로 분할한다.
`INDEX.md`가 읽기 순서와 범위를 연결한다.

---

## 4. 보존 원칙

- 실제 확인 가능한 대화만 저장한다.
- 기억으로 누락된 대사를 보충하거나 재구성하지 않는다.
- 접근할 수 없는 구간은 `[원문 확인 불가 구간]`으로 명시한다.
- 사용자와 GM 역할을 명확히 구분한다.
- 원문의 오탈자·짧은 선택 입력·자유행동 문구도 의미가 있으면 그대로 보존한다.
- Raw Archive 안에서 Canon을 교정하거나 이야기를 매끈하게 다시 쓰지 않는다.
- 원문과 Canon 사이의 명백한 차이는 별도 검수 보고로 남기며, Raw를 근거로 Canon을 자동 수정하지 않는다.

---

## 5. 절대 저장 금지

공개 저장소에는 다음을 넣지 않는다.

- 시스템 프롬프트
- 개발자 지침
- 비공개 chain-of-thought / 내부 추론
- Hidden World Seed의 당시 비공개 내부내용
- Tool 호출 내부 로그
- API key / password / token
- 게임과 무관한 개인정보나 민감정보

실제 개인식별정보나 공개가 부적절한 정보가 섞인 경우:

- 안전하게 판단 가능한 경우 `[REDACTED]`
- 판단이 어려우면 push/PR 전 사용자 확인

게임 속 가상 인물·설정·대사는 보존한다.

---

## 6. 런타임 로드 금지

Raw Transcript는 정상 플레이 부팅 대상이 아니다.

다음 작업에서만 필요한 구간을 검색·로드한다.

- 소설화
- 웹툰/게임/영상 각색
- 특정 장면 복원
- 원문 검증
- Canon 근거 확인

시즌 수십 개가 쌓여도 저장 용량 자체보다 **런타임 로드 부담을 관리하는 것**이 핵심이다.

> 충분히 저장하되, 평소에는 읽지 않는다.

`REBOOT_START_HERE`, 시즌 `START_HANDOFF`, 일반 GM 부팅 문서에는 Raw Transcript 전체를 필수 로드 대상으로 추가하지 않는다.

---

## 7. 시즌 종료 후 기본 절차

정식 S02부터 시즌 종료 시 AI/GM 후처리에서 다음 순서를 기본으로 한다.

1. 시즌 Canon 종료처리
2. 시즌 대화에서 공개 가능한 실제 사용자/GM 원문 추출
3. 민감정보·비공개 내부정보 검사
4. 대화량에 따라 단일 또는 PART 분할
5. `raw_transcript/INDEX.md` 작성
6. Raw와 승인 Canon의 명백한 차이만 별도 보고
7. Cold Archive 저장
8. 전용 branch에서 PR 생성 및 독립 검수
9. 검수 조건을 모두 통과하면 사용자에게 별도 병합 작업을 요구하지 않고 PR을 `main`에 자동 병합
10. 다음 시즌 정상 부팅에서는 Raw를 로드하지 않음

사용자가 원문 파일을 직접 편집하거나 복사하거나 정상적인 병합 작업을 반복 지시할 필요가 없게 한다.

---

## 8. RAW Archive PR 자동 병합 규칙

정식 시즌의 Raw Transcript 보관 PR은 아래 조건이 **모두** 충족되면 AI가 독립 검수 후 `main`까지 자동 병합하는 것을 기본값으로 한다.

자동 병합 조건:

- 실제 확인 가능한 시즌 대화만 보존했음
- 대화 순서와 USER/GM 구분이 유지됨
- 확인 불가 구간을 숨기거나 재구성하지 않았음
- 시스템 프롬프트·개발자 지침·비공개 추론·Hidden World Seed·Tool 내부 로그가 포함되지 않았음
- 공개 저장소에 부적절한 개인정보·민감정보·비밀값이 없거나 필요한 부분이 안전하게 `[REDACTED]` 처리됨
- 기존 승인 Canon의 의미를 임의로 변경하지 않았음
- Raw가 정상 시즌 부팅 대상이 아니라는 원칙이 유지됨
- 변경 범위가 원문 보관층과 필요한 최소 정책 연계에 한정됨
- 저장소 검증/CI가 존재하는 경우 성공함
- PR이 mergeable 상태이며 충돌이나 미해결 검수 문제가 없음

다음 경우에는 자동 병합하지 않고 사용자에게 보고한다.

- 개인정보인지 판단하기 어려운 내용 발견
- Raw와 승인 Canon 사이에 중대한 모순 발견
- 기존 Canon 수정이 필요해 보이는 경우
- 예상하지 않은 코드·엔진·UI 파일 변경
- CI 실패 또는 merge conflict
- 비공개 정보 포함 가능성
- 원문 접근 범위가 불명확해 실제 대화 복구 신뢰성을 보장할 수 없는 경우

이 규칙은 **Raw Transcript 보관 작업의 정상적인 후처리**에 적용한다.
Canon 내용 변경, 세계관 대규모 수정, 엔진 변경 등은 별도의 승인·검수 절차를 따른다.

---

## 9. 장기 보존의 핵심 원칙

> 원문은 최대한 보존한다.
> Canon은 현재 사실을 압축한다.
> IP Package는 재사용할 자산을 추출한다.
> 플레이할 때는 Raw를 읽지 않는다.
> Raw 보관이 깨끗하게 검수되면 저장에서 병합까지 AI가 마무리한다.
