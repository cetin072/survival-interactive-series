# Season Completion Pipeline

한 시즌의 플레이테스트를 끝낸 뒤 실제 플레이를 재사용 가능한 시나리오와 시각 자산으로 만드는 절차.

## 0. 전제
정식 본편은 완성된 대본을 먼저 작성해 플레이하는 구조가 아니다.

첫 플레이 전에는 `docs/WORLD_SEED_PROTOCOL.md`에 따라 GM이 비공개 월드 골격만 고정한다.
- 재난/사건의 실제 성격
- 주요 장소의 실제 상태
- 가족과 NPC의 숨은 상태·목적
- 시간/조건부 사건
- 정보의 진실·오해·지연
- 장기 인과 고리
- 가능한 종료 조건

완성된 장면 순서, 정답 루트, 확정 클라이맥스, 하나의 엔딩은 만들지 않는다.

핵심 원칙:
`세계는 먼저 존재하고, 이야기는 플레이로 생긴다.`

## 1. 플레이 종료 직후 저장
- `players/main/SAVE_STATE.json`
- `players/main/CHECKPOINT.md`
- `players/main/SESSION_LOG.md`
- 해당 시즌 `GM_STATE.json`
- 해당 시즌 `EVENTS.json`
- 사용자 체감 평가

## 2. 플레이테스트 기록
먼저 `playtests/PLAYTEST_NOTES.md`에 다음을 기록한다.
- 재미있었던 부분
- 너무 쉬웠거나 어려웠던 부분
- 선택 대가가 약했던 부분
- 가족이 수동적이었던 부분
- 정보 불확실성이 부족/과도했던 부분
- 현실성 오류
- 몰입을 깬 메타 해설
- 장기 분기가 제대로 회수됐는지
- 새로 발견된 시스템 아이디어
- `[STRESS_TEST]` 등 의도적 시스템 검증 선택

## 3. 플레이 스토리 정리
실제 플레이에서 발생한 사건만 시간순으로 정리한다.
- 오프닝
- 주요 선택
- 발생한 결과
- 가족 변화
- 얻거나 잃은 자원/거점/관계
- 실제 엔딩

산출물 예시: `seasons/S01/PLAYTHROUGH_CANON.md`

## 4. 시즌 설계 수정
첫 플레이를 정답으로 고정하지 않는다.

실제 체감을 바탕으로:
- 느린 구간 압축
- 뻔한 정답 선택 수정
- 좋은 선택끼리 충돌하도록 비용 재설계
- 가족 독립변수 강화
- 정보 출처 충돌 보강
- Fail-Forward 수정
- 장기 인과관계 회수 강화
- 비현실적 장면 수정
- 메타 해설 제거
- 이동/대기/확인 외의 선택 다양성 강화

를 진행한다.

## 5. 시나리오 구조 추출
첫 플레이와 미사용 세계 요소를 분석해 재사용 가능한 구조로 만든다.

포함:
- 시작 상태
- 재난/사건의 실제 구조
- 주요 압력축
- 주요 전환점
- 시간 기반 이벤트
- 조건부 이벤트
- 핵심 NPC와 목적
- 주요 장소
- 큰 선택 갈림길
- 가족별 독립변수
- 정보 불확실성
- 장기 회수 포인트
- Fail-Forward 상태
- 가능한 종료 상태

산출물 예시: `seasons/S01/SCENARIO_V1.md`

## 6. Branch Map 정리
모든 사소한 행동을 나무 구조로 만들지 않는다.
재사용 가치가 있는 큰 갈림길과 장기 인과관계만 기록한다.

초반 선택이 후반에 돌아오는 지점은 명시한다.

산출물 예시: `seasons/S01/BRANCH_MAP.md`

## 7. GM 재사용 데이터 정리
문서만으로 끝내지 않는다.

### `GM_STATE.json`
다른 플레이어 런을 시작하기 전에 다시 시드해야 할 숨은 상태 범주를 정의한다.

### `EVENTS.json`
시간/조건부 사건 풀을 정리한다.

중요:
- 재플레이마다 실제 값과 발동 여부는 달라질 수 있다.
- 플레이어 선택 뒤에 결과를 맞추려고 숨은 상태를 소급 변경하지 않는다.

## 8. 현실 생존 정보 검증
시즌에서 실제로 사용한 현실 지식을 `knowledge/SOURCES.md` 기준으로 검증한다.

한국 배경은 대한민국 공식 재난안전 자료를 우선한다.
플레이어용 본문에는 출처 설명을 삽입하지 않고, AAR/제작 문서에서 근거를 관리한다.

## 9. 필요 시 재플레이
핵심 구조를 크게 수정했거나 플레이테스트에서 본편 품질 기준에 미달하면 v0.2, v0.3 등으로 재테스트한다.

모든 시즌을 반드시 여러 번 플레이할 필요는 없다.
첫 플레이에서 충분히 검증된 구조는 Scenario v1.0으로 승격하고, 이후 외부/내부 플레이에서 v1.1 후보를 수집할 수 있다.

## 10. Scenario v1.0 동결
아래를 만족하면 재사용 가능한 시즌을 `Scenario v1.0`으로 표시한다.
- 첫 플레이 Canon 보존
- 주요 갈림길/종료상태 정리
- 가족 시스템이 재사용 가능한 형태로 정리됨
- Risk Exposure / Fail-Forward 원칙 반영
- 장기 인과관계 후보 정리
- 현실성 검토 기록
- 반복적이거나 뻔한 선택에 대한 개선안 반영
- GM_STATE / EVENTS 재사용 골격 정리

Scenario v1.0은 `모든 장면이 완벽하게 확정된 대본`을 뜻하지 않는다.
재사용 가능한 세계·압력·갈림길·사건 구조가 동결되었다는 뜻이다.

이후 플레이에서도 세부 묘사·대화·자유행동 결과는 AI가 유연하게 생성한다.

## 11. 미디어 후보 정리
플레이 중 남긴 `[삽화 후보]`, `[영상 후보]`를 시즌 전체 기준으로 다시 검토한다.

시즌 동결 직후에는 후보 목록만 확정할 수 있다.
실제 이미지 제작 전에 Visual Bible을 먼저 만든다.

산출물 예시:
- `MEDIA_CANDIDATES.md`

## 12. Visual Bible
Scenario v1.0 이후 `docs/ILLUSTRATION_PIPELINE.md`에 따라 Visual Bible을 만든다.
- 가족 4명 외모/체형/복장/표정
- 반복 랜드마크
- 세계관 건축/도시 분위기
- 화풍/색감/화면비/카메라 규칙
- 재난 표현 강도

## 13. 삽화/영상 계획
Visual Bible 이후 후보를:
- 반드시 필요한 삽화
- 공용 재사용 삽화
- 시즌 전용 삽화
- 없어도 되는 후보
- 영상으로 전환할 극소수 장면

으로 선별한다.

그 후 `ILLUSTRATION_PLAN.md`, 필요 시 `VIDEO_PLAN.md`를 만든다.

## 14. 일괄 제작
Visual Bible과 최종 시나리오를 기준으로 당시 가장 적합한 이미지/영상 생성도구를 선택한다.
도구에 시나리오를 맞추지 않는다.

## 15. 외부 플레이어용 패키지
다른 플레이어에게 제공할 때:
- Scenario v1.0
- Branch Map
- AI GM 규칙
- 이벤트/GM 시드 데이터
- 공용/시즌 시각 자산
- 플레이어별 독립 세이브

를 분리한다.

## 플레이방 ↔ 기획방 루프
`숨은 월드 시드 → 실제 플레이 → 사용자 체감 평가 → 기획방 수정 → Scenario v1.0 → 필요 시 추가 플레이테스트 → Visual Bible/미디어 제작`

## 원칙
첫 플레이의 모든 내용을 정답으로 고정하지 않는다.
재미있었던 것과 검증된 구조만 Canon/Scenario 자산으로 승격한다.
