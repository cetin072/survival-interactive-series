# Season Completion Pipeline

한 시즌의 플레이테스트를 끝낸 뒤 실제 플레이를 재사용 가능한 시나리오와 시각 자산으로 만드는 절차.

## 0. 전제
정식 본편은 플레이 전에 기획방에서 시즌 설계를 `APPROVED FOR PLAYTEST` 상태로 만든 뒤 플레이한다.
플레이방은 세부 장면을 즉흥적으로 생성하지만 시즌 핵심 구조는 기획 승인본을 기준으로 한다.

## 1. 플레이 종료 직후 저장
- `players/main/SAVE_STATE.json`
- `players/main/CHECKPOINT.md`
- `players/main/SESSION_LOG.md`
- 해당 시즌 `GM_STATE.json`
- 해당 시즌 `EVENTS.json`
- 사용자 체감 평가

## 2. 플레이테스트 기록
먼저 `playtests/PLAYTEST_NOTES.md`에 다음을 기록한다.
- 재미있었던 부분
- 너무 쉬웠거나 어려웠던 부분
- 선택 대가가 약했던 부분
- 가족이 수동적이었던 부분
- 정보 불확실성이 부족/과도했던 부분
- 현실성 오류
- 몰입을 깬 메타 해설
- 장기 분기가 제대로 회수됐는지
- 새로 발견된 시스템 아이디어

## 3. 플레이 스토리 정리
실제 플레이에서 발생한 사건만 시간순으로 정리한다.
- 오프닝
- 주요 선택
- 발생한 결과
- 가족 변화
- 얻거나 잃은 자원/거점/관계
- 실제 엔딩

산출물 예시: `seasons/S01/PLAYTHROUGH_CANON.md`

## 4. 시즌 설계 수정
첫 플레이를 정답으로 고정하지 않는다.
기획방에서 원래 설계와 실제 체감을 비교해:
- 느린 구간 압축
- 뻔한 정답 선택 수정
- 좋은 선택끼리 충돌하도록 비용 재설계
- 가족 독립변수 강화
- 정보 출처 충돌 보강
- Fail-Forward 수정
- 장기 인과관계 회수 강화
- 비현실적 장면 수정
- 메타 해설 제거

를 진행한다.

## 5. 시나리오 구조 추출
플레이 중 사용하지 않은 GM 사건과 갈림길을 포함하여 재사용 가능한 구조로 정리한다.
- 시작 상태
- 재난/사건의 실제 구조
- 주요 전환점
- 시간 기반 이벤트
- 조건부 이벤트
- 핵심 NPC와 목적
- 주요 장소
- 큰 선택 갈림길
- 가족별 독립변수
- 정보 불확실성
- 장기 회수 포인트
- Fail-Forward 상태
- 가능한 종료 상태

산출물 예시: `seasons/S01/SCENARIO_V1.md`

## 6. Branch Map 정리
모든 사소한 행동을 나무 구조로 만들지 않는다.
재사용 가치가 있는 큰 갈림길과 장기 인과관계만 기록한다.

예:
START
- 집에 남음
  - 통신 유지 여부에 따라 분기
- 즉시 이동
  - A 경로
  - B 경로
- 가족 분리 행동
  - 팀별 사건/재합류 결과

초반 선택이 후반에 돌아오는 지점은 별도로 표시한다.

산출물 예시: `seasons/S01/BRANCH_MAP.md`

## 7. 현실 생존 정보 검증
시즌에서 실제로 사용된 현실 지식을 `knowledge/SOURCES.md` 기준으로 검증한다.
플레이어용 본문에는 출처 설명을 삽입하지 않는다.
AAR 또는 제작 문서에서만 근거를 관리한다.

## 8. 필요 시 재플레이
핵심 구조를 크게 수정했거나 플레이테스트에서 본편 품질 기준에 미달하면 v0.2, v0.3 등으로 재테스트한다.
모든 시즌을 반드시 여러 번 플레이할 필요는 없지만, 중대한 구조 문제가 있으면 Scenario v1.0 동결 전에 재검증한다.

## 9. Scenario v1.0 동결
아래가 만족되면 재사용 가능한 시즌을 `Scenario v1.0`으로 표시한다.
- 정식 시즌 품질 기준 충족
- 주요 장기 분기 회수 작동
- 가족 시스템 작동
- 현실성 검토 완료
- 지나친 메타 해설 제거
- 주요 분기와 종료상태 정리

그 이후의 플레이는 이 뼈대를 기준으로 하되 세부 묘사·대화·자유행동 결과는 AI가 유연하게 생성할 수 있다.

## 10. Visual Bible
Scenario v1.0 또는 이에 준하는 장면 동결 이후 `docs/ILLUSTRATION_PIPELINE.md`에 따라 Visual Bible을 만든다.
- 가족 4명 외모/체형/복장/표정
- 반복 랜드마크
- 세계관 건축/도시 분위기
- 화풍/색감/화면비/카메라 규칙
- 재난 표현 강도

## 11. 삽화/영상 계획
시나리오에 남겨둔 `[삽화 후보]`, `[영상 후보]`를 전체 시즌 기준으로 다시 검토한다.
- 반드시 필요한 삽화
- 공용 재사용 삽화
- 시즌 전용 삽화
- 없어도 되는 후보
- 영상으로 전환할 극소수 장면

을 선별한다.

산출물:
- `ILLUSTRATION_PLAN.md`
- 필요 시 `VIDEO_PLAN.md`

## 12. 일괄 제작
Visual Bible과 최종 시나리오를 기준으로 당시 가장 적합한 이미지/영상 생성도구를 선택한다.
도구에 시나리오를 맞추지 않는다.

## 13. 외부 플레이어용 패키지
다른 플레이어에게 제공할 때:
- Scenario v1.0
- AI GM 규칙
- 분기/이벤트 데이터
- 공용/시즌 시각 자산
- 플레이어별 독립 세이브

를 분리한다.

## 플레이방 ↔ 기획방 루프
`기획방 시즌 설계 → 플레이방 실제 플레이 → 사용자 체감 평가 → 기획방 수정 → 필요 시 재플레이 → Scenario v1.0 → Visual Bible/미디어 제작`

## 원칙
첫 플레이의 모든 내용을 정답으로 고정하지 않는다. 재미있었던 것과 검증된 구조만 Canon/Scenario 자산으로 승격한다.
