# Season Completion Pipeline

한 시즌을 끝낸 뒤 실제 플레이를 재사용 가능한 시나리오 자산으로 만드는 절차.

## 1. 플레이 종료 직후 저장
- `players/main/SAVE_STATE.json`
- `players/main/CHECKPOINT.md`
- `players/main/SESSION_LOG.md`
- 해당 시즌 `GM_STATE.json`
- 해당 시즌 `EVENTS.json`

## 2. 플레이 스토리 정리
실제 플레이에서 발생한 사건만 시간순으로 정리한다.
- 오프닝
- 주요 선택
- 발생한 결과
- 가족 변화
- 얻거나 잃은 자원/거점/관계
- 실제 엔딩

산출물 예시: `seasons/S01/PLAYTHROUGH_CANON.md`

## 3. 시나리오 구조 추출
플레이 중 사용하지 않은 GM 사건과 갈림길을 포함하여 재사용 가능한 구조로 정리한다.
- 시작 상태
- 재난/사건의 실제 구조
- 주요 전환점
- 시간 기반 이벤트
- 조건부 이벤트
- 핵심 NPC와 목적
- 주요 장소
- 큰 선택 갈림길
- 가능한 종료 상태

산출물 예시: `seasons/S01/SCENARIO_V1.md`

## 4. Branch Map 정리
모든 사소한 행동을 나무 구조로 만들지 않는다.
재사용 가치가 있는 큰 갈림길만 기록한다.

예:
START
- 집에 남음
  - 통신 유지 여부에 따라 분기
- 즉시 이동
  - A 경로
  - B 경로
- 가족 분리 행동

산출물 예시: `seasons/S01/BRANCH_MAP.md`

## 5. 플레이테스트 반영
`playtests/PLAYTEST_NOTES.md`를 검토해 다음을 수정한다.
- 지나치게 느린 구간 삭제/압축
- 뻔한 선택지 개선
- 가족의 수동적인 행동 수정
- 불공정하거나 전조 없는 결과 수정
- 설명이 과한 장면 압축
- 생존지식이 강의처럼 보이는 부분 제거

## 6. 현실 생존 정보 검증
시즌에서 실제로 사용된 현실 지식을 `knowledge/SOURCES.md` 기준으로 검증한다.
플레이어용 본문에는 출처 설명을 삽입하지 않는다.
AAR 또는 제작 문서에서만 근거를 관리한다.

## 7. 삽화 계획
`docs/ILLUSTRATION_PIPELINE.md`에 따라 공용 자산과 시즌 전용 자산을 추출한다.

## 8. Scenario v1.0 동결
위 정리가 끝난 뒤 재사용 가능한 시즌을 `Scenario v1.0`으로 표시한다.
그 이후의 플레이는 이 뼈대를 기준으로 하되 세부 묘사와 대화는 AI가 유연하게 생성할 수 있다.

## 원칙
첫 플레이의 모든 내용을 정답으로 고정하지 않는다. 재미있었던 것만 Canon/Scenario 자산으로 승격한다.
