Each future `RESERVED` event binds an attempt and request ID to an exact READY point and generation key. A later `FAILED` or `QUARANTINED` event closes that attempt while retaining the reservation and its count. Each event includes the previous event's digest and its own digest; this detects accidental edits, not malicious rewrites without an external trusted anchor. A catalog batch is capped at three reservations, with no more than one active reservation or three attempts per point. The journal rejects private scope, stale catalog identity, duplicate reservations, broken event chains, fake success states and execution flags.
