# 《생존일기》 경량 그래픽·로그라이크 UI 계획

## Status
- Canon v2 기반 웹게임 / AI GM 기획에 통합하는 UI·시각화 보조 규칙.
- 게임의 본체는 **텍스트 + AI GM + Engine authoritative state**다.
- 그래픽은 선택과 결과, 누적 성장, 현재 상태를 더 빨리 이해하게 하는 보조 계층이다.
- 현재 Web MVP를 중단하거나 대형 그래픽 프로젝트로 전환하지 않는다.

관련 기존 규칙:
- `docs/ILLUSTRATION_PIPELINE.md` — 모든 턴/선택마다 이미지를 만들지 않고 재사용 가능한 상황·장소·핵심 이벤트 자산을 우선한다.
- `docs/BASE_GROWTH_RULE.md` — 거점의 성장은 실제 플레이 결과로 누적되며, 유지보수 반복노동이 아니라 능력/전문화의 성장으로 표현한다.
- Issue `#57` — 현재 Web Game MVP v1의 구현 Source of Truth.

---

## 1. 핵심 원칙

> 그래픽이 게임의 본체가 되지 않는다. 그래픽은 플레이어가 내린 선택과 그 결과를 더 잘 느끼게 하는 보조 수단이다.

반드시 유지한다.
1. AI GM이 매 턴 이야기를 자연스럽게 진행한다.
2. 선택 후 충분한 이야기 전개가 발생한다.
3. 자유행동이 가능하다.
4. 가족은 플레이어의 말판이 아니며 독자적인 판단을 할 수 있다.
5. 선택 결과가 이후 세계에 누적된다.
6. 거점 성장도 실제 플레이 결과로 발생한다.
7. 그래픽 때문에 턴 진행 속도가 느려지지 않는다.
8. 게임이 단순 카드 선택 게임으로 변하지 않는다.

## 2. 기본 모바일 UI — STORY FIRST SHELL

《생존일기》 웹게임의 기본 화면은 **모바일 우선, 이야기 우선**으로 설계한다.

### 핵심 원칙

> 모바일 화면의 중앙 80% 이상은 AI GM의 스토리 전용 스크롤 영역으로 사용하고, 상·하단에는 합계 20% 이하의 고정 HUD를 배치하여 현재 상황과 가족·거점·자원을 언제든 확인할 수 있게 한다.

20%는 목표 상한선이다. 가능하면 상단 약 6~7%, 하단 약 9~11% 수준으로 시작하여 실제 기기에서 15~18% 정도의 체감 점유율을 우선 테스트한다.

### 기본 구조

```text
┌─────────────────────────────┐
│ 상단 고정 HUD               │
│ DAY · 시간 · 장소 · 위험상태 │
├─────────────────────────────┤
│                             │
│ STORY AREA                  │
│                             │
│ AI GM 이야기                │
│ 가족 대화                    │
│ 사건 발생                    │
│ 선택 결과                    │
│                             │
│ [선택 카드]                  │
│ [선택 카드]                  │
│ [선택 카드]                  │
│ [선택 카드]                  │
│                             │
│ 직접 행동하기...             │
│                             │
│ 다음 AI GM 이야기            │
│                             │
│ ↕ 중앙 영역만 스크롤          │
│                             │
├─────────────────────────────┤
│ 하단 고정 HUD               │
│ 가족 · 거점 · 차량 · 물자     │
└─────────────────────────────┘
```

### 2.1 상단 HUD — `지금`만 표시

상단은 최대한 얇게 유지한다.

권장 정보:
- DAY / TURN
- 현재 시간
- 현재 장소
- 전체 위기 단계 `안정 / 주의 / 위험 / 심각`

예:

`DAY 12 · 22:40 · 외곽주택 · ⚠ 위험`

가족 세부 상태, 물, 식량, 차량, 시설 목록을 상단에 모두 넣지 않는다.

### 2.2 중앙 STORY AREA — 게임의 본체

중앙 영역만 세로 스크롤한다.

흐름은 다음처럼 누적된다.

`이야기 → 선택 → 선택 기록 → 다음 이야기 → 선택 → ...`

AI GM의 이전 장면 본문을 지우고 현재 장면만 보여주는 방식보다, 플레이 중 생성된 이야기가 위쪽에 계속 남는 **웹소설형 transcript**를 기본으로 한다.

선택이 확정되면 큰 카드는 현재 선택 UI에서는 사라지지만, 해당 행동은 작은 `내 선택` 기록으로 축약되어 스토리 흐름 안에 남는다.

### 2.3 하단 HUD — `나의 세계`

하단에는 지속적으로 보고 싶은 핵심 자산만 압축 표시한다.

기본 4영역:
- 가족
- 거점
- 차량
- 물자/자원

예:

`가족 4/4 · 외곽주택 · 차량 1대 · 물 8일`

각 영역을 누르면 중앙 이야기를 완전히 떠나지 않는 작은 상세 패널/바텀시트를 연다.

예: 거점 상세
- 태양광
- 물탱크
- 저장창고
- 창문 보강
- 경계등
- 현재 거점 대표 이미지

설정, BGM, 글자 크기, RESET 같은 보조 기능은 기본 HUD에 계속 노출하지 않고 별도 설정 패널에 넣는다.

## 3. 선택지 카드 UI — 이야기 안에서 등장

카드는 별도 카드게임 화면이나 풀스크린 로그라이크 오버레이가 아니다.

AI GM 이야기를 읽다가 선택 시점이 오면 **스토리 바로 아래에 큰 카드 4개가 이야기의 일부처럼 등장**한다.

모바일에서는 세로형 큰 카드, 넓은 화면에서는 2×2 배치를 우선 검토한다.

카드 기본 구성:
- 작은 아이콘 또는 번호
- 짧은 행동 제목
- 1~2문장의 충분한 행동 설명

설명은 `무엇을 하려는 선택인지`, `행동 범위가 어디까지인지` 이해하게 한다.

카드에 넣지 않는다:
- 위험 감소/증가 예상치
- 신뢰 상승/하락 예상치
- 자원 증감 예상치
- 성공률
- 희귀/특별/등급 표시
- 정답처럼 보이는 강조

핵심 경험은 `카드 평가`가 아니라:

`무엇을 선택했는가 → 실제 결과가 무엇이었는가 → 그 결과가 이후 세계에 어떻게 남는가`

이다.

### 3.1 선택지 수와 복수 선택

복수 선택을 기본 기능으로 사용할 경우 **3지선다는 기본값으로 부족하다.**

MVP 기본값:
- 선택지: 원칙적으로 4개
- 한 턴 최대 선택: 2개
- 선택된 순서를 AI GM 의도로 유지

권장 조작:
- 카드 한 번 터치: 선택 큐에 추가
- 선택된 카드에는 `1순위 / 2순위` 표시
- 다시 터치: 선택 취소
- 세 번째 카드는 선택 불가 또는 최대 2개 안내
- `선택 종료 · N개 실행` 버튼으로 확정
- 하나만 선택해도 같은 확정 버튼으로 실행 가능

AI GM에는 선택된 카드들을 **순서가 있는 하나의 플레이어 의도**로 전달한다.

동시에 성립할 수 없는 행동은 AI가 임의로 모두 실행하지 않는다. 기존 Action Queue / Validator가 충돌을 검증하고, 가능한 부분만 처리하거나 충돌을 이야기 안에 드러낸다.

---

## 4. 자유행동 유지

카드 바로 아래에 자유행동 입력창을 둔다.

카드는 기본 행동 제안일 뿐이며 자유행동은 항상 유지한다.

예:
> 민석에게 통신 상태를 확인시키고 나는 외곽 상황을 살핀다.

AI GM은 의도를 해석하고, Engine은 실제 가능한 상태변화만 검증·커밋한다.

`1`, `1번`, `1번 → 2번` 같은 입력은 현재 선택지 단축 입력으로 해석할 수 있다. 일반 문장 속 숫자는 선택지 번호로 오인하지 않는다.

---

## 5. 서사 가독성 / 타이포그래피

Web MVP 플레이테스트에서 다음 문제가 확인되었다.
- 선택 후 서사가 짧다.
- 줄글로 이어져 가독성이 낮다.
- 기본 글자 크기가 작다.
- 불필요한 환경 묘사가 행동·결과보다 많다.

### MVP 기본 규칙
- 모바일 기준 본문은 대략 17~18px 수준을 우선 검토한다.
- 줄간격은 약 1.7~1.9 수준을 우선 검토한다.
- 문장마다 줄바꿈을 금지하지 않는다. **읽기 편한 문장·문단 단위**를 우선한다.
- 같은 장면의 1~3문장을 자연스러운 묶음으로 구성한다.
- 문장 사이와 장면 묶음 사이의 여백을 충분히 둔다.
- 본문 폭을 지나치게 넓게 쓰지 않는다.
- 설정에서 `작게 / 기본 / 크게` 글자 크기를 제공한다.

### AI GM 서술 우선순위
길이를 늘릴 때 환경 묘사를 늘리지 않는다.

우선순위:
1. 플레이어 행동의 실제 결과
2. 가족/주변 사람의 반응과 판단
3. 세계 또는 자원의 의미 있는 변화
4. 새로 생긴 압력·기회·정보
5. 다음 선택으로 이어지는 장면
6. 필요한 만큼의 최소 환경 묘사

환경·날씨·빛·소리 묘사는 판단이나 긴장에 영향을 줄 때만 상세하게 쓴다.

출력 직전 맞춤법, 띄어쓰기, 인물 이름, 문장 종결을 자체 점검한다.

## 6. 상황판 경량 그래픽화

가족·자원·거점 상태는 하단 HUD 및 상세 패널에서 아이콘 + 짧은 상태 태그 중심으로 표현한다.

예:
- 가족: 아내 — 긴장 / 민석 — 안정 / 아버지 — 피로
- 자원: 물 / 식량 / 전력 / 통신
- 거점: 외곽주택 / 차량 / 도심 아파트

복잡한 게이지를 다수 만들지 않는다. 한눈에 판단 가능한 상태만 우선한다.

기본 아이콘 체계는 **Lucide Icons 우선 검토**. Tabler / Material Symbols는 대안이다. 여러 아이콘 체계를 섞지 않는다.

---

## 7. 현재 위기 단계

상단 HUD에 세계 전체의 위기 정도를 단순 텍스트 단계로 표현할 수 있다.

`안정 → 주의 → 위험 → 심각`

이는 선택의 예상 정답이나 성공률이 아니라 **현재 세계 상태 요약**이다.

---

## 8. 선택 후 주요 변화

선택 전에 결과를 예고하지 않는다.

선택 후에는 플레이어가 알아야 할 변화 1~4개만 스토리 흐름 안에서 짧게 강조한다.

예:
- 물 12L 사용
- 발전기 점검 완료
- 아버지 피로 증가
- 통신 장애 확인

모든 내부 수치를 노출하지 않는다. Engine이 실제로 커밋한 delta만 표시한다.

---

## 9. 거점·차량의 시각적 성장

### 외곽주택
장기적으로 다음 시설이 실제 플레이 결과에 따라 시각적으로 누적될 수 있다.
- 태양광
- 물탱크
- 저장창고
- 창문 보강
- 울타리
- 텃밭
- 작업공간
- 경계등
- 발전기
- 빗물 저장시설

`Lv.1 → Lv.2 → Lv.3`만으로 단순화하지 않는다.

플레이어 선택에 따라:
- 전력 자립형
- 식량 비축형
- 방어 강화형
- 생활 안정형

등 서로 다른 전문화가 눈에 보이게 한다.

초기 MVP에서는 하단 HUD의 거점 상세 패널 안에 시설 슬롯/대표 이미지를 넣고, 장기적으로 레이어 합성 방식을 검토한다.

### 차량
차량도 누적 자산으로 표현한다.
- 비상가방
- 공구함
- 응급키트
- 물자함
- 루프랙
- 보조배터리
- 차량용 무전기
- 추가 적재 공간

차량 이미지는 하단 차량 상세 패널 안에서 보여주는 것을 우선한다.

## 10. 시설 슬롯

대형 이미지 이전에도 작은 아이콘으로 성장 체감을 제공한다.

예:
- 외곽주택: 태양광 / 물탱크 / 저장창고 / 창문 보강 / 미설치 시설
- 차량: 공구함 / 응급키트 / 물자함 / 무전기

이 슬롯은 `BASE_GROWTH_RULE.md`의 capability model과 연결한다. 존재하지 않는 시설을 단순 수집용으로 만들지 않는다.

---

## 11. 플레이 흔적 / 주요 갈림길

전체 분기 트리는 만들지 않는다.

시즌/위기에서 의미가 큰 결정만 기록한다.

예:
- 가족 전원 외곽 이동
- 제한적 협력 선택
- 차량 연료 비축 우선
- 도심 거점 유지
- 야간 조명 최소화

목적은 플레이어가 `이번 플레이가 어떤 방향으로 흘러왔는가`를 한눈에 확인하게 하는 것이다.

스토리 transcript의 선택 기록과 별도로, 시즌 단위의 중요한 갈림길만 장기 기록한다.

---

## 12. AI 이미지 사용 원칙

런타임에서 매 턴 AI 이미지를 생성하지 않는다.

우선순위:
A. 거점 성장 이미지
B. 반복 장소 대표 이미지
C. 정말 중요한 이벤트 이미지

### 상황별 이미지 원칙
선택지마다 이미지를 따로 만들지 않는다.

예: `외곽주택 야간 상황` 이미지 하나를 경계/발전기 확인/물자 확인/가족 대화 등 여러 행동에서 재사용할 수 있다.

기존 `ILLUSTRATION_PIPELINE.md`의 Visual Bible / 후보 태그 / 시즌 종료 후 asset 제작 규칙을 유지한다.

---

## 13. 로그라이크 감각 정의

《생존일기》에서 원하는 로그라이크 감각은 희귀카드·카드등급·랜덤 강화가 아니다.

핵심은:

`선택 → 결과 → 누적 → 세계 변화 → 성장한 상태로 다음 위기`

한 번의 플레이에서 내린 결정이 거점·관계·자원·세계의 형태를 바꾸고, 그 흔적이 다음 위기에 이어지는 것이 핵심이다.

## 14. 단계적 적용 순서

### Phase A — 현재 MVP에 바로 적용
1. **상단/하단 고정 HUD + 중앙 STORY AREA 단독 스크롤**
2. AI 장면 본문을 플레이 transcript에 누적
3. 선택 기록을 축약 형태로 transcript에 남김
4. 장면 본문 기본 글자 확대
5. 글자 크기 `작게 / 기본 / 크게`
6. AI narrative 문장/문단 가독성 개선
7. 불필요한 환경묘사 억제 + 행동/결과/가족반응 중심 프롬프트
8. 이야기 바로 아래 4개 대형 선택 카드
9. 최대 2개의 순서 있는 복수 선택
10. 카드 바로 아래 자유행동 입력
11. Engine commit 기반 `이번 턴 변화` 1~4개
12. 하단 가족/거점/차량/물자 상세 패널

### Phase B — 코어 플레이가 안정된 뒤
- Lucide 기반 아이콘 통일
- 시설 슬롯
- 외곽주택/차량 대표 성장 이미지
- 하단 상세 패널의 시각화 강화

### Phase C — 시즌/세계 자산이 안정된 뒤
- 반복 장소 대표 이미지
- 핵심 이벤트 이미지
- 주요 갈림길/플레이 흔적 UI
- 시설 레이어형 거점 성장 검토

## 15. MVP 중단 금지 규칙

그래픽 작업 때문에 다음을 지연시키지 않는다.
- AI GM의 매 턴 서사 진행 품질
- 자유행동 해석
- Engine commit 안정성
- 가족 자율 반응
- 10~20턴 연속 플레이 안정성
- pressure / compression / growth fun loop

새 그래픽 기능이 이 항목을 막으면 그래픽 기능을 후순위로 내린다.
